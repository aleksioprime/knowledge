**Циклический импорт** (circular import) — это ситуация, когда два или более модуля в Python напрямую или косвенно импортируют друг друга. Такой сценарий часто приводит к ошибкам импорта и сбоям при запуске кода. Понимание проблемы циклического импорта и способов её решения — важная часть профессиональной работы с большими проектами.
## Как возникает циклический импорт

Циклический импорт появляется, когда модули "зависят" друг от друга:

```python
# a.py
from b import foo

def bar():
    foo()

# b.py
from a import bar

def foo():
    bar()
```

В этом примере `a.py` импортирует `foo` из `b.py`, а `b.py` — функцию `bar` из `a.py`.  
Когда интерпретатор Python начинает импортировать `a.py`, он сначала пытается загрузить всё, что требуется, включая `b.py`.  
Но в процессе импорта `b.py` опять начинается импорт `a.py`, который ещё не до конца инициализирован, и возникает ошибка `ImportError` или `AttributeError`.
## Типичные ошибки

- `ImportError: cannot import name 'X' from partially initialized module ...`
- `AttributeError: partially initialized module ... has no attribute ...`
## Почему это проблема

- Модули не могут быть полностью инициализированы, если они ссылаются друг на друга до завершения загрузки.
- Код становится сложно поддерживать и тестировать.
- Циклические зависимости нарушают модульность и разрушают архитектуру проекта.
## Как избежать и исправлять циклический импорт

### 1. **Рефакторинг структуры**

- Вынесите общие зависимости в третий модуль.
- Пересмотрите структуру — возможно, код должен быть разбит по-другому.

**Пример:**

```python
# common.py
def shared_func(): ...
```

Теперь оба модуля импортируют из `common.py`, а не друг друга.
### 2. **Локальный импорт**

- Импортируйте зависимости внутри функций или методов, а не на верхнем уровне файла.
- Это работает, потому что импорт происходит только во время выполнения, когда оба модуля уже инициализированы.

**Пример:**

```python
# a.py
def bar():
    from b import foo
    foo()
```
### 3. **Поздний импорт (import внутри функции)**

- Аналогично локальному: используйте import только тогда, когда это действительно нужно.
- Это временное решение; долгосрочно лучше переработать архитектуру.
### 4. **Избегайте избыточных импортов**

- Импортируйте только то, что действительно необходимо.
- Иногда достаточно импортировать модуль целиком, а не конкретные объекты:

```python
import a
# вместо from a import bar
```

### 5. **Используйте "ленивые" типы аннотаций**

- В новых версиях Python можно писать типы в кавычках (`from __future__ import annotations`), чтобы избежать ранних импортов.
## Советы

- Структурируйте проект так, чтобы основные зависимости были однонаправленными.
- Избегайте "сильных" взаимных связей между модулями.
- Если проект растёт — проводите ревизию структуры.
