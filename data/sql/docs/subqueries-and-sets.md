# Подзапросы, CTE и операции множеств

## Подзапросы и CTE

### Подзапрос

Подзапрос — запрос внутри другого выражения. Он бывает:

- скалярным: одна строка и один столбец;
- табличным: несколько строк/столбцов;
- в `FROM` (derived table);
- в `WHERE`, `HAVING`, `SELECT` или DML.

**Некоррелированный** подзапрос не ссылается на внешний запрос и логически может быть вычислен независимо:

```sql
SELECT *
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
```

**Коррелированный** ссылается на текущую строку внешнего запроса:

```sql
SELECT e.*
FROM employees e
WHERE salary > (
    SELECT AVG(x.salary)
    FROM employees x
    WHERE x.department_id = e.department_id
);
```

Логически коррелированный подзапрос проверяется для внешних строк, но оптимизатор может преобразовать его в join или другой план. Не следует заранее считать, что он обязательно выполнится буквально N раз — смотрите `EXPLAIN`.

### CTE

CTE — именованный результат в рамках одного SQL-выражения:

```sql
WITH department_stats AS (
    SELECT department_id, AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department_id
)
SELECT e.*
FROM employees e
JOIN department_stats s USING (department_id)
WHERE e.salary > s.avg_salary;
```

Отличия от обычного подзапроса:

- CTE даёт имя и часто улучшает читаемость;
- на один CTE можно сослаться несколько раз;
- `WITH RECURSIVE` позволяет обходить деревья и графы;
- CTE не существует после завершения statement;
- это не автоматически «быстрее» и не временная таблица.

В современных PostgreSQL нематериализованный CTE, используемый один раз, обычно может быть встроен в запрос. `MATERIALIZED` принудительно создаёт промежуточный результат, `NOT MATERIALIZED` разрешает встраивание; решение влияет на оптимизацию.

## Объединение результатов

Операции множеств требуют одинакового числа столбцов и совместимых типов:

| Операция | Результат |
|---|---|
| `UNION` | Объединяет и удаляет дубликаты |
| `UNION ALL` | Объединяет и сохраняет дубликаты |
| `INTERSECT` | Общие строки |
| `EXCEPT` | Строки первого запроса, которых нет во втором |

`UNION ALL` обычно дешевле, потому что не делает дедупликацию. Имена результирующих столбцов берутся из первого запроса. Общий `ORDER BY` ставится после последней ветки.

`JOIN` добавляет **столбцы**, сопоставляя строки; `UNION` добавляет **строки** из совместимых выборок.
