### docker search

Поиск образов, доступных в реестре Docker:

```sh
docker search [options] term
```

Поиск в графическом интерфейсе дает те же результаты. Некоторые результаты, встречаются один раз, но некоторые повторяются, потому что образы с повторяющимися названиями были созданы и выгружены разными пользователями для каких-то своих специфических нужд. 

Если выполнить команду `search` с ключом `--filter`, она вернет только наиболее часто используемые образы, опираясь на отзывы других пользователей:

```sh
docker search --filter stars=50 django
```

### docker pull

Загружает указанный образ из реестра **Docker** на локальный компьютер:

```sh
docker pull image:tag
```

Если тег (tag, обозначающий версию) не указан, команда подставит тег `latest` и загрузит только последнюю версию образа `Django`. В этом случае она будет действовать подобно команде:

```sh
docker pull django:latest
```

### docker images

Возвращает список образов верхнего уровня, доступных на локальном компьютере:

```sh
docker images [options]
```

Например, команда `docker images -a` выведет список всех образов верхнего уровня, включающий название репозитория, тег, дату создания и виртуальный размер. 

Важно помнить, что при создании или сборке образов Docker на локальном компьютере дополнительно создаются различные промежуточные уровни. Например, если используемый нами файл `Dockerfile` имеет несколько команд, выполняющих сборку образов, каждая из них обеспечивает дополнительный уровень и образ для него. Это один из ключевых аспектов Docker, который делает контейнеры идеально подходящими для повторного использования.

### docker rmi

Удаляет указанный образ или образы на локальном компьютере:

```sh
docker rmi [options] image [image, image...]
```

Например, команда `docker rmi django` удалит образ Django, а также все уровни, установленные с хоста

### docker run

Запускает указанный образ

```sh
docker run [options] image: tag [command, args]
```

Данная команда разворачивает контейнер в его собственной файловой системе, имеющей свой набор портов и IP-адрес.

Кроме названия образа, команде `run` можно также передать дополнительные ключи и аргументы. Вот наиболее часто используемые из них:

-  `--interactive` переключает команду в интерактивный режим и открывает STDIN;
-  `--tty` создает псевдотерминал TTY.

Команда `docker run` поддерживает множество других ключей, например для запуска процесса в фоновом режиме `-d`, когда контейнер запускается без поддержки командной строки. Также можно переопределить являющиеся частью запускаемого образа команды по умолчанию. Дополнительно можно задать ограничения на объем памяти и количество доступных процессоров.

### docker ps

Выводит список всех контейнеров(ps - process status), запущенных к настоящему моменту:

```sh
docker ps [options]
```

Команда `ps` с ключом `–a` позволяет увидеть список всех контейнеров, даже не запущенных
### docker restart

Перезапускает указанный контейнер: 

```sh
docker restart [options] container
```

Для перезапуска контейнера указывается его идентификатор, полученный через `ps`

### docker attach

Позволяет передать указанный активный контейнер под интерактивное управление или увидеть его стандартный вывод:

```sh
docker attach [options] container
```

Важно отметить, что мы всегда будем получать приглашение к вводу после каждого перезапуска контейнера. Это поведение по умолчанию нельзя изменить, потому что мы определили его, собрав контейнер с ключом `--interactive` в команде `run`. Конечно, мы можем запустить тот же образ `Ubuntu` с другими ключами и параметрами. В этом заключается особая прелесть Docker.

### docker rm

Удаляет указанные контейнеры: 

```sh
docker rm [options] containers
```

Перед удалением контейнер нужно остановить или передать команде `rm` ключ `–f` (force – принудительно), действие которого заключается в отправке сигнала `SIGKILL` процессу, выполняющемуся в контейнере:

```sh
docker stop [options] containers
```

Команда `stop` сначала посылает сигнал `SIGTERM`, а затем, выждав некоторое время, сигнал `SIGKILL`. Период ожидания можно изменить, передав ключ –t с числом секунд. Эта возможность может очень пригодиться в случаях, когда требуется, чтобы процесс в контейнере успел завершить обработку запроса (например, запроса HTTP).

Также можно воспользоваться командой `docker kill`, которая немедленно посылает сигнал `SIGKILL`, но в этом случае процесс в контейнере не получит возможности завершиться обычным путем. Однако эта команда имеет ключ, позволяющий послать процессу в контейнере другой сигнал, отличный от `SIGKILL`.

### docker exec

Позволяет удаленно выполнить другую команду в уже запущенном контейнере. 

```sh
docker exec [options] container command [arg...]
```

Например:

```sh
docker exec dcf8cda72903 ls -a
```

### docker rename

Позволяет переименовать уже запущенный контейнер:

```sh
docker rename container new_name
```

Новое имя можно использовать в командах `docker` вместо его идентификатора

### docker start / stop

Чтобы запустить остановленный контейнер, необходимо ввести `docker start` и далее указать идентификатор или имя контейнера.

Чтобы выключить активный контейнер, используется команда `docker stop` с последующим указанием его идентификатора или имени

### docker cp

Позволяет копировать файлы между контейнером и машиной, на которой тот выполняется:

```sh
docker cp [options] container:src_path dest_path
```

Пример копирование файла из контейнера на локальную машину:

```sh
docker cp ubuntu_main:/var/sample.txt .
```

Пример копирования файла с локальной машины в контейнер:

```sh
docker cp myfile.txt ubuntu_main:/var
```

### docker pause/unpause

 Приостанавливает все процессы в указанных контейнерах: 

```sh
docker pause container [container...]
```

Возобновляет выполнение контейнеров:

```sh
docker unpause container [container...]
```

### docker create

Создает новый уровень контейнера, доступный для записи, поверх указанного образа и подготавливает его для выполнения указанной команды:

```ssh
docker create [options] image [command] [arg...]
```

Эта команда отличается от `docker run -d` тем, что не запускает контейнер. Чтобы запустить его, нужно выполнить команду `docker start`.

Она может пригодиться в случаях, когда нужно заранее создать и настроить контейнер, чтобы он был готов к запуску, когда наступит подходящий момент.
### docker commit

Позволяет создать новый образ со всеми изменениями, выполненными в контейнере:

```ssh
docker commit [options] container [repository:tag]
```

Если, выполнив какие-то изменения в контейнере, вы решите передать его кому-то, например группе разработки или тестирования, в виде образа, то сможете создать такой образ из запущенного контейнера.
### docker diff

Выводит изменения в файлах и каталогах в файловой системе контейнера:

```ssh
docker diff container
```

По прошествии времени, когда вы внесете какие-либо изменения в свой контейнер, эта команда поможет вам увидеть отличия в файловой системе в сравнении с базовым образом.
