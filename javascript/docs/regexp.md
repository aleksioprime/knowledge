# Регулярные выражения: краткий справочник

Регулярное выражение (RegExp) — шаблон для поиска, проверки и замены текста.

## Создание

Литерал используют для заранее известного шаблона, а конструктор — для динамического:

```js
const digits = /\d+/

const part = 'user'
const dynamicPattern = new RegExp('^' + part + '-\\d+$', 'i')
```

В строке для `RegExp` обратный слеш удваивают: строка `'\\d+'` передаёт выражению текст `\d+`.

## Специальные символы

| Запись | Значение |
| --- | --- |
| `.` | любой символ, кроме перевода строки; с флагом `s` — включая его |
| `\` | экранирование |
| `|` | альтернатива «или» |
| `(...)` | группа |
| `[...]` | класс символов |
| `^`, `$` | начало и конец |
| `*`, `+`, `?`, `{...}` | количество повторений |

Обычный символ совпадает сам с собой. Специальный символ для буквального поиска экранируют:

```js
/cat/.test('black cat') // true
/\./.test('file.txt')     // точка
/\+7/.test('+79990000000') // плюс
/\/api\//.test('/api/users') // слеш внутри литерала
```

Основные специальные символы: `\ ^ $ . | ? * + ( ) [ ] { }`. В литерале также экранируют разделитель `/`.

## Классы символов

| Шаблон | Значение |
| --- | --- |
| `[abc]` | один из перечисленных символов |
| `[^abc]` | любой символ, кроме перечисленных |
| `[a-z]` | символ из диапазона |
| `\d` / `\D` | цифра `0–9` / не цифра |
| `\w` / `\W` | латинская буква, цифра или `_` / противоположное |
| `\s` / `\S` | пробельный / непробельный символ |
| `\p{L}` | любая Unicode-буква; нужен `u` или `v` |
| `\p{N}` | любое Unicode-число; нужен `u` или `v` |

```js
/^[A-Z]\d{3}$/.test('A123') // true
/^\p{L}+$/u.test('Привет') // true
```

`\w` не охватывает буквы всех языков. Для кириллицы и других алфавитов используйте явный диапазон или Unicode properties.

Управляющие символы: `\n` — перевод строки, `\r` — возврат каретки, `\t` — табуляция, `\xNN` и `\uNNNN` — символ по коду.

## Границы

| Шаблон | Значение |
| --- | --- |
| `^` | начало строки, а с `m` — каждой строки |
| `$` | конец строки, а с `m` — каждой строки |
| `\b` | граница слова |
| `\B` | позиция не на границе слова |

```js
/cat/.test('concatenate') // true
/^cat$/.test('cat')         // true: совпала вся строка
/\bcat\b/.test('black cat') // true: отдельное слово
```

Для проверки формата всей строки обычно нужны оба якоря: `^...$`.

## Квантификаторы

| Шаблон | Количество |
| --- | --- |
| `x*` | от нуля |
| `x+` | от одного |
| `x?` | ноль или один |
| `x{3}` | ровно три |
| `x{2,}` | два и более |
| `x{2,5}` | от двух до пяти |

```js
/^\d{4}$/.test('2026')   // четыре цифры
/^https?$/.test('https') // http или https
/^(ha)+$/.test('hahaha') // повторение группы
```

Квантификаторы по умолчанию жадные. `?` после квантификатора делает его ленивым:

```js
const html = '<b>one</b><b>two</b>'

html.match(/<b>.*<\/b>/)[0] // '<b>one</b><b>two</b>'
html.match(/<b>.*?<\/b>/)[0] // '<b>one</b>'
```

Это только пример жадности: произвольный HTML следует разбирать DOM-парсером.

## Группы и альтернативы

| Шаблон | Значение |
| --- | --- |
| `(abc)` | захватывающая группа |
| `(?:abc)` | группа без захвата |
| `(?<name>abc)` | именованная группа |
| `a|b` | `a` или `b` |
| `\1` | ссылка на первую группу |
| `\k<name>` | ссылка на именованную группу |

```js
const pattern = /^(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})$/
const match = '2026-08-04'.match(pattern)

match.groups.year // '2026'
match.groups.month // '08'
```

Альтернатива имеет низкий приоритет, поэтому общий контекст объединяют группой:

```js
/^(cat|dog)$/.test('dog') // true
/^(['"]).*\1$/.test('"текст"') // одинаковые кавычки
```

## Lookahead и lookbehind

Проверяют контекст, не включая его в найденную подстроку:

| Шаблон | Проверка |
| --- | --- |
| `x(?=y)` | после `x` находится `y` |
| `x(?!y)` | после `x` не находится `y` |
| `(?<=y)x` | перед `x` находится `y` |
| `(?<!y)x` | перед `x` не находится `y` |

```js
'100 USD'.match(/\d+(?= USD)/)[0] // '100'
'$100'.match(/(?<=\$)\d+/)[0] // '100'
```

## Флаги

Флаг записывается после закрывающего `/` и меняет режим работы всего регулярного выражения.

```js
/hello/gi // g — все совпадения, i — без учёта регистра
new RegExp('hello', 'gi')
```

| Флаг | Значение |
| --- | --- |
| `g` | все совпадения; использует `lastIndex` |
| `i` | без учёта регистра |
| `m` | многострочный режим для `^` и `$` |
| `s` | точка совпадает с переводом строки |
| `u` | Unicode-режим |
| `v` | расширенный Unicode-режим и классы множеств; несовместим с `u` |
| `y` | поиск строго с позиции `lastIndex` |
| `d` | индексы совпадений в результате |

## Методы

| Вызов | Результат |
| --- | --- |
| `regexp.test(text)` | `true` или `false` |
| `regexp.exec(text)` | совпадение с группами либо `null` |
| `text.match(regexp)` | совпадение или массив совпадений с `g` |
| `text.matchAll(regexp)` | iterator всех совпадений с группами; нужен `g` |
| `text.search(regexp)` | индекс первого совпадения или `-1` |
| `text.replace(regexp, replacement)` | строка с заменой |
| `text.split(regexp)` | массив частей |

```js
/^\d+$/.test('12345') // true

const result = /(?<name>\w+)@(?<domain>[\w.-]+)/.exec('alex@example.com')
result.groups.name // 'alex'
result.index // 0

'a1 b2 c3'.match(/\d/g) // ['1', '2', '3']
'hello 2026'.search(/\d/) // 6
'one, two;three'.split(/[,;]\s*/) // ['one', 'two', 'three']
```

Именованные группы можно использовать при замене:

```js
'2026-08-04'.replace(
  /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/,
  '$<day>.$<month>.$<year>',
)
```

В строке замены `$&` означает всё совпадение, `$1` — первую группу, `$<name>` — именованную группу. Вместо строки можно передать функцию.

## Динамический шаблон

Пользовательский текст нельзя вставлять как готовый шаблон: символы вроде `.` и `*` изменят смысл. `RegExp.escape()` создаёт безопасный фрагмент:

```js
const search = 'file.txt'
const pattern = new RegExp(RegExp.escape(search), 'i')

pattern.test('FILE.TXT') // true
```

`RegExp.escape()` экранирует обычную строку для помещения внутрь выражения, а не уже составленный шаблон.

## Практические шаблоны

Эти небольшие выражения показывают типичные проверки. Перед использованием в реальном проекте границы допустимого формата нужно уточнить по требованиям задачи.

```js
const integerPattern = /^-?\d+$/
const usernamePattern = /^[a-z][a-z0-9_-]{2,19}$/i
const hexColorPattern = /^#(?:[\da-f]{3}|[\da-f]{6})$/i
const isoDateShapePattern = /^\d{4}-\d{2}-\d{2}$/
```

Последний шаблон проверяет только форму и пропустит `2026-99-99`. Календарную корректность проверяют отдельно.

Не пытайтесь одной огромной регуляркой полностью проверять email, URL, HTML или формат со сложной грамматикой. Часто надёжнее специализированный парсер, `URL` и последующая бизнес-валидация.

## Частые ошибки

Большинство проблем возникает не из-за синтаксиса, а из-за неверно выбранных границ, экранирования или слишком широкого шаблона:

- забытые `^` и `$` при проверке всей строки;
- один обратный слеш вместо двух в строке для `new RegExp()`;
- `.` вместо экранированной точки;
- ожидание поддержки кириллицы от `\w`;
- захватывающие группы там, где достаточно `(?:...)`;
- динамический текст без `RegExp.escape()`;
- катастрофический backtracking во вложенных неоднозначных повторениях вроде `(a+)+`.

Флаги `g` и `y` изменяют `lastIndex`, поэтому повторный `test()` одного объекта бывает неожиданным:

```js
const pattern = /\d/g

pattern.test('1') // true, lastIndex стал 1
pattern.test('1') // false, поиск продолжился с позиции 1

pattern.lastIndex = 0
```

Для разовой валидации флаг `g` обычно не нужен.

## Как составлять выражение

1. Определите, должна совпасть вся строка или фрагмент.
2. Запишите подходящие и неподходящие примеры.
3. Начните с обычных символов и классов.
4. Добавьте `^` и `$` для всей строки.
5. Добавьте минимально необходимые группы и квантификаторы.
6. Проверьте пустую строку, Unicode, длинный ввод и пограничные значения.
7. Если шаблон трудно объяснить, разделите проверку на несколько шагов.
