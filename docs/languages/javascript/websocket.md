# WebSocket

В чате новое сообщение должно появиться у собеседника сразу, а не после очередного запроса «есть ли что-нибудь новое?». Опрашивать сервер по таймеру дорого и всё равно даёт задержку. WebSocket решает это постоянным двусторонним соединением: после установки обе стороны отправляют сообщения в любой момент, поэтому технология подходит для чатов, уведомлений, совместного редактирования и данных, которые должны обновляться почти сразу.

Обычный HTTP-запрос строится по схеме «клиент запросил — сервер ответил». WebSocket начинается с HTTP-рукопожатия, а затем переходит на отдельный протокол и сохраняет соединение открытым.

## Минимальный пример

```js
const socket = new WebSocket('wss://example.com/ws/tasks')

socket.addEventListener('open', () => {
  socket.send(JSON.stringify({ type: 'subscribe', userId: 42 }))
})

socket.addEventListener('message', (event) => {
  const message = JSON.parse(event.data)
  console.log(message.type, message.title)
  // task_created Купить хлеб
})

socket.addEventListener('close', (event) => {
  console.log(event.code) // 1000 — нормальное закрытие
})
```

Отправлять можно только после события `open`. Сообщения — строки, поэтому объект превращают в JSON перед отправкой и разбирают обратно при получении.

## Как это работает

### Создание соединения

В браузере соединение создаётся встроенным классом `WebSocket`. Для защищённой страницы используют адрес с протоколом `wss`, который шифрует передаваемые данные.

```js
const socket = new WebSocket('wss://example.com/ws/chat')
```

Конструктор возвращает объект сразу, не дожидаясь подключения. Результат установки соединения приходит позже через событие `open` или `error`.

Основные события:

- `open` — соединение установлено и можно отправлять сообщения;
- `message` — от сервера получено сообщение;
- `error` — произошла ошибка соединения;
- `close` — соединение закрыто клиентом, сервером или из-за потери связи.

### Отправка и получение сообщений

Метод `send()` принимает строку, `Blob`, `ArrayBuffer` или один из typed arrays. JavaScript-объект перед отправкой обычно преобразуют в JSON, а полученную строку — обратно в объект.

```js
const socket = new WebSocket('wss://example.com/ws/chat')

socket.addEventListener('open', () => {
  const message = { type: 'join', roomId: 42 }
  socket.send(JSON.stringify(message))
})

socket.addEventListener('message', (event) => {
  const message = JSON.parse(event.data)

  if (message.type === 'new_message') {
    console.log(message.text)
  }
})

socket.addEventListener('error', () => {
  console.error('Ошибка WebSocket')
})

socket.addEventListener('close', (event) => {
  console.log(event.code, event.reason)
})
```

Формат сообщений определяет само приложение. Поле `type` позволяет передавать через одно соединение разные события и выбирать нужный обработчик.

Данные от сервера являются внешними данными. Перед использованием нужно проверять структуру сообщения, даже если JSON разобрался без ошибки.

### Состояния соединения

Свойство `readyState` показывает текущее состояние WebSocket:

| Константа | Значение | Состояние |
| --- | ---: | --- |
| `WebSocket.CONNECTING` | `0` | подключение ещё устанавливается |
| `WebSocket.OPEN` | `1` | сообщения можно отправлять |
| `WebSocket.CLOSING` | `2` | началось закрытие соединения |
| `WebSocket.CLOSED` | `3` | соединение закрыто или не установилось |

Если сообщение отправляется не из обработчика `open`, состояние нужно проверить явно:

```js
function sendMessage(socket, message) {
  if (socket.readyState !== WebSocket.OPEN) {
    return false // сообщение не отправлено
  }

  socket.send(JSON.stringify(message))
  return true
}
```

Успешный вызов `send()` означает, что данные добавлены в очередь отправки, а не гарантированно обработаны сервером. Если подтверждение важно, сервер должен прислать отдельное сообщение с идентификатором операции.

### Закрытие соединения

Соединение следует закрывать, когда оно больше не нужно, например при выходе пользователя из чата.

```js
socket.close(1000, 'Пользователь вышел из чата') // 1000 — код нормального завершения
```

Код `1000` означает нормальное закрытие. Пользовательские коды приложения выбирают из диапазона `3000–4999`. Причина закрытия должна быть короткой строкой.

Событие `close` содержит полезные свойства:

- `code` — код закрытия;
- `reason` — переданная сторонами причина;
- `wasClean` — завершилось ли закрытие корректным WebSocket-handshake.

### Что важно учитывать

- браузер не восстанавливает потерянное WebSocket-соединение автоматически;
- повторное подключение обычно делают с постепенно увеличивающейся задержкой;
- сервер может использовать ping/pong или сообщения heartbeat для обнаружения оборванной связи;
- медленный клиент может накопить данные в `socket.bufferedAmount`;
- браузерный конструктор `WebSocket` не позволяет произвольно добавить заголовок `Authorization`;
- серверная реализация зависит от выбранной платформы или фреймворка.

## Частые ошибки

- `send()` вызван сразу после `new WebSocket(...)` → исключение `InvalidStateError`, потому что соединение ещё в состоянии `CONNECTING` → отправлять из обработчика `open` или проверять `readyState === WebSocket.OPEN`.
- В `send()` передан объект без `JSON.stringify()` → сервер получает строку `[object Object]` → сериализовать сообщение в JSON и разбирать `event.data` через `JSON.parse()`.
- Сообщение от сервера используется без проверки структуры → обработчик падает на неожиданном поле или `JSON.parse()` бросает исключение на невалидной строке → разбирать в `try/catch` и проверять `type` и обязательные поля.
- Нет переподключения после `close` → после потери сети приложение молча перестаёт получать обновления → переподключаться с нарастающей задержкой и показывать пользователю состояние соединения.
- Со страницы `https://` открыт адрес `ws://` → браузер блокирует небезопасное соединение (mixed content) → использовать `wss://`.

## Когда не использовать

WebSocket стоит выбирать, когда сервер действительно должен самостоятельно и часто отправлять изменения. Для редких обновлений обычный HTTP-запрос обычно проще в разработке, тестировании и эксплуатации: постоянное соединение требует переподключения, heartbeat и отдельной серверной инфраструктуры.

Если данные идут только от сервера к клиенту — лента событий, прогресс длинной операции, — проще Server-Sent Events: они работают поверх обычного HTTP, переподключаются сами и не требуют отдельного протокола. Для запросов по действию пользователя достаточно [`fetch`](requests.md).
