# Elasticsearch: полнотекстовый поиск

Пользователь ищет «отчёты» и ожидает увидеть задачу «Подготовить отчёт о продажах». В PostgreSQL `WHERE title LIKE '%отчёты%'` её не найдёт: другая форма слова. Опечатку «отчот» тоже не простит, а на миллионах строк `LIKE '%...%'` ещё и медленный. Elasticsearch сделан для такого поиска: он приводит слова к основе, терпит опечатки, сортирует результаты по релевантности и подсвечивает найденное.

```bash
docker run -d --name es -p 9200:9200 \
  -e discovery.type=single-node -e xpack.security.enabled=false -e ES_JAVA_OPTS="-Xms512m -Xmx512m" \
  docker.elastic.co/elasticsearch/elasticsearch:8.15.3

pip install "elasticsearch>=8,<9"
```

`xpack.security.enabled=false` отключает пароль и HTTPS. Так делают только на своей машине.

## Минимальный пример

```python
from elasticsearch import Elasticsearch

es = Elasticsearch('http://localhost:9200')

es.indices.create(index='tasks', mappings={
    'properties': {
        'title': {'type': 'text', 'analyzer': 'russian'},
        'done': {'type': 'boolean'},
        'owner': {'type': 'keyword'},
    },
})

es.index(index='tasks', id=1, document={'title': 'Купить хлеб и молоко', 'done': False, 'owner': 'anna'})
es.index(index='tasks', id=2, document={'title': 'Подготовить отчёт о продажах', 'done': False, 'owner': 'anna'})
es.indices.refresh(index='tasks')

response = es.search(index='tasks', query={'match': {'title': 'отчёты'}})
for hit in response['hits']['hits']:
    print(hit['_score'], hit['_source']['title'])
# 1.16 Подготовить отчёт о продажах
```

## Как это работает

**Индекс** — аналог таблицы, **документ** — JSON-объект, как в [MongoDB](../mongodb/basics.md). **Маппинг** описывает поля и то, как их обрабатывать.

Главное происходит при записи. Текст поля типа `text` проходит через **анализатор**: разбивается на слова, приводится к нижнему регистру, а русский анализатор ещё и отрезает окончания:

```python
es.indices.analyze(index='tasks', field='title', text='Подготовить отчёты о продажах')
# ['подготов', 'отчет', 'продаж']   — анализатор russian

es.indices.analyze(analyzer='standard', text='Подготовить отчёты о продажах')
# ['подготовить', 'отчёты', 'о', 'продажах']   — стандартный, без учёта языка
```

Из этих основ строится **инвертированный индекс** — как предметный указатель в конце книги: для каждого слова список документов, где оно встречается. Поисковый запрос проходит через тот же анализатор, поэтому «отчёты» превращается в `отчет` и сразу находит нужные документы.

Затем результаты сортируются по **релевантности** (`_score`): чем реже слово встречается во всём индексе и чем короче поле, в котором оно нашлось, тем выше оценка.

## Типы полей: `text` и `keyword`

- **`text`** — для поиска по смыслу: названия, описания. Анализируется, находится по отдельным словам.
- **`keyword`** — для точного совпадения, фильтров, сортировки и группировки: статусы, теги, логины. Хранится как есть.

```python
# term ищет точное значение и не анализирует запрос
es.search(index='tasks', query={'term': {'owner': 'anna'}})                 # найдёт
es.search(index='tasks', query={'term': {'title': 'Купить хлеб и молоко'}})  # 0 результатов!
```

Второй запрос ничего не находит: в индексе поля `title` лежат отдельные основы слов, а не исходная строка целиком.

## Основные запросы

**Опечатки** — `fuzziness`. `AUTO` разрешает одну-две ошибки в зависимости от длины слова:

```python
es.search(index='tasks', query={'match': {'title': 'отчот'}})
# 0 результатов

es.search(index='tasks', query={'match': {'title': {'query': 'отчот', 'fuzziness': 'AUTO'}}})
# 0.93 Подготовить отчёт о продажах
```

**Поиск по нескольким полям** с разным весом: совпадение в названии важнее, чем в описании:

```python
es.search(index='tasks', query={'multi_match': {'query': 'отчёт', 'fields': ['title^2', 'description']}})
```

**Поиск с фильтрами** — `bool`. В `must` — то, что влияет на релевантность, в `filter` — точные условия, которые только отсекают:

```python
es.search(index='tasks', query={'bool': {
    'must': [{'match': {'title': 'отчёт'}}],
    'filter': [
        {'term': {'done': False}},
        {'term': {'owner': 'anna'}},
        {'range': {'due_date': {'lte': '2026-10-31'}}},
    ],
}})
```

Условия в `filter` не считают `_score` и кэшируются, поэтому работают быстрее.

**Подсветка найденного:**

```python
response = es.search(
    index='tasks',
    query={'match': {'description': 'отчёт'}},
    highlight={'fields': {'description': {}}},
)
response['hits']['hits'][0]['highlight']
# {'description': ['Квартальные <em>отчёты</em> для руководителя']}
```

**Группировка** по `keyword`-полю — аналог `GROUP BY`:

```python
response = es.search(index='tasks', size=0, aggs={'by_tag': {'terms': {'field': 'tags'}}})
[(b['key'], b['doc_count']) for b in response['aggregations']['by_tag']['buckets']]
# [('дом', 2), ('работа', 2), ('срочно', 2)]
```

## Изменение и удаление

```python
es.update(index='tasks', id=2, doc={'done': True})
es.delete(index='tasks', id=2)
es.get(index='tasks', id=2)  # NotFoundError: 404
```

## Elasticsearch рядом с основной базой

Elasticsearch почти никогда не бывает основной базой: в нём нет транзакций и связей, а данные можно перестроить из источника. Обычная схема — данные живут в PostgreSQL, а в Elasticsearch лежит их копия для поиска. При каждом изменении задачи приложение обновляет документ в индексе — лучше через очередь или фоновую задачу, чтобы сбой поиска не ломал сохранение.

Если поиск нужен простой и данных немного, сначала попробуйте [полнотекстовый поиск PostgreSQL](https://www.postgresql.org/docs/current/textsearch.html) (`tsvector`, конфигурация `russian`) — он умеет основы слов и работает без отдельного сервера.

## Частые ошибки

- **Документ не находится сразу после записи.** Индекс обновляется примерно раз в секунду: поиск сразу после `es.index(...)` может его не увидеть. В тестах вызывайте `es.indices.refresh(...)` или передавайте `refresh='wait_for'`. В рабочем коде обновлять индекс после каждой записи не нужно — это дорого.
- **Маппинг «угадан» автоматически.** Без явного маппинга строка станет `text` с вложенным `keyword`, но с анализатором `standard` — и «отчёты» не найдут «отчёт». Задавайте маппинг заранее. Тип уже созданного поля поменять нельзя, только пересоздать индекс и переложить данные.
- **Анализатор — не волшебство.** Стеммер отрезает окончания по правилам и не знает однокоренных слов: «Отчитаться о поездке» по запросу «отчёт» не находится. Для синонимов и родственных слов настраивают словари синонимов.
- **Неверный формат данных.** Строка `'завтра'` в поле `date` не запишется: `document_parsing_exception: failed to parse field [due_date] of type [date]`.
- **Отключённая безопасность в продакшене.** Открытый Elasticsearch в интернете находят и выкачивают за часы.

## Когда не использовать

Для поиска по точному значению — логину, статусу, id, метке — Elasticsearch лишний: это обычный `WHERE` с индексом в PostgreSQL. С него же стоит начать и полнотекстовый поиск, если данных немного и хватает основ слов без опечаток и тонкой релевантности: `tsvector` с конфигурацией `russian` не требует отдельного сервера и второй копии данных.

Elasticsearch не годится как основное хранилище: нет транзакций, связей и строгих ограничений, а документ после записи виден не сразу. Деньги, заказы и пользователи живут в реляционной базе, в индексе лежит их копия для поиска. Если нужны вложенные документы ради хранения, а не поиска, это задача [MongoDB](../mongodb/basics.md).
