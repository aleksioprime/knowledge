# Степени и логарифмы

Логарифм отвечает на вопрос «сколько раз нужно поделить `n` пополам, чтобы дойти до 1», и этот вопрос разработчик задаёт постоянно: сколько шагов сделает бинарный поиск, сколько бит хранит число, почему сортировка стоит `O(n log n)`. Степени — обратная операция, и их правила объясняют, почему логарифм превращает умножение в сложение.

## Минимальный пример

Бинарный поиск в миллионе элементов укладывается в 20 шагов — ровно `log₂(1 000 000)`, округлённый вверх. Та же величина говорит, сколько бит нужно, чтобы записать число.

```python run
import math

for size in (1024, 1_000_000, 1_000_000_000):
    print(size, math.ceil(math.log2(size)))
# 1024 10
# 1000000 20
# 1000000000 30

print(2 ** 10)               # 1024
print(math.log2(1024))       # 10.0 — в какую степень возвести 2, чтобы получить 1024
print(math.log(1000, 10))    # 2.9999999999999996 — логарифм по произвольному основанию считается с погрешностью
print(math.log10(1000))      # 3.0 — для 10 и 2 есть точные функции
print((255).bit_length())    # 8 — бит для хранения числа; то же, что ⌊log₂(255)⌋ + 1
```

## Как это работает

### Возведение в степень

Степень — это короткая запись умножения числа само на себя:
```
a^n = a · a · … · a   (n раз)
```

Пример:
```
2^3 = 2 · 2 · 2 = 8
5^2 = 25
10^4 = 10000
```

- `a` — **основание**
- `n` — **показатель степени**

**Свойства степеней.** Очень важно помнить эти 5 правил:

```
a^m · a^n = a^(m+n)        →   2^3 · 2^4 = 2^7 = 128
a^m / a^n = a^(m-n)        →   2^5 / 2^2 = 2^3 = 8
(a^m)^n   = a^(m·n)        →   (2^3)^2 = 2^6 = 64
(a·b)^n   = a^n · b^n      →   (2·3)^2 = 4·9 = 36
(a/b)^n   = a^n / b^n
```

**Особые случаи.**

```
a^0 = 1   для любого a ≠ 0    (договорённость, удобная для формул)
a^1 = a
a^(-n) = 1 / a^n              →   2^(-3) = 1/8
```

**Дробные степени = корни.**

```
a^(1/n) = ⁿ√a       (корень n-й степени)
a^(m/n) = ⁿ√(a^m)
```

Примеры:
```
9^(1/2)  = √9 = 3
8^(1/3)  = ∛8 = 2
27^(2/3) = ∛(27²) = ∛729 = 9
```

В Python:
```python run
print(2 ** 10)          # 1024
print(2 ** -3)          # 0.125
print(9 ** 0.5)         # 3.0
print(pow(8, 1/3))      # 2.0
print(2 ** 100)         # 1267650600228229401496703205376 — целые не переполняются
```

### Логарифм

**Логарифм — это обратная операция к возведению в степень.**

Вопрос: «в какую степень нужно возвести `a`, чтобы получить `b`?»

```
log_a(b) = c    ⟺    a^c = b
```

Примеры:
```
log_2(8)   = 3        потому что 2^3 = 8
log_10(100) = 2       потому что 10^2 = 100
log_5(1)   = 0        потому что 5^0 = 1
log_2(1024) = 10      потому что 2^10 = 1024
```

Читается «логарифм по основанию `a` от числа `b`».

**Свойства логарифмов.** Зеркальны правилам степеней — отсюда и польза:

```
log_a(x · y) = log_a(x) + log_a(y)        ← умножение → сложение
log_a(x / y) = log_a(x) - log_a(y)        ← деление → вычитание
log_a(x^n)   = n · log_a(x)               ← степень → коэффициент
log_a(1)     = 0
log_a(a)     = 1
```

Главная идея: **логарифмы превращают умножение в сложение**. Поэтому до появления калькуляторов их использовали для ручных расчётов, а сегодня — чтобы перемножать тысячи вероятностей, не уходя в ноль.

**Замена основания.**

```
log_a(b) = log_c(b) / log_c(a)
```

Удобно, чтобы посчитать `log_2(x)` через `log_10` или `ln`:
```python run
import math

print(math.log(8, 2))       # 3.0  — логарифм 8 по основанию 2
print(math.log10(1000))     # 3.0  — десятичный
print(math.log(math.e))     # 1.0  — натуральный (ln, основание e)
print(math.log2(1024))      # 10.0 — двоичный
print(math.log(8) / math.log(2))   # 3.0 — замена основания вручную
```

### Где это нужно разработчику

**1. Оценка сложности алгоритмов (Big-O)**

`log₂(n)` — сколько раз можно поделить `n` пополам, пока не получится 1.

```
n = 1024           →   log₂(1024) = 10 шагов
n = 1_000_000      →   ~20 шагов
n = 1_000_000_000  →   ~30 шагов
```

Алгоритмы со сложностью `O(log n)`: бинарный поиск, операции в сбалансированном дереве поиска, в куче.
Алгоритмы `O(n log n)`: сортировки слиянием и пирамидальная, быстрая (в среднем).

Основание логарифма в `O`-нотации не пишут: `log₂ n` и `log₁₀ n` отличаются постоянным множителем `log₂ 10 ≈ 3.32`, а константы в нотации отбрасываются.

**2. Биты и числа**

```
log₂(N) = сколько бит нужно для записи N значений
log₂(256) = 8 бит  →  можно хранить 256 значений
log₂(2^32) = 32 бита
```

**3. Шкалы**

Логарифмическая шкала: децибелы (звук), магнитуда землетрясений, pH. Каждая «единица» — умножение в 10 раз.

**4. ML и статистика**

Логарифм правдоподобия (log-likelihood) устойчивее по числам, чем произведение тысячи вероятностей меньше 1: произведение уйдёт в ноль, а сумма логарифмов — нет.

```python run
import math

probabilities = [0.5] * 2000
print(math.prod(probabilities))                  # 0.0 — произведение «исчезло» в float
print(sum(math.log(p) for p in probabilities))   # -1386.29... — сумма логарифмов осталась числом
```

## Частые ошибки

- `math.log(x)` принят за десятичный логарифм → `math.log(100)` даёт `4.605`, а не `2` → десятичный — `math.log10`, двоичный — `math.log2`.
- `math.log(1000, 10)` вместо `math.log10(1000)` → `2.9999999999999996`, и `int()` от него даёт `2` → для оснований 2 и 10 брать специальные функции, для остальных округлять через `round` или `math.isclose`.
- Логарифм от нуля или отрицательного числа → `ValueError: math domain error` → проверять аргумент или прибавлять малую константу: `math.log(count + 1)`.
- Пропущены скобки в показателе: `2 ** 3 * 2` вместо `2 ** (3 * 2)` → `**` имеет более высокий приоритет, чем `*`, получается 16 вместо 64 → ставить скобки в показателе.
- `x ** 0.5` или `pow(8, 1/3)` для целочисленного корня → `pow(64, 1/3)` даёт `3.9999999999999996` → для целых использовать `math.isqrt(n)` или `round(n ** (1/3))` с проверкой.

## Когда не использовать

Логарифм и дробная степень возвращают `float`, поэтому для целочисленных задач они лишние: число бит — `n.bit_length()`, целый квадратный корень — `math.isqrt(n)`, проверка «степень двойки» — `n & (n - 1) == 0`. Эти способы точны, а `int(math.log2(n))` на граничных значениях ошибается на единицу.

Большие степени не нужно считать через `exp(n · ln a)`: Python умножает целые без переполнения, а `pow(a, b, m)` считает степень по модулю за логарифм шагов. Если же логарифм берётся от результата, где важна точность малых значений — `log(1 + x)` при крошечном `x`, — лучше `math.log1p`, чем формула в лоб.
