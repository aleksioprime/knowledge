# Шаблон заметки

Скопируйте этот файл, переименуйте и замените текст в разделах. Разделы, которые не подходят теме, можно убрать: шаблон помогает не забыть важное, а не заставляет писать лишнее.

---

# Название темы

Одно-два предложения: какую проблему решает инструмент или приём. Пишите от задачи, а не от определения.

> Пример: «Логгер нужен, когда `print` уже не помогает: сообщения смешиваются, их нельзя отключить и непонятно, откуда они пришли».

## Минимальный пример

Код на 5–20 строк, который можно скопировать и запустить. Результат показывайте в комментарии или отдельным блоком.

```python
from dataclasses import dataclass


@dataclass
class Task:
    title: str
    done: bool = False


print(Task('Купить хлеб'))  # Task(title='Купить хлеб', done=False)
```

## Как это работает

Объяснение простыми словами. Если помогает — бытовая аналогия. Затем подробности, которые нужны на практике.

## Частые ошибки

- Ошибка → чем она проявляется → как исправить.

## Когда не использовать

Где инструмент лишний и что выбрать вместо него.

## Правила стиля

**Текст**

- Сначала задача, потом решение. Читатель должен понять, *зачем*, до того как узнает, *как*.
- Короткие абзацы и обычные слова. Термин объясняем по-русски, английское название — в скобках: «подсказки типов (type hints)».
- Одна мысль — один абзац. Списки — для перечислений, а не для связного объяснения.

**Код**

- Пример должен запускаться. Перед добавлением прогоните его.
- Имена из жизни: `user`, `task`, `order`, а не `foo` и `x`.
- Комментарий пишем, только если он показывает результат (`# 42`) или объясняет неочевидное (`# копируется ссылка, а не объект`). Комментарий-пересказ (`# создаём переменную`) не нужен.
- Сквозной пример — учебный проект [«Задачник»](docs/practice/projects/tasker/README.md): задачи, пользователи, сроки. Если тема ложится на него, берите примеры оттуда.
