# Шифрование, хеширование и пароли

В «Задачнике» хранятся пароли, а в профиле появился телефон. Отсюда сразу несколько вопросов: можно ли хранить пароль так, чтобы даже администратор базы его не узнал; как спрятать телефон, но уметь его прочитать; почему payload JWT виден всем, а подделать токен нельзя. Ответы зависят от того, какое из четырёх преобразований данных нужно: кодирование, хеширование, подпись или шифрование. Их часто путают, и отсюда берутся ошибки вроде «пароль в base64» или «секрет в payload токена».

```bash
pip install cryptography argon2-cffi bcrypt
```

## Четыре разных преобразования

| Что | Обратимо? | Нужен ключ? | Для чего |
| --- | --- | --- | --- |
| Кодирование (base64, URL-encoding) | да, кем угодно | нет | передать байты там, где разрешён только текст |
| Хеширование (SHA-256, argon2) | нет | нет | отпечаток данных, хранение паролей |
| HMAC и цифровая подпись | нет | да | доказать, что данные не меняли и их выпустил владелец ключа |
| Шифрование (AES, RSA) | да, с ключом | да | скрыть содержимое |

**Кодирование** — не защита. Payload JWT читается одной строкой:

```python
import base64
import json

token = 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxIiwiZXhwIjoxNzkzMjE2NDg2fQ.sig'
print(json.loads(base64.urlsafe_b64decode(token.split('.')[1] + '==')))
# {'sub': '1', 'exp': 1793216486}
```

**Хеш** — отпечаток фиксированной длины: по нему нельзя восстановить данные, но одинаковые данные дают одинаковый хеш. Подходит для проверки целостности файла или ключа кэша.

**HMAC** — хеш, в который подмешан секретный ключ. Посчитать правильный HMAC может только тот, кто знает ключ. Так подписан JWT с алгоритмом HS256 и cookie сессии во Flask и Starlette.

```python
import hashlib
import hmac

key = b'server-secret'
tag = hmac.new(key, b'task:42:done', hashlib.sha256).hexdigest()
expected = hmac.new(key, b'task:42:done', hashlib.sha256).hexdigest()
print(hmac.compare_digest(tag, expected))  # True
```

**Шифрование** скрывает содержимое, но без ключа ничего не доказывает, если это не шифр с проверкой целостности (о нём ниже).

### Сравнение за постоянное время

Обычное `==` останавливается на первом несовпавшем символе. Если атакующий может отправить тысячи запросов и измерить время ответа, он угадывает подпись или токен по одному символу. `hmac.compare_digest` сравнивает строки целиком за одинаковое время. Его используют везде, где сравнивают секрет: подпись вебхука, API-ключ, токен сброса пароля. Функции проверки паролей (`argon2`, `bcrypt`) делают это сами.

## Симметричное шифрование

Один и тот же ключ шифрует и расшифровывает. Это быстро и подходит для больших объёмов, но ключ должен быть у обеих сторон, и его нужно как-то им передать.

Стандарт — **AES-GCM**. Это AEAD-шифр (authenticated encryption with associated data): он не только прячет данные, но и добавляет тег, по которому расшифровка обнаружит любое изменение шифротекста. Голый AES в режимах вроде CBC без отдельной проверки целостности позволяет атакующему незаметно портить данные.

```python
import os

from cryptography.hazmat.primitives.ciphers.aead import AESGCM

key = AESGCM.generate_key(bit_length=256)
aes = AESGCM(key)

nonce = os.urandom(12)                        # новый для каждого сообщения
user_id = b'user:1'                           # связанные данные: не шифруются, но защищены
ciphertext = aes.encrypt(nonce, b'+7 900 123-45-67', user_id)
print(len(ciphertext))                        # 32: 16 байт текста + 16 байт тега

print(aes.decrypt(nonce, ciphertext, user_id))  # b'+7 900 123-45-67'
aes.decrypt(nonce, ciphertext, b'user:2')        # InvalidTag
```

Последняя строка показывает, зачем нужны связанные данные: если злоумышленник с доступом к базе скопирует зашифрованный телефон Анны в строку Бориса, расшифровка не пройдёт. Нонс хранится рядом с шифротекстом, он не секретный, но **не должен повторяться** с тем же ключом: повтор в GCM раскрывает данные и позволяет подделывать теги.

Если не хочется думать о нонсах, есть **Fernet** из той же библиотеки — готовый рецепт (AES-CBC + HMAC + метка времени) с одним методом на шифрование и один на расшифровку:

```python
from cryptography.fernet import Fernet

key = Fernet.generate_key()          # хранить вне базы
fernet = Fernet(key)

token = fernet.encrypt('+7 900 123-45-67'.encode())
print(len(token))                    # 120 — заметно длиннее исходных 16 байт
print(fernet.decrypt(token).decode())  # +7 900 123-45-67

Fernet(Fernet.generate_key()).decrypt(token)  # InvalidToken
```

`MultiFernet([new, old])` позволяет сменить ключ: шифрует новым, расшифровывает любым, а `rotate()` перешифровывает старые записи.

## Асимметричное шифрование и подпись

У каждой стороны пара ключей: **закрытый** хранит владелец, **открытый** можно раздавать всем. Операции работают в двух направлениях:

- **шифрование**: открытым ключом шифрует кто угодно, расшифровать может только владелец закрытого;
- **подпись**: закрытым ключом подписывает владелец, проверить открытым может кто угодно.

```python
from cryptography.exceptions import InvalidSignature
from cryptography.hazmat.primitives.asymmetric import ed25519

private_key = ed25519.Ed25519PrivateKey.generate()
public_key = private_key.public_key()

message = b'{"sub":"1","role":"user"}'
signature = private_key.sign(message)          # 64 байта
public_key.verify(signature, message)           # нет исключения — подпись верна
public_key.verify(signature, b'{"sub":"1","role":"admin"}')  # InvalidSignature
```

Алгоритмы: **RSA** (старый и универсальный, ключ 2048+ бит, умеет и шифровать, и подписывать), **ECDSA** (на эллиптических кривых, ключи короче), **Ed25519** (современная подпись, быстрая и без подводных камней со случайными числами). Асимметрия в сотни раз медленнее симметрии, поэтому большие данные ей не шифруют: шифруют случайный симметричный ключ, а данные — им.

### HS256 и RS256 в JWT

Разница не в стойкости, а в том, **кто может выпускать токены**:

- **HS256** — HMAC с общим секретом. Кто может проверить токен, тот может и выпустить его. Годится, когда выпускает и проверяет одно приложение, как в [JWT в FastAPI](../../frameworks/fastapi/auth_jwt.md).
- **RS256/ES256/EdDSA** — подпись закрытым ключом. Выпускает только сервер авторизации, а проверяют все сервисы по открытым ключам. Так работает [Keycloak](../../microservices/keycloak/README.md): ключи публикуются в JWKS, и взлом одного сервиса не даёт права выпускать токены.

## Где всё это в TLS

[TLS](../http/https_tls.md) собирает все приёмы вместе. Сервер подтверждает, что владеет ключом из сертификата, **подписью**, а сертификат подписан центром сертификации. Стороны договариваются об общем ключе через обмен Диффи — Хеллмана (ECDHE), не передавая его по сети. Дальше трафик шифруется **симметрично** (AES-GCM или ChaCha20-Poly1305), потому что это быстро. Хеш-функции используются при выводе ключей и в подписях.

## Хранение паролей

### Почему не sha256

SHA-256 создан быть **быстрым** — а для паролей это плохо. Если базу украли, атакующий перебирает словарь популярных паролей и сравнивает хеши. Замер на ноутбуке (Apple M1, Python 3.12, хеши считаются по одному в цикле):

```text
sha256:      1,971,869 хешей/с
pbkdf2:           12.8 хешей/с   (SHA-256, 600 000 итераций)
bcrypt12:          4.0 хешей/с   (cost 12)
scrypt:            3.8 хешей/с   (n=2^17, r=8, p=1)
argon2id:         18.4 хешей/с   (настройки argon2-cffi по умолчанию: t=3, m=64 МиБ, p=4)
```

Скрипт замера:

```python
import hashlib
import time

import bcrypt
from argon2 import PasswordHasher


def rate(func, seconds=2.0):
    count, start = 0, time.perf_counter()
    while time.perf_counter() - start < seconds:
        func()
        count += 1
    return count / (time.perf_counter() - start)


argon = PasswordHasher()
salt = bcrypt.gensalt(rounds=12)
password = b'secret123'

print(f'sha256:   {rate(lambda: hashlib.sha256(password).digest()):>12,.0f} хешей/с')
print(f'pbkdf2:   {rate(lambda: hashlib.pbkdf2_hmac("sha256", password, b"salt", 600_000)):>12,.1f} хешей/с')
print(f'bcrypt12: {rate(lambda: bcrypt.hashpw(password, salt)):>12,.1f} хешей/с')
print(f'scrypt:   {rate(lambda: hashlib.scrypt(password, salt=b"salt", n=2**17, r=8, p=1, maxmem=2**28)):>12,.1f} хешей/с')
print(f'argon2id: {rate(lambda: argon.hash("secret123")):>12,.1f} хешей/с')
```

Для SHA-256 цифра занижена накладными расходами Python: видеокарта считает миллиарды таких хешей в секунду. Разница со специальными функциями — пять-восемь порядков. Пароль из восьми строчных букв и цифр (около 2,8·10¹² вариантов) при миллиарде SHA-256 в секунду перебирается меньше чем за час.

### Соль

Без соли одинаковые пароли дают одинаковые хеши:

```python
import hashlib

for user, password in [('anna', 'qwerty123'), ('boris', 'qwerty123')]:
    print(user, hashlib.sha256(password.encode()).hexdigest()[:16])
# anna daaad6e5604e8e17
# boris daaad6e5604e8e17
```

Это значит, что по базе видно, у кого пароли совпадают, а хеши популярных паролей можно посчитать заранее и просто искать в готовой таблице (rainbow tables и их упрощённый вариант — словарь «хеш → пароль»).

**Соль** — случайная строка, которую подмешивают к паролю перед хешированием. Она должна быть **уникальной для каждого пользователя** и храниться рядом с хешем — она не секрет. Одна статическая соль на всё приложение защищает только от чужих готовых таблиц: атакующий посчитает свою таблицу один раз, и одинаковые пароли по-прежнему будут видны. С уникальной солью перебирать приходится для каждого пользователя отдельно.

Современные функции генерируют соль сами и кладут её в строку хеша:

```python
from argon2 import PasswordHasher

ph = PasswordHasher()
print(ph.hash('qwerty123'))
print(ph.hash('qwerty123'))
# $argon2id$v=19$m=65536,t=3,p=4$xNHwWsFdW2eANblDqFBR1Q$ETso3OEWxDWDh0TYAqx5VSEX+Jf9WQryq6lT1xDMg/o
# $argon2id$v=19$m=65536,t=3,p=4$3hBRGQoQPUT27maXlIloBg$6A/igU4qsJlpb20BvYgxK1G29Ri7mckXh4WmRT755yg
```

В строке всё, что нужно для проверки: алгоритм, версия, параметры, соль и сам хеш. Поэтому отдельная колонка для соли не нужна.

### Перец

**Перец (pepper)** — ещё один секрет, общий для всех пользователей, но хранящийся **вне базы**: в переменной окружения, хранилище секретов или HSM. Если утекла только база (SQL-инъекция, украденный бэкап), без перца хеши перебрать нельзя вообще.

```python
import hashlib
import hmac
import os

from argon2 import PasswordHasher

PEPPER = os.environ.get('PASSWORD_PEPPER', 'dev-only-pepper').encode()
hasher = PasswordHasher()


def peppered(password: str) -> str:
    return hmac.new(PEPPER, password.encode(), hashlib.sha256).hexdigest()


stored = hasher.hash(peppered('secret123'))
print(hasher.verify(stored, peppered('secret123')))  # True
```

Цена — перец нельзя потерять и трудно сменить: при смене нужно хранить версию перца рядом с хешем и пересчитывать при входе. Это дополнительная мера, а не замена медленной функции.

### Какую функцию выбрать

- **argon2id** — рекомендация OWASP по умолчанию. Требует много памяти, поэтому перебор на видеокартах и специализированных чипах дорог. Минимум по OWASP — `m=19 МиБ, t=2, p=1`; в `argon2-cffi` по умолчанию `m=64 МиБ, t=3, p=4`.
- **bcrypt** — проверен временем, есть везде. Параметр — cost (`12` значит 2¹² раундов). Ограничение: учитываются только первые **72 байта** пароля. Старые версии библиотеки молча обрезали длинный пароль, `bcrypt` 5.0 бросает исключение:

  ```python
  import bcrypt

  hashed = bcrypt.hashpw(b'a' * 72, bcrypt.gensalt())
  bcrypt.checkpw(b'a' * 72 + b'-anything', hashed)
  # ValueError: password cannot be longer than 72 bytes, truncate manually if necessary (e.g. my_password[:72])
  ```

  В UTF-8 кириллица занимает 2 байта на символ, так что предел — 36 русских букв.
- **scrypt** — тоже требует памяти, есть в стандартной библиотеке (`hashlib.scrypt`).
- **PBKDF2** — только когда нужна сертификация FIPS. Для SHA-256 OWASP советует 600 000 итераций. Память не нагружает, поэтому на видеокартах перебирается легче остальных.

Стоимость подбирают так, чтобы проверка занимала порядка 50–500 мс на сервере: пользователь задержки не заметит, а перебор станет медленнее в миллионы раз. Медленная функция — это ещё и нагрузка на CPU, поэтому вход нужно [ограничивать по частоте](server_attacks.md#отказ-в-обслуживании).

### Повышение стоимости со временем

Железо дешевеет, и параметры пятилетней давности становятся слабыми. Пересчитать старые хеши без паролей нельзя, но в момент входа пароль известен — тогда и пересчитывают:

```python
from argon2 import PasswordHasher
from argon2.exceptions import VerifyMismatchError

old_hasher = PasswordHasher(time_cost=1, memory_cost=19 * 1024)
stored_hash = old_hasher.hash('secret123')

hasher = PasswordHasher()                       # текущие параметры: t=3, m=64 МиБ


def login(password: str) -> bool:
    global stored_hash
    try:
        hasher.verify(stored_hash, password)
    except VerifyMismatchError:
        return False
    if hasher.check_needs_rehash(stored_hash):
        stored_hash = hasher.hash(password)      # в приложении — UPDATE user SET password_hash = ...
        print('пересчитан:', stored_hash[:30])
    return True


print(stored_hash[:30])     # $argon2id$v=19$m=19456,t=1,p=4
print(login('wrong'))       # False
print(login('secret123'))   # пересчитан: $argon2id$v=19$m=65536,t=3,p=4  → True
print(login('secret123'))   # True — второй раз пересчитывать не нужно
```

`verify` проверяет хеш по параметрам, записанным в нём самом, а `check_needs_rehash` сравнивает их с текущими. Так же переезжают с bcrypt на argon2: при входе проверяют старым алгоритмом и сохраняют новый хеш. Библиотека `pwdlib`, которая используется в [JWT в FastAPI](../../frameworks/fastapi/auth_jwt.md), делает это одним вызовом `verify_and_update`.

## Шифрование полей в базе

Телефон или паспортные данные пользователя иногда нужно читать (отправить SMS), поэтому хешировать их нельзя — только шифровать. Шифрование на уровне приложения (AES-GCM или Fernet, как выше) защищает от утечки бэкапа, дампа или доступа к базе через SQL-инъекцию в другом сервисе.

Самое важное — **где ключ**. Ключ в той же базе или в репозитории ничего не защищает. Варианты по возрастанию надёжности:

1. переменная окружения, задаваемая при деплое (минимум);
2. хранилище секретов: HashiCorp Vault, Yandex Lockbox, AWS Secrets Manager;
3. KMS: ключ шифрования ключей (KEK) никогда не покидает сервис, а приложение получает от него расшифрованный ключ данных (DEK) — схема envelope encryption.

Что теряется при шифровании: по зашифрованному полю нельзя искать и сортировать. Если нужен поиск «есть ли пользователь с таким телефоном», рядом хранят **слепой индекс** — HMAC от нормализованного телефона с отдельным ключом — и ищут по нему. Ещё одна альтернатива — шифрование на уровне диска или СУБД (TDE): оно защищает от кражи диска, но не от того, кто читает базу через SQL.

## Частые ошибки

- **«Шифрование» паролей.** Пароль, который можно расшифровать, утечёт вместе с ключом. Пароли только хешируют медленной функцией.
- **Свой криптоалгоритм или свой режим AES.** Берите готовые рецепты: `Fernet`, `AESGCM`, `argon2-cffi`. Библиотека `cryptography` недаром прячет низкоуровневые примитивы в модуль `hazmat` («опасные материалы»).
- **Повтор нонса в AES-GCM.** Нонс из счётчика, который сбрасывается при перезапуске, или фиксированный нонс ломают шифр. Генерируйте `os.urandom(12)` для каждого сообщения.
- **Секретное в payload JWT.** Это base64, а не шифрование. Если данные нужно скрыть, их не кладут в токен (или используют JWE, но это редкость).
- **`random` для токенов и солей.** Модуль `random` предсказуем. Для секретов — `secrets.token_urlsafe()` и `os.urandom()`.
- **Сравнение подписей через `==`.** Используйте `hmac.compare_digest`.
- **Обрезанный пароль в bcrypt.** Пароли длиннее 72 байт либо ограничивайте при регистрации, либо выбирайте argon2id.
