# Работа с цветами

На фотографии «красный» никогда не бывает `(0, 0, 255)`: сжатие JPEG, освещение и камера сдвигают каждый канал на десятки единиц. Поэтому цвет сравнивают не точно, а с допуском, усредняют по области и ищут ближайший из набора эталонов. Все эти операции — арифметика над массивом NumPy.

## Минимальный пример

Средний цвет области и проверка, похож ли он на эталон. Изображение 4×4 залито почти чистым красным с шумом, и среднее по области всё равно близко к `(0, 0, 255)`.

```python
import cv2
import numpy as np

image = np.full((4, 4, 3), (10, 5, 240), dtype=np.uint8)   # «красный» с искажениями, BGR
image[0, 0] = (30, 20, 200)

average = np.mean(image, axis=(0, 1))           # среднее по строкам и столбцам, отдельно по каналам
print(average)                                  # [ 11.25     5.9375 237.5   ]

reference = np.array([0, 0, 255])
print(np.all(np.abs(average - reference) < 30))   # True — каждый канал отличается меньше чем на 30

binary = np.where(image > 200, 255, 0).astype(np.uint8)   # бинаризация по порогу
cv2.imwrite('binary.png', binary)
```

## Как это работает

### Обработка цветов с учётом искажений

Из-за искажений в формате JPEG, освещения и особенностей камеры важно иметь способы корректировать и округлять цвета. Простейший приём — порог: `np.where(условие, 255, 0)` заменяет все значения выше порога на 255, остальные на 0.

```python
import cv2
import numpy as np

image = cv2.imread('image.jpg')

rounded = np.where(image > 200, 255, 0).astype(np.uint8)   # без astype получится int64
cv2.imwrite('result_image.png', rounded)
```

### Вычисление среднего цвета

`np.mean()` считает среднее элементов массива. Два параметра важны для изображений:

- `axis` — оси, вдоль которых усреднять. `axis=(0, 1)` сворачивает строки и столбцы и оставляет по одному числу на канал.
- `dtype` — тип результата, например `np.int32`, чтобы получить целые значения.

```python
avg_all = np.mean(image)
print(avg_all)                      # 129.72916666666666 — одно число по всем пикселям и каналам

avg_channels = np.mean(image, axis=(0, 1), dtype=np.int32)
print(avg_channels)                 # [249  87  51] — средние по каналам B, G, R
```

### Сравнение цвета с эталоном

Проверка состоит из двух шагов: вычислить средний цвет области и убедиться, что он отличается от эталонного не больше чем на допуск по каждому каналу.

```python
def check_color(img, color, tolerance=30):
    avg_color = np.mean(img, axis=(0, 1))
    return np.all(np.abs(avg_color - color) < tolerance)

region = image[100:150, 200:250]              # область 50×50 пикселей
print(check_color(region, (0, 0, 255)))       # True, если область в среднем красная
```

`avg_color - color` даёт массив разностей по каналам, `np.abs` убирает знак отклонения, сравнение с `tolerance` превращает разности в три булевых значения, а `np.all` требует, чтобы подошли все три канала. Если хотя бы один канал выбивается, результат `False`.

### Сравнение цвета с ближайшим эталоном

Когда эталонов несколько, ищут тот, до которого цвет ближе всего. Расстоянием служит евклидово — длина отрезка между двумя точками в трёхмерном пространстве `(B, G, R)`, его считает `np.linalg.norm`.

```python
def find_closest_color(color, color_dict):
    closest_color = None
    min_distance = float('inf')
    for reference in color_dict:
        distance = np.linalg.norm(np.array(color) - np.array(reference))
        if distance < min_distance:
            min_distance = distance
            closest_color = color_dict[reference]
    return closest_color
```

Эталоны задаются словарём «BGR → название»:

```python
colors = {
    (255, 255, 255): "белый",
    (255, 0, 0): "синий",
    (0, 255, 0): "зелёный",
    (0, 0, 255): "красный",
    (255, 255, 0): "голубой",
    (255, 0, 255): "пурпурный",
    (0, 255, 255): "жёлтый",
    (0, 0, 0): "чёрный",
    (128, 128, 128): "серый",
    (128, 0, 0): "тёмно-синий",
    (0, 128, 0): "тёмно-зелёный",
    (0, 0, 128): "тёмно-красный",
    (128, 128, 0): "оливковый",
    (255, 128, 128): "розовый",
    (255, 128, 0): "оранжевый",
}

color = [100, 150, 200]
print(find_closest_color(color, colors))   # серый
```

Тот же поиск без цикла: собрать эталоны в массив формы `(n, 3)` и посчитать все расстояния сразу.

```python
references = np.array(list(colors))                  # (15, 3)
names = list(colors.values())
distances = np.linalg.norm(references - np.array(color), axis=1)
print(names[np.argmin(distances)])                   # серый
```

## Частые ошибки

- Результат `np.where(image > 200, 255, 0)` сохранён или передан в OpenCV без приведения типа → `int64`, файл чёрный или `cv2.error` → `.astype(np.uint8)`.
- Разность цветов на `uint8` → `np.array([10], dtype=np.uint8) - 50` даёт `216`, расстояние считается неверно → переводить в `int` или `float` до вычитания; `np.mean` уже возвращает `float`.
- Эталоны записаны в RGB → `(255, 0, 0)` в OpenCV — синий, и «красный» объект определяется как синий → хранить эталоны в BGR или один раз перевести изображение через `cvtColor`.
- `np.mean(image)` без `axis` для среднего цвета → одно число вместо трёх → `axis=(0, 1)`.
- Слишком маленький или большой допуск → при `tolerance=5` цвет не распознаётся из-за шума, при `100` красный путается с розовым → подбирать на реальных кадрах, начиная с 30–40.
- Среднее по области с фоном → фон перетягивает средний цвет, объект определяется неверно → сначала выделить объект маской и усреднять только его пиксели: `image[mask]`.

## Когда не использовать

Сравнение в BGR плохо переносит смену освещения: в тени все три канала падают, и красный объект оказывается ближе к «тёмно-красному» или «чёрному». Если условия съёмки меняются, переводят в HSV (`cv2.cvtColor(image, cv2.COLOR_BGR2HSV)`) и сравнивают тон (Hue) отдельно от яркости, а диапазон задают через `cv2.inRange`.

Для порогов с подбором значения есть `cv2.threshold` и адаптивный `cv2.adaptiveThreshold`, для усреднения по областям — `cv2.blur` и `cv2.resize`. Они учитывают `uint8` и работают быстрее самодельных формул.
