# Обработка исключений

Исключения нужны, когда операция может не получиться: файл не открылся, в строке не число, деление на ноль. Без обработки программа упадёт на первой же ошибке, а с «глотающим» `except` — продолжит работать с неверными данными. `try`/`except` позволяет решить, что делать в каждом случае: подставить резервное значение, сообщить пользователю или передать ошибку выше.

## Минимальный пример

```python run
a = 10
b = 0

try:
    # код, который может завершиться ошибкой
    result = a / b
except ZeroDivisionError:
    # выполняется, если в try возникла указанная ошибка (блоков except может быть несколько)
    result = None  # резервное значение
else:
    # выполняется, если в try ошибок не было
    ...
finally:
    # выполняется в любом случае
    ...

print(result)  # None
```

## Как это работает

Когда в блоке `try` возникает ошибка, интерпретатор прерывает выполнение и ищет подходящий `except` — сначала в текущей функции, затем у той, что её вызвала, и так до самого верха. Если обработчик не найден, программа завершается с трассировкой. Блок `else` выполняется только при успехе, а `finally` — всегда, поэтому в него кладут освобождение ресурсов.

### Несколько блоков `except`

Срабатывает первый подходящий блок `except`, поэтому более конкретные исключения ставят выше общих.

```python run
try:
    raise ValueError(1)
except ValueError:
    print("ValueError")  # сработает этот блок
except Exception:
    # если поставить этот блок первым, сработает он: Exception — базовый класс для ValueError
    print("Exception")
```

В одном `except` можно перечислить несколько типов кортежем. Если исключение не подошло ни под один `except`, его обработает интерпретатор — программа завершится с ошибкой.

```python run
try:
    raise TypeError(1)
except (ValueError, TypeError):
    print("Value or Type Error")
except SyntaxError:
    print("SyntaxError")
```

`except` без типа ловит всё, включая исключения, которые не наследуют `Exception`, а наследуют напрямую `BaseException` — например, `GeneratorExit`, `KeyboardInterrupt`, `SystemExit`.

```python run
try:
    raise GeneratorExit
except Exception:
    print("Exception")
except:
    print("Base Exception")
```

### Повторный выброс исключения (re-raise)

Если внутренний обработчик поймал ошибку, внешний её уже не увидит. Чтобы передать ошибку дальше, во внутреннем обработчике пишут `raise` без аргументов.

```python run
try:
    try:
        raise ValueError(1)
    except Exception:
        print("INNER")
        raise  # без этой строки OUTER не напечатается
except Exception:
    print("OUTER")
```

### Группы исключений

В Python 3.11 появились `ExceptionGroup` и `BaseExceptionGroup`. Они позволяют выбросить сразу несколько исключений — например, из задач, которые работали параллельно в `asyncio`.

```python run
# Блок except перехватывает всю группу целиком
try:
    eg = ExceptionGroup(
        "exception group",
        [
            TypeError("Некорректный тип"),
            ValueError("Неверное значение"),
        ]
    )
    raise eg
except ExceptionGroup as e:
    print("Полностью пойманная группа исключений:")
    print(e)

# Синтаксис except* обрабатывает отдельные типы исключений из группы
try:
    eg = ExceptionGroup(
        "exception group",
        [
            TypeError("Некорректный тип"),
            ValueError("Неверное значение"),
        ]
    )
    raise eg
except* TypeError as e:
    print("\nОбработка TypeError:")
    print(e)
except* ValueError as e:
    print("\nОбработка ValueError:")
    print(e)
```

### Свой тип исключения

Собственный класс исключения делает сообщения об ошибках информативнее и позволяет передать с ошибкой дополнительные данные. Пример ниже специально завершается ошибкой `Custom: My Error`.

```python run
class Custom(Exception):
    def __init__(self, value, message="Default message"):
        self.value = value
        self.message = message
        super().__init__(self.message)

raise Custom(500, message="My Error")
```

## Частые ошибки

- Голый `except:` или `except Exception: pass` → ошибки исчезают без следа, и программа продолжает работать с неверными данными; заодно перехватывается `KeyboardInterrupt` → ловите конкретные типы, а если нужно «поймать всё», хотя бы логируйте ошибку.
- Общий `except Exception` стоит выше конкретного `except ValueError` → конкретный блок никогда не срабатывает → ставьте блоки от частного к общему.
- Слишком большой блок `try` → непонятно, какая из десяти строк вызвала `KeyError`, и перехватываются ошибки, которых вы не ждали → оборачивайте только ту строку, которая может упасть, остальное переносите в `else`.
- `raise e` вместо `raise` внутри обработчика → трассировка обрывается на месте повторного выброса, и исходную строку с ошибкой найти труднее → пишите `raise` без аргумента, а при обёртке в свой тип — `raise MyError(...) from e`.
- Собственное исключение наследуется от `BaseException` → его не ловит `except Exception`, и ошибка проходит сквозь все обычные обработчики → наследуйте от `Exception` или более узкого встроенного класса.

## Когда не использовать

Исключения не нужны для обычного ветвления логики. Если ключ может отсутствовать, а это нормальная ситуация, проще `dict.get(key, default)` или `if key in order`, чем `try`/`except KeyError`. Если функция регулярно возвращает «ничего не найдено», верните `None` или пустой список вместо выброса исключения — вызывающему коду так удобнее.

Не оборачивайте в `try` то, что должно упасть: ошибка программиста (опечатка в имени, неверный тип аргумента) должна проявиться сразу, а не маскироваться резервным значением. Исключения — для ситуаций, которые зависят от внешнего мира: ввода пользователя, файлов, сети.
