# Рекурсия

Некоторые данные вложены сами в себя: у задачи есть подзадачи, у каталога — подкаталоги, у узла дерева — дочерние узлы. Обойти их циклом неудобно: глубина вложенности заранее неизвестна. **Рекурсия** — приём, при котором функция вызывает сама себя для каждой вложенной части, и глубина перестаёт иметь значение.

## Минимальный пример

Посчитать все задачи в дереве подзадач: задача считается как единица плюс сумма по её подзадачам.

```python run
task = {
    'title': 'Запустить сайт',
    'subtasks': [
        {'title': 'Сверстать страницы', 'subtasks': [
            {'title': 'Главная', 'subtasks': []},
            {'title': 'Контакты', 'subtasks': []},
        ]},
        {'title': 'Настроить сервер', 'subtasks': []},
    ],
}

def count_tasks(task):
    if not task['subtasks']:                                   # база: подзадач нет
        return 1
    return 1 + sum(count_tasks(sub) for sub in task['subtasks'])   # шаг

print(count_tasks(task))   # 5
```

## Как это работает

Некоторые задачи естественно описываются через саму себя: факториал `n` — это `n`, умноженное на факториал `n - 1`.

В рекурсивной функции обязательны две части:

1. **База** — условие выхода. Без неё вызовы не прекратятся, и Python упадёт с `RecursionError`.
2. **Шаг** — вызов с уменьшенными данными, который ведёт к базе.

### Факториал

```python run
def factorial(n):
    if n <= 1:                    # база
        return 1
    return n * factorial(n - 1)   # шаг

factorial(5)   # 120
```

### Числа Фибоначчи: наивная рекурсия за O(2ⁿ)

Одно и то же значение `fib(k)` пересчитывается много раз, поэтому сложность экспоненциальная.

```python run
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

fib(10)   # 55
```

### Мемоизация — O(n)

**Мемоизация** (memoization) — кеширование результата для каждого `n`. Готовый декоратор для этого — `functools.lru_cache`.

```python run
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

fib(100)   # мгновенно; без кеша считалось бы вечность
```

### Лимит рекурсии в Python

По умолчанию глубина рекурсии ограничена примерно 1000 вызовами. Python не оптимизирует **хвостовую рекурсию** (tail recursion), поэтому слишком глубокая рекурсия падает с `RecursionError`.

```python run
import sys
print(sys.getrecursionlimit())   # 1000
# sys.setrecursionlimit(10_000)  # можно повысить, но лучше переписать на цикл
```

### Когда рекурсия — естественный выбор

- Структуры с самоповторением: деревья, графы, JSON, синтаксические деревья (AST).
- Алгоритмы «разделяй и властвуй» (divide and conquer): сортировка слиянием, быстрая сортировка, бинарный поиск.
- **Поиск с возвратом** (backtracking): перебор вариантов с откатом — перестановки, расстановка ферзей, судоку.

### Поиск с возвратом: все перестановки

```python run
def permutations(arr):
    result = []
    def backtrack(path, remaining):
        if not remaining:
            result.append(path)
            return
        for i, x in enumerate(remaining):
            backtrack(path + [x], remaining[:i] + remaining[i+1:])
    backtrack([], arr)
    return result

permutations([1, 2, 3])
```

### Поиск с возвратом: задача о N ферзях

Нужно расставить N ферзей на доске N×N так, чтобы они не били друг друга.

```python run
def solve_n_queens(n):
    result = []
    cols = set()
    diag1 = set()   # row - col
    diag2 = set()   # row + col
    board = [-1] * n

    def backtrack(row):
        if row == n:
            result.append(board.copy())
            return
        for col in range(n):
            if col in cols or (row - col) in diag1 or (row + col) in diag2:
                continue
            cols.add(col); diag1.add(row - col); diag2.add(row + col)
            board[row] = col
            backtrack(row + 1)
            cols.remove(col); diag1.remove(row - col); diag2.remove(row + col)

    backtrack(0)
    return result

print(f'Решений для N=4: {len(solve_n_queens(4))}')   # 2
print(f'Решений для N=8: {len(solve_n_queens(8))}')   # 92
```

### Как переписать рекурсию на цикл

Любую рекурсию можно переписать через цикл и явный стек (`list`). Иногда это необходимо из-за лимита глубины в Python. Факториалу стек даже не нужен:

```python run
def factorial_iter(n):
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result

factorial_iter(5)
```

## Частые ошибки

- Нет базы или шаг не приближает к ней (`factorial(n)` вместо `factorial(n - 1)`) → `RecursionError: maximum recursion depth exceeded` → первой строкой проверять условие выхода и убедиться, что каждый вызов уменьшает задачу.
- Результат рекурсивного вызова не возвращён (`factorial(n - 1)` без `return`) → функция возвращает `None`, а выше падает `TypeError` при умножении → писать `return n * factorial(n - 1)`.
- Изменяемый список передаётся во все ветки поиска с возвратом без копии → в результатах оказываются одинаковые или «затёртые» варианты → добавлять `board.copy()` при сохранении и откатывать изменения после возврата.
- Экспоненциальная рекурсия без кеша (`fib(40)`) → программа «зависает», хотя на малых `n` работала → добавить `@lru_cache` или переписать на цикл по таблице.
- Рекурсия по длинному списку или глубокой структуре (десятки тысяч уровней) → `RecursionError` на реальных данных, хотя тесты проходили → переписать на цикл с явным стеком; `sys.setrecursionlimit` только отодвигает проблему.

## Когда не использовать

Рекурсия лишняя, когда задача решается простым проходом: сумма списка, факториал, обход плоской коллекции. Цикл здесь короче, быстрее и не упирается в лимит глубины.

Для глубоких структур (длинные цепочки, деревья с тысячами уровней, большие графы) берите цикл с явным стеком или очередью: тот же алгоритм, но без риска `RecursionError`. Если задача разбивается на перекрывающиеся подзадачи, вместо рекурсии с кешем часто удобнее таблица — это [динамическое программирование](dynamic_programming.md).
