# Переобучение и кросс-валидация

Модель, которая на обучающих данных ошибается на ноль рублей, кажется идеальной. На новых квартирах она внезапно работает хуже простой модели. Она не выучила закономерность «метр в центре дороже», а запомнила каждую квартиру с её случайными особенностями. Это и есть **переобучение** (overfitting): модель слишком хорошо подогнана под примеры и плохо обобщает.

## Минимальный пример

Дерево решений с разной максимальной глубиной. Чем глубже дерево, тем сложнее правила, которые оно может выучить:

```python
from sklearn.tree import DecisionTreeRegressor

for depth in [1, 3, 5, 8, 12, None]:
    model = make_pipeline(preprocess, DecisionTreeRegressor(max_depth=depth, random_state=42))
    model.fit(X_train, y_train)
    ...
```

```text
глубина   ошибка на обучении   ошибка на тесте
1         3.17 млн             3.23 млн      ← недообучение: обе ошибки большие
3         1.79 млн             1.86 млн
5         1.14 млн             1.28 млн
8         0.66 млн             1.10 млн      ← лучший результат на тесте
12        0.14 млн             1.30 млн
None      0.00 млн             1.35 млн      ← переобучение: запомнило всё, а на новых — хуже
```

## Как это работает

Ошибка на обучающих данных при усложнении модели всегда падает: модель подстраивается под примеры всё точнее. А ошибка на новых данных сначала падает, а потом растёт.

- **Недообучение** (underfitting) — модель слишком простая и не улавливает закономерность. Дерево глубины 1 знает одно правило, например «центр или не центр». Плохо и на обучении, и на тесте;
- **Переобучение** — модель настолько сложная, что выучила и шум. Дерево без ограничений построило по листу на каждую квартиру. Отлично на обучении, плохо на тесте.

Главный признак переобучения — **большой разрыв** между ошибкой на обучении и на тесте: 0,00 против 1,35 млн.

## Кросс-валидация

Подбирать глубину по тестовой выборке нельзя: тогда тест перестаёт быть честной проверкой, мы просто подогнали параметр и под него. Нужна ещё одна независимая проверка, но откладывать для неё отдельную часть данных жалко.

**Кросс-валидация** делит обучающие данные на 5 частей. Модель обучается 5 раз: каждый раз на четырёх частях, а проверяется на пятой. Итог — среднее по пяти проверкам:

```python
from sklearn.model_selection import GridSearchCV

pipe = make_pipeline(preprocess, DecisionTreeRegressor(random_state=42))
search = GridSearchCV(
    pipe,
    {'decisiontreeregressor__max_depth': [3, 5, 8, 12, None]},
    cv=5,
    scoring='neg_mean_absolute_error',
)
search.fit(X_train, y_train)

search.best_params_  # {'decisiontreeregressor__max_depth': 8}
```

```text
глубина   средняя ошибка на кросс-валидации
3         1.84 млн
5         1.30 млн
8         1.14 млн
12        1.28 млн
None      1.31 млн
```

Кросс-валидация выбрала глубину 8, ни разу не заглянув в тестовую выборку. И только теперь, один раз, проверяем на тесте: **1,10 млн**.

В scikit-learn метрики ошибок передаются со знаком минус (`neg_mean_absolute_error`), потому что `GridSearchCV` всегда ищет максимум.

## Как бороться с переобучением

- **ограничить сложность модели**: глубину дерева, число листьев, силу регуляризации у линейных моделей;
- **больше данных**: с тысячей примеров запомнить шум сложнее, чем с сотней;
- **ансамбли**: случайный лес усредняет сотни разных деревьев, и их случайные ошибки взаимно гасятся. Поэтому лес и бустинг в [первой модели](first_model.md) точнее одного дерева;
- **меньше лишних признаков**: каждый случайный признак даёт модели ещё один способ подогнаться под шум;
- **ранняя остановка** для бустинга и нейросетей: прекратить обучение, когда ошибка на отложенных данных перестала падать.

## Частые ошибки

- **Подбор параметров по тестовой выборке.** После десятка попыток «лучшая» модель просто удачно легла на тест. Тест — для финальной проверки, подбор — на кросс-валидации.
- **Сравнение только ошибок на обучении.** Самая сложная модель всегда выигрывает на обучении.
- **Утечка данных.** Признак, который косвенно содержит ответ, даёт прекрасные цифры на тесте и бесполезную модель в работе. Например, «дата продажи» у модели, которая должна предсказывать, будет ли квартира продана.
- **Перемешивание временных данных.** Если данные зависят от времени (цены растут год от года), случайное разделение позволяет модели «подглядывать в будущее». Делите по времени: учимся на прошлом, проверяем на более поздних данных (`TimeSeriesSplit`).
