# Число e, экспонента и натуральный логарифм

Число `e` появляется везде, где величина растёт или убывает пропорционально самой себе: сложные проценты, размножение бактерий, распад, остывание. В коде разработчика оно живёт в сигмоиде и softmax, в экспоненциальных задержках между повторами запроса, в нормальном распределении. Заметка объясняет, откуда берётся `e`, что такое экспонента `e^x` и почему `math.log` в Python — это натуральный логарифм.

## Минимальный пример

Банк начисляет 100 % годовых. Если проценты капитализировать чаще, итоговая сумма растёт, но не бесконечно: она упирается в `e`. А натуральный логарифм отвечает на обратный вопрос — за какое время вклад удвоится при непрерывном начислении.

```python run
import math

deposit = 1.0
for periods in (1, 2, 12, 365, 1_000_000):
    total = deposit * (1 + 1 / periods) ** periods
    print(periods, round(total, 5))
# 1 2.0
# 2 2.25
# 12 2.61304
# 365 2.71457
# 1000000 2.71828

print(round(math.e, 5))                     # 2.71828
print(round(math.exp(1), 5))                # 2.71828 — e^1
print(round(math.log(2), 3))                # 0.693 — ln(2): при ставке 100 % вклад удвоится за 0.693 года
print(round(math.exp(math.log(2)), 3))      # 2.0 — exp и log взаимно обратны
```

## Как это работает

### Число e

```
e ≈ 2.71828182845904…
```

Это иррациональное число (бесконечная непериодическая дробь), такая же «фундаментальная константа», как `π`.

**Откуда оно взялось.** Представь банк с 100 % годовой ставкой. Положили `1₽`, через год получили `2₽`. А что если начислять проценты не раз в год, а **n раз** (с реинвестом)?

```
после года = (1 + 1/n)^n
```

- 1 раз в год: `(1 + 1/1)^1 = 2.00000`
- 2 раза: `(1 + 1/2)^2 = 2.25`
- 12 раз (раз в месяц): `2.61304`
- 365 раз (раз в день): `2.71457`
- бесконечно часто: `2.71828… = e`

То есть **`e` — это предельный множитель при непрерывном начислении процентов**:

```
e = lim (1 + 1/n)^n   при  n → ∞
```

### Экспонента e^x

Функция `f(x) = e^x` называется **экспонентой**.

```
e^0 = 1
e^1 ≈ 2.718
e^2 ≈ 7.389
e^(-1) ≈ 0.368
```

Это обычная показательная функция, но с основанием `e`. Часто пишут `exp(x)`.

```python run
import math

print(math.exp(1))     # 2.718281828459045
print(math.exp(0))     # 1.0
print(math.exp(-1))    # 0.36787944117144233
print(math.e)          # 2.718281828459045
```

**Почему именно e? Главное свойство.** Производная от `e^x` равна сама себе:

```
(e^x)' = e^x
```

Это единственная функция (с точностью до множителя) с таким свойством. Из-за этого `e` выскакивает везде, где есть процессы роста или убывания, пропорциональные текущему значению:

- размножение бактерий (чем больше бактерий, тем быстрее они делятся)
- радиоактивный распад (чем больше атомов, тем больше распадается)
- зарядка и разрядка конденсатора
- модели в финансах (непрерывное начисление)

**График.**

- `e^x` стремительно растёт вправо: `e^10 ≈ 22000`, `e^20 ≈ 485 млн`.
- При `x → -∞` стремится к 0, но никогда не равен 0.
- Всегда положительна.

### Натуральный логарифм ln(x)

**Натуральный логарифм** — это логарифм по основанию `e`:

```
ln(x) = log_e(x)
```

Вопрос: «в какую степень возвести `e`, чтобы получить `x`?»

```
ln(1)   = 0           потому что e^0 = 1
ln(e)   = 1           потому что e^1 = e
ln(e^2) = 2
ln(10)  ≈ 2.302
```

Свойства — те же, что у любого логарифма:
```
ln(x · y) = ln(x) + ln(y)
ln(x / y) = ln(x) - ln(y)
ln(x^n)   = n · ln(x)
```

```python run
import math

print(math.log(math.e))   # 1.0 — это ln(e)
print(math.log(10))       # 2.302585092994046 — это ln(10)
print(math.log(1))        # 0.0
print(math.log10(10))     # 1.0 — десятичный логарифм живёт в отдельной функции
```

Обрати внимание: в Python `math.log(x)` без второго аргумента — это **натуральный** логарифм, а не десятичный.

### Связь e^x и ln(x)

Это **обратные функции**:

```
ln(e^x) = x
e^(ln x) = x
```

То есть если применить экспоненту, а потом натуральный логарифм (или наоборот) — вернёмся к исходному числу.

### Где встречается в работе разработчика

**1. ML и нейросети**

Сигмоида переводит любое число в интервал `(0, 1)` — удобно для вероятностей:
```
σ(x) = 1 / (1 + e^(-x))
```

Softmax (для классификации):
```
softmax(x_i) = e^(x_i) / Σ e^(x_j)
```

Кросс-энтропия (cross-entropy loss) использует `log`, обычно натуральный.

```python run
import math

def sigmoid(x):
    return 1 / (1 + math.exp(-x))

print(round(sigmoid(0), 3))     # 0.5
print(round(sigmoid(4), 3))     # 0.982
print(round(sigmoid(-4), 3))    # 0.018
```

**2. Распределения вероятностей**

Нормальное (гауссово) распределение содержит `e^(-x²/2)`. Распределение Пуассона, экспоненциальное распределение — везде `e`.

**3. Финансы**

Непрерывное начисление процентов: сумма за время `t` со ставкой `r`:
```
A = P · e^(r·t)
```

**4. Алгоритмы и инфраструктура**

`ln(n)` встречается в анализе случайных алгоритмов и хеш-таблиц (например, ожидаемое число коллизий). Экспоненциальная задержка (exponential backoff) между повторами запроса — `delay = base · 2^attempt` — тот же рост, только с основанием 2.

## Частые ошибки

- `math.log(100)` принят за десятичный логарифм → вместо `2` получается `4.605` → для десятичного брать `math.log10(x)`, для произвольного основания `math.log(x, base)`.
- `math.exp(1000)` в сигмоиде или softmax → `OverflowError: math range error`, в NumPy — `inf` и `nan` → перед `exp` вычитать максимум из входов (`x - max(x)`): результат softmax не меняется, а переполнение исчезает.
- `math.log(0)` или логарифм вероятности, которая округлилась до нуля → `ValueError: math domain error` → прибавлять малую константу (`log(p + 1e-12)`) или считать сразу `log`-вероятности, не переходя к самим вероятностям.
- `e` принято за «просто ещё одно число около 2.7», и в формулах роста ставят `2.7` или `2.718` → ошибка накапливается при больших показателях → использовать `math.e` и `math.exp`.
- Сравнение `math.exp(math.log(x)) == x` → из-за округления `float` равенство иногда ложно → сравнивать через `math.isclose`.

## Когда не использовать

Если рост идёт дискретными шагами с фиксированным множителем — удвоение памяти списка, повторы запроса с задержкой `2^n`, число бит, — естественное основание не `e`, а `2`: `2 ** n` и `math.log2` читаются понятнее и не тянут за собой погрешность перевода основания.

Для больших степеней целых чисел экспонента и логарифм не нужны вовсе: `2 ** 1000` и `pow(a, b, m)` считают точно, а `math.exp(1000 * math.log(2))` переполнится. Для сумм в логарифмическом масштабе лучше взять готовые функции `math.log1p`, `math.expm1` и `scipy.special.logsumexp`, чем выводить формулы вручную.
