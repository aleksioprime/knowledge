**Утечка памяти** — это ситуация, когда программа **использует всё больше памяти и не освобождает её**, даже когда данные больше не нужны.

Python автоматически управляет памятью через **сборщик мусора (Garbage Collector, GC)**, но **утечки памяти всё равно возможны!**

Циклические ссылки. Python использует **счётчик ссылок** для удаления ненужных объектов. Если объект **ссылается сам на себя** или два объекта ссылаются друг на друга, сборщик мусора **не может их удалить**.

```python
import gc

class Node:
    def __init__(self):
        self.ref = self  # Объект ссылается сам на себя

node = Node()
del node  # ❌ Объект не удаляется, так как есть циклическая ссылка!
gc.collect()  # 🚨 Принудительно запускаем сборщик мусора
```

```python
import weakref

class Node:
    pass

node = Node()
node.ref = weakref.ref(node)  # 🔥 Теперь объект может быть удалён
```

Глобальные переменные. Python **не удаляет глобальные переменные** до завершения программы.  Если переменная **содержит большой объект**, он **навсегда останется в памяти**.

```python
big_data = [i for i in range(10**6)]  # 1 миллион элементов

def process():
    global big_data  # 🔥 Используем глобальную переменную (и она не удалится!)
    print(len(big_data))

process()
```

```python
del big_data # Освобождаем память
```

Замыкания (Closures). Функции в Python **могут "запоминать" переменные из внешней области видимости**.  Иногда это приводит к утечке памяти, если переменная ссылается на **большой объект**.

```python
def create_closure():
    big_data = [i for i in range(10**6)]  # 🔥 Большой список

    def inner():
        return big_data[0]  # Функция хранит ссылку на big_data

    return inner

closure = create_closure()  # ❌ Теперь big_data никогда не освободится
```

```python
def create_closure():
    big_data = [i for i in range(10**6)]

    def inner():
        nonlocal big_data
        result = big_data[0]
        big_data = None  # 🔥 Удаляем ссылку на список
        return result

    return inner

closure = create_closure()
```

Обработчики событий (Event Listeners). Если объект **подписан на событие** (например, в `tkinter`, `PyQt`, `asyncio`), но его **никто не отписывает**, он **останется в памяти навсегда**.

```python
class Window:
    def __init__(self):
        self.button = Button()
        self.button.clicked.connect(self.on_click)  # 🔥 Обработчик остаётся в памяти

    def on_click(self):
        print("Clicked!")

win = Window()
del win  # ❌ Объект не удалится, потому что button ссылается на on_click
```

```python
self.button.clicked.disconnect(self.on_click) # Отписываем обработчик
```

Неуправляемые потоки и процессы. Если поток (`threading.Thread`) или процесс (`multiprocessing.Process`) **не завершается**, он может **навсегда оставаться в памяти**.

```python
import threading
import time

def worker():
    while True:  # 🔥 Поток никогда не завершится
        time.sleep(1)

t = threading.Thread(target=worker)
t.start()

del t  # ❌ Поток всё равно работает!
```

```python
# Явное завершение потока
t.join(timeout=5)

# Или использовать `daemon=True`, чтобы поток автоматически завершался при закрытии программы:
t = threading.Thread(target=worker, daemon=True)
t.start()
```

Переопределение переменной без удаления старого объекта. Если переменная **содержит ссылку на большой объект** и мы **присваиваем ей новый объект**, старый объект **останется в памяти**, если на него есть другие ссылки.

```python
big_data = [i for i in range(10**6)] big_data = "заменили на строку" # ❌ Список остаётся в памяти
```

```python
del big_data 
big_data = "заменили на строку"
```

Проверка утечек:

```python
import gc
print(len(gc.get_objects()))  # Количество объектов в памяти
```

```python
import tracemalloc

tracemalloc.start()  # Включаем отслеживание

big_data = [i for i in range(10**6)]  # Создаём утечку памяти
snapshot = tracemalloc.take_snapshot()

top_stats = snapshot.statistics('lineno')  # Статистика по строкам кода
for stat in top_stats[:5]:
    print(stat)
```
