# Slots в компонентах Vue

Карточка, модальное окно или панель повторяются по всему приложению, но внутри у них каждый раз разное содержимое: текст, кнопки, таблица. Передавать всё это через props неудобно — пришлось бы описывать разметку строками. Слоты (slots) позволяют родителю вставить собственную разметку в заранее отведённое место дочернего компонента. Здесь — обычный slot, именованные slots и scoped slots, через которые дочерний компонент отдаёт данные наружу.

## Минимальный пример

```vue
<!-- TaskCard.vue -->
<template>
  <article class="card">
    <h3><slot name="title">Задача</slot></h3>
    <slot />
  </article>
</template>
```

```vue
<!-- App.vue -->
<script setup>
import TaskCard from './TaskCard.vue'
</script>

<template>
  <TaskCard>
    <template #title>Купить хлеб</template>
    <p>Срок: завтра</p>
  </TaskCard>
  <!-- <article class="card"><h3>Купить хлеб</h3><p>Срок: завтра</p></article> -->
</template>
```

## Как это работает

### Контент через slot

`slot` позволяет передать разметку внутрь дочернего компонента.

#### Дочерний компонент

```vue
<template>
  <section class="card">
    <h3>Профиль</h3>
    <slot />
  </section>
</template>
```

#### Родитель

```vue
<template>
  <ProfileCard>
    <p>Текст внутри слота</p>
  </ProfileCard>
</template>
```

- `slot` делает компонент гибким без жесткой привязки к одному шаблону.
- Для сложных случаев используйте именованные и scoped slots.

### Именованные slots

Именованные слоты полезны, когда у компонента несколько зон вставки: например header, body и footer.

#### Дочерний компонент

```vue
<template>
  <article class="panel">
    <header>
      <slot name="header">Заголовок по умолчанию</slot>
    </header>

    <main>
      <slot />
    </main>

    <footer>
      <slot name="footer" />
    </footer>
  </article>
</template>
```

#### Родитель

```vue
<template>
  <BasePanel>
    <template #header>
      <h2>Пользователь</h2>
    </template>

    <p>Основной контент</p>

    <template #footer>
      <button>Сохранить</button>
    </template>
  </BasePanel>
</template>
```

- Используйте `#header` как короткую форму `v-slot:header`.
- Давайте слотам понятные имена по роли, а не по внешнему виду.

### Scoped slots (передача данных в slot)

Scoped slot нужен, когда дочерний компонент передает данные в разметку родителя.

#### Дочерний компонент

```vue
<template>
  <ul>
    <li v-for="user in users" :key="user.id">
      <slot name="item" :user="user" :is-active="user.isActive">
        {{ user.name }}
      </slot>
    </li>
  </ul>
</template>

<script setup>
const users = [
  { id: 1, name: 'Alex', isActive: true },
  { id: 2, name: 'Mira', isActive: false },
]
</script>
```

#### Родитель

```vue
<template>
  <UsersList>
    <template #item="{ user, isActive }">
      <strong :class="{ active: isActive }">{{ user.name }}</strong>
    </template>
  </UsersList>
</template>
```

- Передавайте в scoped slot только то, что реально используется.
- Имена slot props должны отражать смысл данных.
- Держите fallback-контент в дочернем компоненте для надежности.

### Практические советы

- Проектируйте slots как часть публичного API компонента.
- Не перегружайте slot props: передавайте только нужный минимум.
- Если слотов много и они обязательны, явно документируйте их назначение в README компонента.

## Частые ошибки

- У родителя написано `<template #header>`, а в дочернем компоненте слот называется `title` → содержимое молча не отображается, показывается fallback → сверять имена слотов, при сомнении смотреть `$slots` в devtools.
- Содержимое слота обращается к данным дочернего компонента (`{{ user.name }}` у родителя без scoped slot) → ошибка «user is not defined»: шаблон родителя видит только своё состояние → передавать данные наружу через scoped slot `<slot :user="user">`.
- Именованный слот передан атрибутом `slot="header"` на элементе → этот синтаксис Vue 2 в Vue 3 не работает, содержимое попадает в слот по умолчанию → использовать `<template #header>`.
- Обёртка вокруг необязательного слота рендерится всегда (`<footer><slot name="footer" /></footer>`) → в вёрстке остаются пустые блоки с отступами → проверять `$slots.footer` через `v-if` перед выводом обёртки.
- Через scoped slot передаётся весь внутренний объект состояния → родитель зависит от внутренностей компонента и ломается при рефакторинге → передавать только нужные поля.

## Когда не использовать

Если родителю нужно передать строку или число — заголовок, счётчик, флаг — слот лишний: достаточно prop. Слоты нужны именно для разметки, которую дочерний компонент не должен знать заранее.

Когда вариантов содержимого два-три и они фиксированы (например, иконка «успех» или «ошибка»), проще передать prop `type` и выбрать разметку через `v-if` внутри компонента. А если родитель через scoped slot фактически переписывает весь шаблон дочернего компонента, вероятно, компонент стоит разделить на два или вынести общую логику в composable.
