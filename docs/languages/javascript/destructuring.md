# Деструктуризация

Из ответа API нужны три поля из двадцати, в функцию приходит объект настроек, где половина значений необязательна, а два массива надо объединить в третий, не трогая исходные. Без деструктуризации, spread и rest это цепочки `const name = user.name`, проверок на `undefined` и вызовов `concat()`. Здесь способы извлекать значения из массивов и объектов, задавать значения по умолчанию, раскрывать и собирать значения через `...`.

## Минимальный пример

```js
const user = { id: 42, name: 'Alex', role: 'admin', password: 'secret' }

const { name, role = 'user', ...rest } = user
console.log(name, role) // Alex admin
console.log(rest) // { id: 42, password: 'secret' }

const [first, , third = 'нет'] = ['Купить хлеб', 'Позвонить врачу']
console.log(first, third) // Купить хлеб нет

function createTask({ title, done = false } = {}) {
  return { title, done }
}
console.log(createTask({ title: 'Сдать отчёт' })) // { title: 'Сдать отчёт', done: false }

const merged = { ...user, role: 'user' }
console.log(merged.role) // user
console.log(Math.max(...[3, 7, 2])) // 7
```

## Как это работает

### Деструктуризация массивов

Переменные сопоставляются с элементами по позиции:

```js
const colors = ['red', 'green', 'blue']
const [first, second] = colors // first — первый элемент, second — второй

first // 'red'
second // 'green'
```

Элемент можно пропустить, а оставшиеся значения собрать rest-оператором:

```js
const [first, , third, ...others] = values
```

Значение по умолчанию используется только для отсутствующего элемента или `undefined`, но не для `null`:

```js
const [first = 10] = [] // элемента нет, поэтому first получает значение по умолчанию 10
const [second = 10] = [undefined] // элемент равен undefined, поэтому second тоже получает 10
const [third = 10] = [null] // null считается заданным значением, поэтому third получает null
```

#### Обмен значений

Деструктуризация позволяет поменять значения двух переменных без временной третьей переменной.

```js
let left = 1
let right = 2

;[left, right] = [right, left]
```

Точка с запятой защищает выражение, если предыдущая строка может соединиться с `[` при автоматической расстановке точек с запятой.

### Деструктуризация объектов

Переменная по умолчанию получает имя свойства:

```js
const user = {
  id: 42,
  name: 'Alex',
  role: 'admin',
}

const { id, name } = user
```

Свойство можно переименовать, задать значение по умолчанию и собрать остальные собственные перечисляемые свойства:

```js
const {
  name: displayName,
  avatar = '/default.png',
  ...userDetails
} = user
```

Здесь `name` — ключ объекта, а `displayName` — новая переменная. Переменная `name` не создаётся.

#### Вложенная деструктуризация

Шаблон деструктуризации может повторять форму вложенного объекта и извлекать глубокое свойство за одну операцию.

```js
const response = {
  data: {
    profile: {
      city: 'Moscow',
    },
  },
}

const {
  data: { // переменная data не создаётся
    profile: { city },
  },
} = response
```

Промежуточные переменные `data` и `profile` здесь не создаются. Если вложенного объекта может не быть, безопаснее сначала использовать optional chaining или значение по умолчанию.

#### Вычисляемый ключ

Если имя нужного свойства хранится в переменной, его записывают в квадратных скобках прямо внутри шаблона.

```js
const propertyName = 'role'
const { [propertyName]: role } = user
```

#### Присваивание существующим переменным

При объектной деструктуризации без объявления нужны круглые скобки, иначе `{}` будет воспринят как блок:

```js
let name

;({ name } = user) // без let/const выражение берут в скобки
```

### Параметры функций

Объект можно деструктурировать прямо в параметрах:

```js
function printUser({ name, role = 'user' }) {
  console.log(`${name}: ${role}`)
}
```

Если весь аргумент необязателен, добавьте значение по умолчанию для объекта:

```js
function createUser({ name = 'Без имени', active = true } = {}) {
  return { name, active }
}

createUser() // значения берутся из пустого объекта по умолчанию
```

### Spread

Spread записывается как `...` и раскрывает значение на отдельные элементы, аргументы или свойства.

#### Копирование и объединение массивов

В литерале массива spread раскрывает элементы исходного массива в новый. Так можно сделать поверхностную копию или собрать несколько массивов в один.

```js
const first = [1, 2]
const second = [3, 4]

const copy = [...first]
const combined = [...first, ...second]
const withMiddle = [0, ...first, 2.5, ...second, 5]
```

Копия поверхностная: вложенные объекты остаются общими.

Spread часто нагляднее `concat()`, когда элементы добавляются в разные части выражения. При этом `concat()` тоже не изменяет исходные массивы и может принимать одиночные неитерируемые значения.

#### Строки и другие iterable-объекты

Spread массива требует iterable-значение. Строка является iterable:

```js
const letters = [...'JavaScript']
const unique = [...new Set([1, 1, 2])]
```

Обычный объект не является iterable, поэтому `[...user]` вызовет `TypeError`.

#### Аргументы функции

В месте вызова spread превращает элементы массива в отдельные позиционные аргументы функции.

```js
const numbers = [3, 7, 2]

Math.max(...numbers) // 7
```

Очень большой массив не следует раскрывать в аргументы: среда выполнения ограничивает их количество.

#### Объекты

Объектный spread раскрывает собственные перечисляемые свойства:

```js
const defaults = { theme: 'light', pageSize: 10 }
const settings = { pageSize: 20 }

const result = {
  ...defaults, // сначала значения по умолчанию, потом они перезаписываются
  ...settings,
  loaded: true,
}
// { theme: 'light', pageSize: 20, loaded: true }
```

Позднее свойство перезаписывает ранее записанное. Копирование остаётся поверхностным и не сохраняет прототип или исходные property descriptors.

### Rest

Rest выглядит так же — `...`, но выполняет обратную задачу: собирает оставшиеся значения.

#### В деструктуризации

Rest внутри шаблона сохраняет часть значений в отдельную коллекцию, чтобы они не потерялись после извлечения первых элементов или свойств.

```js
const [first, ...otherNumbers] = [1, 2, 3] // first = 1, otherNumbers = [2, 3]
const { password, ...publicUser } = user
```

Rest должен быть последним элементом шаблона. Объектный rest собирает оставшиеся собственные перечисляемые свойства в новый поверхностный объект.

#### В параметрах функции

Rest-параметр собирает все оставшиеся аргументы вызова в настоящий массив.

```js
function sum(...numbers) {
  return numbers.reduce((total, number) => total + number, 0)
}

sum(1, 2, 3) // 6 — numbers внутри функции станет массивом [1, 2, 3]
```

Rest-параметр:

- собирает любое количество оставшихся аргументов;
- является настоящим массивом;
- должен быть последним параметром;
- может быть только один;
- не допускает запятую после себя.

Он обычно удобнее псевдомассива `arguments`, особенно в стрелочных функциях, у которых собственного `arguments` нет.

## Частые ошибки

- Значение по умолчанию ожидается для `null` → `const { avatar = '/default.png' } = { avatar: null }` оставляет `null`, подстановка не срабатывает → помнить, что default применяется только к `undefined`; `null` заменять через `??`.
- Деструктуризация вложенного объекта, которого может не быть (`const { data: { profile } } = response`) → `TypeError: Cannot read properties of undefined` → добавить значение по умолчанию для промежуточного уровня `data: { profile } = {}` или проверять через optional chaining заранее.
- Объектная деструктуризация в уже объявленные переменные без скобок: `{ name } = user` → `SyntaxError`, фигурные скобки прочитаны как блок → брать выражение в круглые скобки: `({ name } = user)`.
- Переименование записано наоборот: `const { displayName: name } = user` в расчёте получить `displayName` → создаётся переменная `name` из свойства `displayName`, которого нет → слева ключ объекта, справа новое имя: `{ name: displayName }`.
- Spread объекта принят за глубокую копию → вложенные объекты остаются общими, изменение копии меняет оригинал → для глубокого копирования использовать `structuredClone()`.

## Когда не использовать

Если из объекта нужно одно свойство, `const name = user.name` читается не хуже деструктуризации, а глубокие шаблоны с тремя уровнями вложенности и переименованиями быстро становятся нечитаемыми — лучше извлечь промежуточный объект в переменную. В параметрах функции деструктуризация с десятком полей тоже сигнал, что функции стоит принимать объект целиком.

Spread не подходит для очень больших массивов в аргументах (`Math.max(...hugeArray)`): среда ограничивает количество аргументов, и вызов упадёт с `RangeError` — считайте через `reduce()`. Для объединения массивов «на месте», когда копия не нужна, `push(...items)` тоже раскрывает значения, но без создания нового массива.
