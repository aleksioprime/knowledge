# Заголовки, cookies и кеширование

## Частые заголовки

| Заголовок | Назначение |
|---|---|
| `Host` | Домен, к которому обращается клиент |
| `Content-Type` | Формат тела сообщения |
| `Content-Length` | Размер тела в байтах |
| `Accept` | Предпочтительные форматы ответа |
| `Accept-Encoding` | Поддерживаемое сжатие, например `gzip` или `br` |
| `Authorization` | Учётные данные или токен доступа |
| `User-Agent` | Информация о клиенте |
| `Location` | Адрес созданного ресурса или перенаправления |
| `Vary` | Какие заголовки запроса влияют на вариант кешированного ответа |

Названия заголовков регистронезависимы. Прокси и сервер не должны доверять клиентским `X-Forwarded-*`, если запрос пришёл не от доверенного прокси.

## Cookies

Сервер устанавливает cookie заголовком `Set-Cookie`, а браузер возвращает её в `Cookie`:

```http
Set-Cookie: session=abc123; Path=/; Secure; HttpOnly; SameSite=Lax
```

- `Secure` — отправлять только по HTTPS;
- `HttpOnly` — запретить чтение из JavaScript;
- `SameSite` — ограничить межсайтовую отправку и снизить риск CSRF;
- `Domain` и `Path` — ограничить область действия;
- `Max-Age` или `Expires` — задать срок хранения.

В cookie не стоит хранить секретные данные в открытом виде. Даже подписанное значение пользователь может прочитать.

## Кеширование

```http
Cache-Control: public, max-age=3600
ETag: "version-42"
```

Клиент может проверить актуальность ресурса:

```http
If-None-Match: "version-42"
```

Если ресурс не изменился, сервер возвращает `304 Not Modified` без тела. Для персональных или чувствительных данных обычно используют `Cache-Control: private` или `no-store`. Заголовок `Vary` должен отражать все параметры запроса, от которых зависит представление, иначе прокси может отдать ответ не тому клиенту.
