# Функции и области видимости

Счётчик, который помнит своё значение между вызовами, обработчик, который через секунду «теряет» объект, и метод, переданный в `setTimeout` без `this`, — всё это вопросы о том, как функция видит переменные и как получает контекст. Без понимания областей видимости, замыканий и правил `this` ошибки выглядят случайными: код работает в одном месте и ломается в другом. Здесь формы объявления функций, доступность переменных, замыкания и способы задать `this` явно.

## Минимальный пример

```js
function createCounter(start = 0) {
  let value = start

  return () => {
    value += 1
    return value
  }
}

const nextTaskId = createCounter()
console.log(nextTaskId()) // 1
console.log(nextTaskId()) // 2

const user = {
  name: 'Alex',
  greet() {
    return `Привет, ${this.name}`
  },
}
console.log(user.greet()) // Привет, Alex

const greet = user.greet
console.log(greet.call({ name: 'Anna' })) // Привет, Anna
```

## Как это работает

### Виды функций

Все функции имеют `typeof value === 'function'`. Названия ниже описывают синтаксис или способ использования функции, а не разные типы данных.

Три основные формы отличаются не только записью:

| Особенность | Declaration | Expression | Arrow function |
|---|---|---|---|
| Собственный `this` | да | да | нет |
| `arguments` | да | да | нет |
| Вызов через `new` | да | да | нет |
| Доступна до строки объявления | да | нет | нет |

Стрелочная функция обычно удобна для коротких callbacks. Обычная функция нужна, когда значение `this` должно определяться способом вызова, требуется `arguments` или функцию планируется использовать как конструктор.

Функция является объектом: её можно передавать, сравнивать по ссылке и добавлять ей собственные свойства. Но прикладное состояние обычно лучше хранить отдельно.

```js
function loadUser(id, options) {}

loadUser.description = 'Загружает пользователя'
loadUser.name // 'loadUser'
loadUser.length // 2
```

Основные встроенные свойства функции:

- `name` — объявленное или автоматически выведенное имя;
- `length` — количество параметров до первого параметра со значением по умолчанию; rest-параметр не учитывается;
- `prototype` — объект, используемый при вызове обычной конструируемой функции через `new`; у стрелочной функции его нет.

`name` и `length` обычно нельзя изменить простым присваиванием: их свойства имеют `writable: false`. Пользовательские свойства функции при этом добавлять можно.

```js
function example(first, second, third = 0, ...others) {}

example.length // 2 — параметры после first и second не учитываются из-за значения по умолчанию
```

#### Function declaration

Function declaration — именованное объявление, которое доступно до строки определения благодаря hoisting:

```js
function sum(a, b) {
  return a + b
}
```

#### Function expression

Функция создаётся внутри выражения и обычно сохраняется в переменной. Она может быть анонимной или именованной:

```js
const sum = function (a, b) {
  return a + b
}
```

#### Arrow function

Стрелочная функция предоставляет короткий синтаксис и может неявно возвращать одно выражение:

```js
const sum = (a, b) => a + b
```

Для неявного возврата объекта нужны круглые скобки, иначе `{}` будет воспринят как тело функции:

```js
const createUser = (name) => ({ name })
```

Особенности стрелочной функции:

- не создаёт собственный `this`, а берёт его из внешней лексической области;
- не имеет собственного `arguments`, вместо него используют rest-параметр;
- не имеет `prototype` и не вызывается через `new`;
- не может быть генератором `function*`;
- методы `call`, `apply` и `bind` не могут заменить её `this`.

```js
const context = { name: 'Alex' }
const arrow = () => this

arrow.call(context) !== context // true
```

`bind()` всё ещё может зафиксировать аргументы стрелочной функции, но не её контекст.

Если нужен изменяемый `this`, используйте обычную функцию:

```js
function printName() {
  return this.name
}

printName.call(context) // 'Alex'
```

Если нужен именно лексический контекст, создайте стрелочную функцию внутри обычного метода или явно обращайтесь к объекту:

```js
const user = {
  name: 'Alex',

  printLater() {
    setTimeout(() => console.log(this.name), 1000)
  },
}
```

#### Метод

Функция, хранящаяся в свойстве объекта. В сокращённой записи `this` определяется объектом перед точкой при вызове:

```js
const user = {
  greet() {
    return `Привет, ${this.name}`
  },
}
```

#### Функция-конструктор

Обычная функция, вызываемая через `new`. По соглашению её имя начинается с заглавной буквы. В современном коде для этой задачи часто используют `class`.

```js
function User(name) {
  this.name = name
}

const user = new User('Alex')
```

#### Названия по способу использования

Одну и ту же функцию можно называть по её роли в программе. Эти термины описывают способ применения, а не новый тип данных:

- callback передаётся другой функции для последующего вызова;
- функция высшего порядка принимает или возвращает функцию;
- IIFE вызывается сразу после создания;
- рекурсивная функция вызывает саму себя.

Одна функция может одновременно подходить под несколько определений, например быть стрелочным callback внутри `map()`.

### Область видимости

Область видимости определяет, из какой части программы доступна переменная.

| Область | Где создаётся | Что важно |
|---|---|---|
| глобальная | верхний уровень обычного script | доступна из разных частей программы |
| функциональная | внутри функции | параметры и `var` видны во всей функции |
| блочная | внутри `{}` | `let`, `const` и `class` ограничены блоком |
| модульная | верхний уровень ES-модуля | значения не становятся глобальными автоматически |

```js
const globalValue = 'global'

function example(parameter) {
  var functionValue = 'function'

  if (true) {
    const blockValue = 'block'
    console.log(globalValue, parameter, functionValue, blockValue)
  }

  // blockValue здесь недоступна
}
```

`var` не имеет блочной области, поэтому объявление внутри `if` остаётся доступным до конца функции. В ES-модуле верхнеуровневые переменные принадлежат модулю и доступны другим модулям только через `export`/`import`.

Функция видит собственные переменные и внешнее лексическое окружение:

```js
function createCounter() {
  let value = 0

  return () => {
    value += 1
    return value
  }
}

const next = createCounter()
next() // 1
next() // 2
```

Возвращённая функция сохраняет доступ к `value`. Это называется замыканием.

#### Hoisting, TDZ и лексическое окружение

Перед выполнением движок создаёт объявления в соответствующих областях видимости. Function declaration доступна сразу, `var` до присваивания содержит `undefined`, а `let` и `const` до строки инициализации находятся во временной мёртвой зоне — TDZ.

Лексическое окружение хранит локальные переменные и ссылку на внешнее окружение. Поэтому вложенная функция находит переменные сначала у себя, а затем во внешних областях — это основа областей видимости и замыканий.

### Функции как значения

В JavaScript функции являются объектами первого класса: их можно сохранять в переменных, передавать аргументами и возвращать. Функция высшего порядка принимает другую функцию или возвращает её; `map`, `filter` и `reduce` — знакомые примеры.

Callback — функция, переданная для последующего вызова. Он не обязательно асинхронный: функция внутри `map()` тоже callback.

#### IIFE

IIFE — функциональное выражение, вызываемое сразу после создания:

```js
;(function () {
  const privateValue = 42
})() // круглые скобки в конце сразу вызывают созданную функцию
```

До ES-модулей IIFE часто использовали для изоляции переменных. Сейчас эта техника нужна реже.

#### Каррирование

Каррирование преобразует функцию с несколькими аргументами в цепочку функций по одному аргументу:

```js
const multiply = (a) => (b) => a * b
const double = multiply(2) // множитель 2 зафиксирован заранее

double(5) // 10
```

Не путайте его с частичным применением, при котором заранее фиксируется только часть аргументов.

#### Рекурсия

Рекурсивная функция вызывает сама себя и обязательно должна иметь условие остановки:

```js
function factorial(number) {
  if (number <= 1) return 1
  return number * factorial(number - 1)
}
```

Слишком глубокая рекурсия может переполнить стек вызовов; обычный цикл часто безопаснее.

Рекурсия особенно естественна для рекурсивных структур: деревьев, вложенных комментариев, каталогов и DOM-узлов.

```js
const tree = {
  value: 'root',
  children: [
    { value: 'left', children: [] },
    { value: 'right', children: [] },
  ],
}

function collectValues(node) {
  return [
    node.value,
    ...node.children.flatMap(collectValues),
  ]
}

collectValues(tree) // ['root', 'left', 'right']
```

У рекурсивного алгоритма должны быть базовый случай и шаг, приближающий данные к нему. В примере базовым случаем является пустой `children`.

### Принципы функционального программирования

JavaScript поддерживает функциональный стиль, хотя не является чисто функциональным языком.

- функция является значением первого класса;
- чистая функция при одинаковых аргументах возвращает одинаковый результат и не создаёт наблюдаемых побочных эффектов;
- данные предпочитают не изменять, а создавать новые значения;
- небольшие функции объединяют через композицию;
- операции описывают декларативно через `map`, `filter`, `reduce` и другие функции высшего порядка;
- побочные эффекты — сеть, DOM, хранилище — стараются изолировать на границах программы.

```js
const getActiveNames = (users) => users
  .filter((user) => user.active)
  .map((user) => user.name)
```

Эта функция не изменяет `users` и зависит только от аргумента, поэтому её легко тестировать. Полный запрет изменений не является целью сам по себе: важнее контролировать общее изменяемое состояние.

### `this`

У обычной функции `this` определяется способом вызова:

```js
const user = {
  name: 'Alex',
  greet() {
    return `Привет, ${this.name}`
  },
}

user.greet() // this === user
```

Arrow function не создаёт собственный `this`, а берёт его из внешней области. Поэтому её удобно использовать в callback, но обычно не стоит использовать как метод, которому нужен динамический `this`.

```js
const greet = user.greet
greet()                // контекст user потерян
user.greet.bind(user)() // контекст привязан явно
```

#### `call()`, `apply()` и `bind()`

Эти методы явно задают `this` обычной функции:

| Метод | Аргументы | Когда выполняет функцию | Что возвращает |
|---|---|---|---|
| `call(thisArg, ...args)` | отдельно | сразу | результат функции |
| `apply(thisArg, argsArray)` | array-like объект | сразу | результат функции |
| `bind(thisArg, ...presetArgs)` | отдельно | не вызывает | новую функцию |

```js
greet.call(user, 'Привет')       // аргументы по отдельности
greet.apply(user, ['Привет'])    // аргументы в array-like объекте
const boundGreet = greet.bind(user) // вызов произойдёт позже
```

`bind()` также поддерживает частичное применение аргументов:

```js
const add = (a, b) => a + b
const addTen = add.bind(null, 10)

addTen(5) // 15
```

У стрелочной функции собственный `this` отсутствует, поэтому `call`, `apply` и `bind` не могут заменить её лексический `this`.

#### Потеря `this` в callback

Контекст теряется, когда метод передают другой функции отдельно от объекта:

```js
const user = {
  name: 'John',

  printName() {
    console.log(this.name)
  },

  delayedPrintName() {
    setTimeout(this.printName, 1000)
  },
}

user.delayedPrintName()
```

Вызов `user.delayedPrintName()` получает правильный `this === user`. Но выражение `this.printName` только извлекает функцию и передаёт её в `setTimeout()`. Через секунду таймер вызывает callback уже без `user` слева от точки, поэтому `this` внутри `printName()` не указывает на `user`. Точное значение `this` у callback таймера зависит от среды, но имя `'John'` таким способом не будет получено.

Первый вариант исправления — стрелочный callback. Он сохраняет `this` из `delayedPrintName()`:

```js
delayedPrintName() {
  setTimeout(() => this.printName(), 1000)
}
```

Второй вариант — создать функцию с привязанным контекстом через `bind()`:

```js
delayedPrintName() {
  setTimeout(this.printName.bind(this), 1000)
}
```

Не вызывайте метод при передаче в таймер:

```js
setTimeout(this.printName(), 1000) // неправильно
```

Здесь `printName()` выполнится сразу, а его результат будет передан в `setTimeout()`.

Стрелочная функция в качестве самого метода тоже обычно не исправляет ситуацию:

```js
const user = {
  name: 'John',
  printName: () => console.log(this.name),
}
```

У такой функции нет собственного `this`: она берёт его из внешней области, а не из объекта `user`.

### Мемоизация

Мемоизация сохраняет результат функции по её аргументам, чтобы не повторять одинаковое вычисление:

```js
function memoize(fn) {
  const cache = new Map()

  return (value) => {
    if (cache.has(value)) return cache.get(value)

    const result = fn(value)
    cache.set(value, result)
    return result
  }
}
```

Она лучше всего подходит чистым функциям. Нужно продумать ключ кеша, ограничение его размера и очистку.

### Debounce и throttle

Оба приёма ограничивают слишком частые вызовы функции, но выбирают разные моменты выполнения:

- debounce вызывает функцию после того, как частые события прекратились на заданное время;
- throttle разрешает вызов не чаще указанного интервала.

Debounce удобен для поиска после ввода, throttle — для обработки прокрутки или перемещения указателя. В обоих случаях важно сохранять аргументы и `this`, а также предусмотреть отмену отложенного вызова.

## Частые ошибки

- Метод передан в callback отдельно от объекта (`setTimeout(this.printName, 1000)`) → внутри `this` не указывает на объект, выводится `undefined` → обернуть в стрелочную функцию `() => this.printName()` или привязать через `bind(this)`.
- Стрелочная функция использована как метод объекта с обращением к `this` → `this` берётся из внешней области, а не из объекта, свойства не находятся → объявлять метод обычной функцией или сокращённой записью `greet() {}`.
- Стрелочная функция возвращает объект без скобок (`() => { name }`) → фигурные скобки воспринимаются как тело, функция возвращает `undefined` → оборачивать литерал в круглые скобки: `() => ({ name })`.
- Переменная `let` или `const` используется до строки объявления → `ReferenceError` из-за временной мёртвой зоны (TDZ), хотя `var` в том же месте дал бы `undefined` → объявлять переменные до первого использования и не полагаться на hoisting.
- Метод вызван при передаче в таймер: `setTimeout(this.printName(), 1000)` → функция выполняется сразу, а таймер получает её результат → передавать саму функцию, без круглых скобок.

## Когда не использовать

Замыкание для хранения состояния удобно для небольших вещей вроде счётчика или кеша, но если данных и методов становится много, читать набор вложенных функций тяжело — лучше описать [класс](classes.md) с явными полями. IIFE для изоляции переменных в современном коде тоже не нужен: ES-модуль сам ограничивает область видимости.

`call()`, `apply()` и `bind()` стоит применять только там, где `this` действительно должен задаваться снаружи, например при работе с чужим API. В собственном коде проще передавать объект явным параметром или использовать стрелочный callback — тогда вопрос «какой здесь `this`» не возникает.
