# Нотация «О большое»

Два решения одной задачи могут работать одинаково быстро на десяти элементах и совсем по-разному на миллионе. **Нотация «О большое»** (Big O) описывает, как растут время работы или потребляемая память алгоритма с ростом размера входных данных `n`.

Нас интересует поведение при `n → ∞`, поэтому константы и младшие члены отбрасываем. Если функция выполняет `3n² + 5n + 100` операций, пишем `O(n²)`.

## Шкала сложностей

От лучшей к худшей:

| Big O | Название | Пример |
|---|---|---|
| O(1) | константная | доступ к элементу массива по индексу |
| O(log n) | логарифмическая | бинарный поиск |
| O(n) | линейная | проход по массиву |
| O(n log n) | линейно-логарифмическая | сортировка слиянием, быстрая сортировка (в среднем) |
| O(n²) | квадратичная | вложенный цикл, пузырьковая сортировка |
| O(2ⁿ) | экспоненциальная | наивный рекурсивный Фибоначчи |
| O(n!) | факториальная | перебор перестановок (задача коммивояжёра полным перебором) |

## Примеры для каждой сложности

### O(1) — константная

Доступ к элементу по индексу, поиск ключа в хеш-таблице. Одна операция независимо от длины данных.

```python run
def first_element(arr):
    return arr[0]

first_element([1, 2, 3, 4, 5])
```

### O(log n) — логарифмическая

На каждом шаге задача уменьшается вдвое.

```python run
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

binary_search([1, 3, 5, 7, 9, 11], 7)
```

### O(n) — линейная

Один проход по данным.

```python run
def find_max(arr):
    m = arr[0]
    for x in arr:            # n операций
        if x > m:
            m = x
    return m

find_max([3, 1, 4, 1, 5, 9, 2, 6])
```

### O(n log n) — линейно-логарифмическая

Так работает любая эффективная сортировка сравнениями. Встроенный `sorted()` использует Timsort.

```python run
sorted([5, 3, 8, 1, 9, 2])
```

### O(n²) — квадратичная

Вложенный цикл по всем парам элементов.

```python run
def has_duplicate_pair(arr):
    n = len(arr)
    for i in range(n):
        for j in range(i + 1, n):   # ~ n² / 2 пар
            if arr[i] == arr[j]:
                return True
    return False

has_duplicate_pair([1, 2, 3, 2])
```

### O(2ⁿ) — экспоненциальная

Рекурсия с двумя вызовами на каждом шаге и без мемоизации.

```python run
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)   # 2 вызова → 2ⁿ

fib(10)
```

### O(n!) — факториальная

Перебор всех перестановок. На практике такой сложности почти всегда нужно избегать.

```python run
from itertools import permutations

list(permutations([1, 2, 3]))   # 3! = 6 вариантов
```

## Время и память

Big O оценивает не только **время**, но и **дополнительную память**:

- сортировка слиянием — `O(n log n)` по времени и `O(n)` по памяти (нужен буфер для слияния);
- быстрая сортировка — `O(n log n)` по времени и `O(log n)` по памяти (стек рекурсии).

## Лучший, средний и худший случай

- **Лучший случай** (best case) — самый удачный сценарий: бинарный поиск сразу попал в середину, `O(1)`.
- **Средний случай** (average case) — типичная нагрузка.
- **Худший случай** (worst case) — гарантия сверху. Обычно указывают именно его.

Например, у быстрой сортировки средний случай `O(n log n)`, а худший — `O(n²)`, если опорный элемент всегда оказывается минимальным.

## Амортизированная сложность

**Амортизированная сложность** нужна, когда отдельная операция иногда дорогая, но в среднем по многим операциям — дешёвая.

Пример — `list.append` в Python. Обычно это `O(1)`, но иногда массив приходится перевыделить и скопировать, а это `O(n)`. В среднем на N добавлений получается амортизированно `O(1)`.

## Сложность операций встроенных структур Python

### list

| Операция | Сложность |
|---|---|
| `lst[i]` (индекс) | O(1) |
| `lst.append(x)` | O(1) амортизированно |
| `lst.insert(0, x)` (в начало) | O(n) |
| `lst.pop()` (с конца) | O(1) |
| `lst.pop(0)` (с начала) | O(n) |
| `x in lst` | O(n) |
| `len(lst)` | O(1) |

### dict и set

| Операция | Сложность |
|---|---|
| `d[k]`, `k in d` | O(1) в среднем, O(n) в худшем |
| `d[k] = v` | O(1) в среднем |
| `del d[k]` | O(1) в среднем |

### collections.deque

| Операция | Сложность |
|---|---|
| `append`, `appendleft` | O(1) |
| `pop`, `popleft` | O(1) |
| `d[i]` (по индексу в середине) | O(n) |

## Как оценивать сложность

1. **Считайте вложенные циклы**: два вложенных цикла по `n` дают `O(n²)`.
2. **Деление пополам** почти всегда означает логарифм.
3. **Хеш-структуры** (`dict`, `set`) дают поиск за `O(1)`.
4. **Сортировка** почти бесплатна: `O(n log n)` через `sorted()`.
5. На собеседовании всегда называйте сложность и по времени, и по памяти.
