# Байты и Unicode

Кодировки дают о себе знать, когда файл с русским текстом открывается «кракозябрами», сервер отвечает `UnicodeDecodeError` или длина строки вдруг не совпадает с размером данных. Причина одна: в программе текст — это строка (`str`), а на диске и в сети — байты (`bytes`), и между ними всегда стоит кодировка. Понимание этой границы избавляет от большинства таких ошибок.

## Минимальный пример

```python run
title = 'Купить хлеб'
data = title.encode('utf-8')  # str -> bytes
print(len(title), len(data))  # 11 21
print(data)  # b'\xd0\x9a\xd1\x83\xd0\xbf\xd0\xb8\xd1\x82\xd1\x8c \xd1\x85\xd0\xbb\xd0\xb5\xd0\xb1'

print(data.decode('utf-8'))  # Купить хлеб
print(data.decode('cp1251'))  # РљСѓРїРёС‚СЊ С…Р»РµР± — не та кодировка
try:
    data.decode('ascii')
except UnicodeDecodeError as error:
    print(error)  # 'ascii' codec can't decode byte 0xd0 in position 0: ordinal not in range(128)
```

Одна строка из 11 символов занимает 21 байт: каждая кириллическая буква в UTF-8 кодируется двумя байтами. Декодировать байты нужно той же кодировкой, которой их кодировали.

## Как это работает

### Байты

Объект `bytes` — это последовательность целых чисел от 0 до 255, каждое занимает один байт. При выводе Python показывает такие байты символами или в шестнадцатеричном виде.

Байты неизменяемы (immutable): поменять элемент на месте нельзя.

```python run
b = b'abc'
b[0] = 65  # TypeError: 'bytes' object does not support item assignment
```

Если байты нужно менять, есть массив байтов (`bytearray`). Он изменяемый (mutable).

```python run
ba = bytearray(b'abc')
ba[0] = 65  # 65 — код символа 'A'
print(ba)  # bytearray(b'Abc')
```

### Кодирование и декодирование

Стандарт Unicode чётко разделяет два понятия:

- **Кодовая позиция** (code point) — идентификатор символа, число от 0 до 1 114 111. В стандарте его записывают 4–6 шестнадцатеричными цифрами с префиксом `U+`, например `U+00E9` для `é`.
- **Байтовое представление** — последовательность из одного или нескольких байтов, которая получается, когда к кодовой позиции применяют конкретную кодировку.

Кодировка (encoding) — это алгоритм, который переводит кодовые позиции Unicode в байты и обратно. Один и тот же символ в разных кодировках может иметь разное байтовое представление.

При выводе `bytes` байт, соответствующий печатному ASCII-символу (коды 32–126), показывается самим символом. Остальные байты выводятся как escape-последовательность `\xHH`, где `HH` — две шестнадцатеричные цифры.

```python run
s = 'café'
print(f"Text = {s}, len(s) = {len(s)}, type(s) = {type(s)}")

b = s.encode('utf8')  # str -> bytes
print(f"Bytes = {b}, len(b) = {len(b)}, type(b) = {type(b)}")

c = b.decode('utf8')  # bytes -> str
print(f"Decoded = {c}, len(c) = {len(c)}, type(c) = {type(c)}")
```

В строке четыре символа, а в байтах — пять: в UTF-8 символ `é` занимает два байта (`\xc3\xa9`).

## Частые ошибки

- `open(path)` без `encoding` → на Windows файл читается в cp1251, на Linux в UTF-8, и один и тот же код даёт «кракозябры» или `UnicodeDecodeError` → всегда указывать `open(path, encoding='utf-8')`.
- Байты декодируют не той кодировкой → либо `UnicodeDecodeError`, либо текст вида `РљСѓРїРёС‚СЊ` без ошибки → выяснить реальную кодировку источника (заголовок HTTP, BOM, документация); `errors='replace'` использовать только для диагностики.
- Склеивают `str` и `bytes` → `TypeError: can't concat str to bytes` → кодировать и декодировать на границе ввода-вывода, а внутри программы работать только со строками.
- `len(data)` байтов принимают за длину текста → лимиты и обрезка «по символам» срабатывают на середине буквы → считать длину по `str`, байты — только для размера в сети или на диске.
- Байты режут по фиксированному размеру и декодируют каждый кусок отдельно → `UnicodeDecodeError: unexpected end of data` на границе куска → резать уже декодированную строку или использовать `codecs.iterdecode` для потока.

## Когда не использовать

`bytes` и `bytearray` не нужны, пока данные не уходят во внешний мир: внутри программы текст держат в `str`, а кодируют только при записи в файл, сокет или базу. Если библиотека сама принимает и возвращает строки (`json`, `csv`, `requests` с `response.text`), ручное `encode`/`decode` только добавит ошибок.

Выбирать кодировку, отличную от UTF-8, стоит только ради совместимости со старой системой, которая иначе не читает данные. Для новых файлов, API и баз UTF-8 — единственный разумный вариант.
