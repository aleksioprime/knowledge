# Redis: основы

Некоторые данные нужны очень часто и очень быстро, но хранить их надёжно не обязательно: сессии, счётчики просмотров, кэш тяжёлых запросов. Класть их в PostgreSQL — лишняя нагрузка на диск и транзакции. Redis держит данные в оперативной памяти и отвечает за доли миллисекунды. Это словарь «ключ → значение», доступный по сети всем вашим сервисам.

```bash
docker run -d --name redis -p 6379:6379 redis:7.4
docker exec -it redis redis-cli
```

## Минимальный пример

```text
127.0.0.1:6379> SET session:abc123 "user:1" EX 1800
OK
127.0.0.1:6379> GET session:abc123
"user:1"
127.0.0.1:6379> TTL session:abc123
(integer) 1800
```

Сессия сохранена на 30 минут. Через 1800 секунд Redis удалит ключ сам — никакой фоновой очистки писать не нужно.

То же самое из Python:

```bash
pip install redis
```

```python
import redis

r = redis.Redis(host='localhost', port=6379, decode_responses=True)

r.set('session:abc123', 'user:1', ex=1800)
r.get('session:abc123')  # 'user:1'
r.ttl('session:abc123')  # 1800
r.get('nothing')         # None — ключа нет
```

`decode_responses=True` превращает ответы в строки. Без него вернутся байты: `b'user:1'`.

## Как это работает

Все данные лежат в памяти одного процесса, а команды выполняются **по одной, строго по очереди**. Отсюда два главных свойства:

- **скорость** — нет диска и сложного планирования запросов;
- **атомарность каждой команды** — пока выполняется `INCR`, никто не вклинится между чтением и записью. Поэтому счётчик в Redis не теряет обновления, если в него одновременно пишут десять сервисов.

Ключ — это строка. Принято делить её двоеточиями, как путь: `user:1`, `task:42:tags`, `rate:login:10.0.0.1`. Так проще искать ключи и не путать данные разных частей приложения.

## Типы значений

**Строка** — текст, число или JSON. Числа можно увеличивать атомарно:

```text
> INCR views:task:42
(integer) 1
> INCR views:task:42
(integer) 2
```

**Хэш** — маленький словарь внутри ключа. Удобен для объекта, поля которого меняются по отдельности:

```text
> HSET user:1 name "Анна" email "anna@example.com" tasks_done 0
(integer) 3
> HINCRBY user:1 tasks_done 1
(integer) 1
> HGET user:1 name
"Анна"
```

**Список** — очередь или «последние N»:

```text
> RPUSH recent:user:1 "task:5" "task:7" "task:9"
(integer) 3
> LRANGE recent:user:1 0 -1
1) "task:5"
2) "task:7"
3) "task:9"
> LPOP recent:user:1
"task:5"
```

**Множество** — уникальные значения без порядка:

```text
> SADD task:42:tags "дом" "срочно" "дом"
(integer) 2
> SISMEMBER task:42:tags "работа"
(integer) 0
```

**Упорядоченное множество** — значения с числовым весом, всегда отсортированные. Это готовый рейтинг:

```text
> ZADD leaderboard 12 "anna" 30 "boris" 7 "vera"
(integer) 3
> ZINCRBY leaderboard 25 "anna"
"37"
> ZREVRANGE leaderboard 0 1 WITHSCORES
1) "anna"
2) "37"
3) "boris"
4) "30"
```

Есть и другие типы: `HyperLogLog` для приблизительного подсчёта уникальных значений, `Stream` для журналов событий, геоиндексы.

## Несколько команд за один раз

Каждая команда — это поход по сети. Если нужно выполнить несколько подряд, их отправляют пачкой через `pipeline`:

```python
pipe = r.pipeline()
pipe.incr('views:task:42')
pipe.expire('views:task:42', 60)
pipe.ttl('views:task:42')
pipe.execute()  # [1, True, 60]
```

По умолчанию `pipeline` в redis-py ещё и оборачивает команды в транзакцию `MULTI/EXEC`: другие клиенты не вклинятся между ними.

## Асинхронный клиент

Для FastAPI и других асинхронных приложений — тот же API с `await`:

```python
import redis.asyncio as redis

r = redis.from_url('redis://localhost:6379/0', decode_responses=True)
await r.set('key', 'value')
await r.get('key')  # 'value'
await r.aclose()
```

## Сохранность данных

Redis хранит данные в памяти, но умеет сбрасывать их на диск: снимками (RDB) раз в несколько минут или журналом команд (AOF). При падении можно потерять последние секунды или минуты записей. Поэтому в Redis хранят то, что можно восстановить или потерять без беды: кэш, сессии, счётчики, очереди с повтором. Деньги, заказы и пользователей хранят в PostgreSQL.

## Частые ошибки

- **Ключи без срока жизни.** Кэш, в который только добавляют, однажды съест всю память. Почти всем временным ключам ставьте `EX`.
- **`KEYS *` на рабочем сервере.** Команда перебирает все ключи и на это время блокирует Redis: остальные запросы стоят. Для перебора есть `SCAN`.
- **Большие значения.** Список на миллион элементов или JSON на десятки мегабайт тормозит все остальные команды, ведь они выполняются по очереди.
- **Байты вместо строк.** Забыли `decode_responses=True` — сравнение `r.get('k') == 'v'` всегда даёт `False`.
