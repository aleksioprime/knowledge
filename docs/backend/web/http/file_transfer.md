# Передача файлов по HTTP

Пользователь прикладывает отчёт к задаче, скачивает экспорт в PDF или перематывает видео. Для всего этого хватает HTTP, но у каждого сценария свои заголовки и свои риски: загрузку легко превратить в дыру в безопасности, а большой файл — в переполнение памяти сервера. Здесь — как принимать, отдавать и докачивать файлы.

## Минимальный пример

```bash
# Загрузка: форма с файлом и текстовым полем
curl -i -F 'file=@report.pdf' -F 'description=Отчёт' https://example.com/files
# HTTP/1.1 201 Created
# Location: /files/42

# Скачивание: сервер предлагает сохранить файл под своим именем
curl -sI https://example.com/files/42 | grep -iE 'content-(type|disposition|length)|accept-ranges'
# Content-Type: application/pdf
# Content-Disposition: attachment; filename="report.pdf"
# Content-Length: 3145728
# Accept-Ranges: bytes

# Докачка: запросить только байты начиная с 1 МиБ
curl -s -D - -o /dev/null -r 1048576- https://example.com/files/42 | head -2
# HTTP/1.1 206 Partial Content
# Content-Range: bytes 1048576-3145727/3145728
```

## Как это работает

### Загрузка на сервер

Формы обычно отправляют файлы как `multipart/form-data`:

```sh
curl -F 'file=@report.pdf' -F 'description=Отчёт' https://example.com/files
```

Каждая часть содержит собственные заголовки и отделяется boundary. Для загрузки одного бинарного объекта без дополнительных полей можно отправить тело как `application/octet-stream`.

Сервер должен:

- ограничивать размер тела и время загрузки;
- генерировать имя хранения самостоятельно;
- не доверять расширению, имени и `Content-Type` от клиента;
- проверять фактический тип и допустимое содержимое;
- хранить пользовательские файлы вне исполняемых директорий;
- при необходимости проверять файлы антивирусом;
- удалять временные и незавершённые загрузки.

### Скачивание

```http
HTTP/1.1 200 OK
Content-Type: application/pdf
Content-Disposition: attachment; filename="report.pdf"
Content-Length: 1048576
```

`Content-Disposition: attachment` предлагает скачать файл, а `inline` разрешает показать поддерживаемый формат в браузере. Имя файла необходимо безопасно кодировать и очищать от управляющих символов.

### Потоковая передача и диапазоны

Большие файлы лучше читать и отправлять частями, не загружая целиком в память. Запрос диапазона позволяет продолжить скачивание или перемотать видео:

```http
Range: bytes=1048576-
```

Сервер отвечает `206 Partial Content` и указывает `Content-Range`. Для возобновляемой загрузки на сервер обычно применяют отдельный прикладной протокол: загрузку частями с идентификатором сессии либо прямую загрузку в объектное хранилище по временной подписанной ссылке.

### NGINX

NGINX может ограничить тело директивой `client_max_body_size`, буферизовать загрузку, эффективно отдавать статику и поддерживать диапазоны. Настройки прокси должны учитывать максимальный размер файла и таймауты приложения.

## Частые ошибки

- Не настроен `client_max_body_size` → NGINX отвечает `413 Request Entity Too Large` уже на 1 МБ, хотя приложение готово принять больше → задать лимит в NGINX и такой же в приложении.
- Имя файла от клиента попадает в путь на диске → `../../etc/passwd` в поле `filename` перезаписывает чужие файлы → хранить под сгенерированным именем (UUID), оригинальное имя — в базе.
- Тип проверяют по расширению или `Content-Type` → загружен HTML или SVG со скриптом, который выполняется с вашего домена → проверять содержимое (сигнатуру файла), отдавать с `Content-Disposition: attachment` и `X-Content-Type-Options: nosniff`, лучше с отдельного домена.
- Файл целиком читают в память (`await file.read()` в обработчике) → процесс падает по памяти на большом файле → читать и отдавать частями: `StreamingResponse`, `sendfile` или `X-Accel-Redirect` через NGINX.
- Кириллица в `filename="Отчёт.pdf"` без `filename*` → часть браузеров показывает нечитаемое имя → добавлять `filename*=UTF-8''%D0%9E...` рядом с ASCII-вариантом.
- Диапазоны не поддержаны → видео не перематывается, прерванное скачивание начинается с нуля → отдавать `Accept-Ranges: bytes` и `206`; статику отдавать через NGINX, который умеет это сам.

## Когда не использовать

Большие файлы не стоит пропускать через своё приложение вообще: прямая загрузка в объектное хранилище (S3-совместимое) по подписанной ссылке снимает с сервера трафик, память и лимиты, а приложение хранит только метаданные и выдаёт ссылки.

Отдавать статику и уже загруженные файлы из Python-кода тоже невыгодно: NGINX делает это быстрее, с диапазонами и кешированием, см. [статику и файлы в NGINX](../nginx/static_and_files.md). Приложение остаётся для проверки прав и принятия решений, а не для копирования байтов.
