# Микросервисная архитектура

Микросервисная архитектура — это подход к разработке программного обеспечения, при котором большое, сложное приложение строится как набор малых, независимых сервисов, которые общаются друг с другом по сети. Это прямая противоположность монолитной архитектуре, где все компоненты приложения упакованы в один большой исполняемый блок.

Принципы:
- Декомпозиция по бизнес-возможностям: микросервисы обычно организуются вокруг конкретных бизнес-функций или доменов. Например, сервис для управления пользователями, сервис для обработки заказов, сервис для каталога товаров и т.д. Каждый сервис владеет своими данными и бизнес-логикой
- Независимость развёртывания: каждый микросервис может быть развёрнут, обновлён и масштабирован независимо от других
- Слабая связанность: сервисы взаимодействуют друг с другом через легковесные механизмы, обычно используя HTTP/REST API или асинхронные очереди сообщений (например, Kafka, RabbitMQ). Изменение внутреннего кода одного сервиса не должно требовать изменений в другом, если контракт API остаётся прежним
- Автономность и владение данными: каждый микросервис (или группа тесно связанных микросервисов) обычно имеет собственную базу данных или хранилище данных
- Отказоустойчивость: сбой в одном сервисе не должен приводить к полному отказу всей системы. Если один сервис перестаёт отвечать, другие могут продолжать работать, возможно, с некоторой ограниченной функциональностью или использованием механизмов компенсации
- Децентрализованное управление данными и языками: в микросервисах команды могут выбирать наиболее подходящие языки программирования, фреймворки и базы данных для каждого конкретного сервиса, что позволяет использовать сильные стороны различных технологий.
- Автоматизация: внедрение сервисов требует автоматизированного тестирования, непрерывной интеграции (CI), непрерывной поставки (CD) и автоматизации развёртывания

Недостатки:
- Сложность управления: распределённые системы сложнее проектировать, развёртывать и отлаживать
- Сложность тестирования: тестирование всей системы становится более сложным из-за распределённого характера
- Нагрузка на сеть: увеличение сетевого трафика и задержек из-за межсервисного взаимодействия
- Управление данными: сложности с распределёнными транзакциями и обеспечением согласованности данных между сервисами
- Операционные издержки: Требуется больше усилий и инструментов для CI/CD, мониторинга и эксплуатации
