# Объекты

Задача, пользователь, заказ — у каждого есть несколько связанных полей, и передавать их по отдельности в функции неудобно. Объект собирает такие данные в именованные свойства, но ведёт себя не как число или строка: при присваивании копируется ссылка, и изменение «копии» меняет оригинал. Здесь разобраны создание и чтение свойств, встроенные методы `Object`, варианты копирования и базовая модель управления памятью.

## Минимальный пример

```js
const task = {
  id: 1,
  title: 'Купить хлеб',
  deadline: { date: '2026-08-04' },
}

const alias = task
alias.title = 'Купить молоко'
console.log(task.title) // Купить молоко

const copy = structuredClone(task)
copy.deadline.date = '2026-09-01'
console.log(task.deadline.date) // 2026-08-04

console.log(Object.keys(task)) // [ 'id', 'title', 'deadline' ]
console.log(Object.hasOwn(task, 'done')) // false
console.log(task.assignee?.name) // undefined
```

## Как это работает

### Создание объекта

Литерал `{}` — основной способ создать объект. Внутри перечисляют свойства с данными и методы с поведением.

```js
const user = {
  id: 42,
  name: 'Alex',
  ['is' + 'Active']: true,
  greet() {
    return `Привет, ${this.name}`
  },
}

user.name
user['isActive']
```

Проверять собственное свойство следует через `Object.hasOwn(user, 'name')`. Оператор `in` учитывает и свойства в цепочке прототипов.

#### Терминология объектов

Несколько терминов важно различать, потому что они описывают разные части одной структуры:

- объект — коллекция свойств и внутренняя связь с прототипом;
- свойство — пара из ключа и значения;
- метод — свойство, значением которого является функция;
- собственное свойство находится непосредственно в объекте;
- унаследованное свойство найдено выше в цепочке прототипов;
- перечисляемые свойства участвуют в `Object.keys()` и `for...in`;
- getter и setter выполняют функции при чтении и записи свойства.

```js
const user = {
  firstName: 'Alex',
  lastName: 'Prime',

  get fullName() {
    return `${this.firstName} ${this.lastName}`
  },
}
```

#### Что может быть ключом объекта

Ключ свойства объекта может быть только строкой или `Symbol`. Числа и другие значения при использовании в качестве ключа преобразуются в строки.

```js
const object = {}

object[1] = 'один'
object['1'] // 'один': это тот же ключ

const id = Symbol('id')
object[id] = 42
```

`Symbol` создаёт уникальный ключ и не попадает в `Object.keys()` или обычный `for...in`. Получить symbol-ключи можно через `Object.getOwnPropertySymbols()`, а все собственные ключи — через `Reflect.ownKeys()`.

Объект не подходит как ключ другого обычного объекта: он обычно преобразуется в строку `'[object Object]'`, из-за чего разные объекты могут создать один и тот же ключ.

```js
const firstKey = { id: 1 }
const secondKey = { id: 2 }
const dictionary = {}

dictionary[firstKey] = 'first'
dictionary[secondKey] = 'second'

dictionary[firstKey] // 'second'
```

Если ключом должен быть объект, число без строкового преобразования или другое значение, используйте `Map`:

```js
const roles = new Map()
roles.set(firstKey, 'admin')
roles.set(secondKey, 'user')
```

#### Доступ к свойствам

Точка подходит для заранее известного корректного имени. Квадратные скобки позволяют использовать вычисляемое значение, пробелы и symbol-ключи.

```js
user.name
user['first name']
user[propertyName]
user[id]
```

Optional chaining `?.` прекращает чтение цепочки, если значение слева равно `null` или `undefined`. Вместо ошибки всё выражение вернёт `undefined`:

```js
const city = user.address?.city // undefined, если address нет
const firstPhone = user.contacts?.phones?.[0] // undefined, если массива нет
const label = user.getLabel?.() // undefined, если getLabel равен null или undefined
```

Оператор проверяет только значение непосредственно слева от `?.`. Например, в `user.address?.city` переменная `user` всё равно должна существовать.

У свойства есть descriptor: `value`, `writable`, `enumerable`, `configurable` либо функции `get` и `set`. Посмотреть его можно через `Object.getOwnPropertyDescriptor()`.

### Встроенные методы `Object`

Большинство современных методов вызываются у конструктора `Object`, а объект передаётся аргументом: `Object.keys(user)`. Это статические методы — они не вызываются как `user.keys()`.

#### Получение ключей и значений

Статические методы ниже превращают собственные перечисляемые свойства объекта в массив, который затем можно перебирать обычными методами массивов.

```js
const user = { name: 'Alex', role: 'admin' }

Object.keys(user) // ['name', 'role']
Object.values(user) // ['Alex', 'admin']
Object.entries(user) // [['name', 'Alex'], ['role', 'admin']]
```

Эти методы возвращают только собственные перечисляемые свойства со строковыми ключами. Symbol-ключи они не включают.

Дополнительные варианты:

- `Object.getOwnPropertyNames(object)` — все собственные строковые ключи, включая неперечисляемые;
- `Object.getOwnPropertySymbols(object)` — собственные symbol-ключи;
- `Reflect.ownKeys(object)` — все собственные строковые и symbol-ключи.

`Object.fromEntries()` выполняет обратную операцию для пар ключ–значение:

```js
const entries = [['name', 'Alex'], ['role', 'admin']]
Object.fromEntries(entries) // { name: 'Alex', role: 'admin' }
```

Например, объект можно преобразовать через методы массива:

```js
const doubled = Object.fromEntries(
  Object.entries({ a: 1, b: 2 })
    .map(([key, value]) => [key, value * 2]),
)
// { a: 2, b: 4 }
```

#### Проверка свойств

Результат проверки зависит от того, нужно ли учитывать унаследованные свойства или только свойства самого объекта.

```js
Object.hasOwn(user, 'name') // true
'toString' in user          // true: найдено в прототипе
```

`Object.hasOwn()` проверяет только собственное свойство и предпочтительнее `user.hasOwnProperty()`: объект может не иметь прототипа или содержать собственное свойство с таким именем.

Основные варианты:

| Проверка | Собственное свойство | Унаследованное свойство |
|---|---:|---:|
| `key in object` | да | да |
| `Object.hasOwn(object, key)` | да | нет |
| `object.hasOwnProperty(key)` | да | нет |
| `Reflect.has(object, key)` | да | да |

```js
const parent = { inherited: true }
const object = Object.create(parent)

object.own = undefined

'own' in object // true
'inherited' in object // true
Object.hasOwn(object, 'own') // true
Object.hasOwn(object, 'inherited') // false
Reflect.has(object, 'inherited') // true
```

Проверка через значение не определяет наличие свойства:

```js
object.own !== undefined // false
Object.hasOwn(object, 'own') // true
```

Свойство существует, но его значение равно `undefined`. Поэтому:

- используйте `Object.hasOwn()` для собственного свойства;
- используйте `in`, если подходят и унаследованные свойства;
- сравнивайте значение с `undefined`, только если важно именно значение, а не наличие ключа.

Ключом проверки может быть строка или `Symbol`. Правая часть `in` должна быть объектом: выражение `'name' in null` выбросит `TypeError`.

#### Создание и объединение

Эти методы создают объект с нужной структурой, копируют свойства либо группируют элементы коллекции:

- `Object.assign(target, ...sources)` копирует перечисляемые собственные свойства в `target` и изменяет его;
- `Object.create(prototype, descriptors)` создаёт объект с указанным прототипом;
- `Object.groupBy(items, callback)` группирует элементы iterable-объекта по строковым или symbol-ключам.

```js
const merged = Object.assign({}, defaults, settings)
const dictionary = Object.create(null)

const usersByRole = Object.groupBy(users, (user) => user.role)
// { admin: [...], user: [...] }
```

Результат `Object.groupBy()` не наследуется от `Object.prototype`. Если группировочный ключ должен оставаться объектом без преобразования в строку, используйте `Map.groupBy()`.

#### Сравнение через `Object.is()`

`Object.is()` почти совпадает с `===`, но иначе обрабатывает `NaN` и знаковые нули:

```js
Object.is(NaN, NaN) // true
NaN === NaN // false — строгое равенство считает NaN неравным даже самому себе

Object.is(0, -0) // false
0 === -0 // true — строгое равенство не различает положительный и отрицательный ноль
```

Объекты, как и при `===`, сравниваются по ссылке.

#### Descriptors

Descriptor описывает не только значение свойства, но и правила чтения, записи, перечисления и удаления. Для работы с ним используются следующие методы:

- `Object.getOwnPropertyDescriptor()` получает описание одного свойства;
- `Object.getOwnPropertyDescriptors()` — всех собственных свойств;
- `Object.defineProperty()` создаёт или изменяет одно свойство;
- `Object.defineProperties()` работает с несколькими свойствами.

```js
Object.defineProperty(user, 'id', {
  value: 42,
  writable: false,
  enumerable: false,
  configurable: false,
})
```

У свойств, созданных обычным присваиванием, три флага равны `true`. У нового свойства через `defineProperty()` неуказанные флаги по умолчанию равны `false`.

#### Ограничение изменений

| Метод | Добавление | Удаление | Изменение существующего значения |
|---|---|---|---|
| `Object.preventExtensions()` | нет | да | да |
| `Object.seal()` | нет | нет | да, если свойство writable |
| `Object.freeze()` | нет | нет | нет для data-свойств |

Состояние проверяют через `Object.isExtensible()`, `Object.isSealed()` и `Object.isFrozen()`. Все ограничения поверхностные и не распространяются автоматически на вложенные объекты.

#### Методы `Object.prototype`

Обычные объекты наследуют несколько методов:

- `toString()` и `toLocaleString()` — строковое представление;
- `valueOf()` — по умолчанию возвращает сам объект; некоторые встроенные типы переопределяют его;
- `isPrototypeOf()` — проверка присутствия объекта в цепочке прототипов;
- `propertyIsEnumerable()` — проверка собственного перечисляемого свойства;
- `hasOwnProperty()` — старая проверка собственного свойства.

```js
Object.prototype.toString.call([]) // '[object Array]'
prototype.isPrototypeOf(user)
user.propertyIsEnumerable('name')
```

Для новых проверок собственного свойства используйте `Object.hasOwn()`, а для массива — `Array.isArray()`.

### Копирование объектов

#### Присваивание не копирует объект

При обычном присваивании копируется ссылка. Обе переменные указывают на один объект:

```js
const original = { name: 'Alex' }
const sameObject = original // копируется ссылка, а не сам объект

sameObject.name = 'Anna'
original.name // 'Anna'
```

#### Поверхностная копия

`Object.assign()` может создать новый объект, но копирует только первый уровень. Вложенные объекты остаются общими:

```js
const original = {
  name: 'Alex',
  address: { city: 'Moscow' },
}

const assignCopy = Object.assign({}, original) // поверхностная копия

assignCopy.name = 'Anna' // меняется только копия
assignCopy.address.city = 'Kazan'

original.name // 'Alex'
original.address.city // 'Kazan'
```

Метод копирует собственные перечисляемые свойства, включая symbol-ключи. Он не сохраняет исходные descriptors и пользовательский прототип.

`Object.assign(target, source)` изменяет и возвращает первый аргумент. Для новой копии передавайте пустой объект как `target`.

#### Глубокая копия через `structuredClone()`

`structuredClone()` рекурсивно копирует поддерживаемые данные, умеет работать с циклическими ссылками, `Date`, `Map`, `Set`, `ArrayBuffer` и typed arrays.

```js
const original = {
  createdAt: new Date(),
  address: { city: 'Moscow' },
}

const copy = structuredClone(original) // глубокая копия

copy.address.city = 'Kazan'
original.address.city // 'Moscow'
```

Функции, symbol-значения, `WeakMap`, `WeakSet` и некоторые объекты среды клонировать нельзя. Descriptors, getters/setters и прототип экземпляра пользовательского класса также не следует ожидать в исходном виде.

#### Копирование прототипа и descriptors

Поверхностную копию с тем же прототипом, getter/setter и флагами свойств можно создать так:

```js
const copy = Object.create( // сохраняет прототип и дескрипторы свойств
  Object.getPrototypeOf(original),
  Object.getOwnPropertyDescriptors(original),
)
```

Вложенные значения при этом всё равно не копируются глубоко.

#### Ручное копирование

Когда нужно скопировать только часть бизнес-объекта или преобразовать данные, явная функция часто понятнее универсального клонирования:

```js
function copyUser(user) {
  return {
    id: user.id,
    name: user.name,
    address: user.address ? { ...user.address } : null,
  }
}
```

Кратко:

| Способ | Глубина | Основное применение |
|---|---|---|
| `b = a` | копии нет | ещё одна ссылка на тот же объект |
| `Object.assign({}, a)` | один уровень | обычные plain objects |
| `structuredClone()` | глубокая | поддерживаемые структуры данных |
| ручная функция | контролируемая | бизнес-модели и выборочные поля |

### `Proxy`

`Proxy` перехватывает операции над объектом: чтение, запись, проверку `in`, удаление, вызов функции и другие.

```js
const user = new Proxy({ age: 20 }, {
  set(target, key, value) {
    if (key === 'age' && value < 0) {
      throw new RangeError('Возраст не может быть отрицательным')
    }

    return Reflect.set(target, key, value)
  },
})
```

`Proxy` применяют для реактивности, валидации и логирования. `Reflect` выполняет стандартную операцию внутри trap без ручного воспроизведения её правил.

### Сборка мусора

Движок освобождает память объектов, которые больше недостижимы из корней программы. Наличие циклических ссылок само по себе не мешает сборке мусора; проблема возникает, если на всю структуру всё ещё существует достижимая ссылка.

Управлять моментом сборки нельзя. На практике важно удалять ненужные обработчики и таймеры, не удерживать DOM-элементы в долгоживущих коллекциях и ограничивать кеши.

### Стек и куча

Стек вызовов (call stack) хранит активные вызовы функций — stack frames. Каждый frame содержит информацию, необходимую для продолжения функции: её параметры, локальные привязки и адрес возврата. После завершения функции её frame снимается со стека.

```js
function first() {
  second()
}

function second() {
  console.trace()
}

first()
```

Слишком глубокая рекурсия переполняет стек и приводит к ошибке вроде `RangeError: Maximum call stack size exceeded`.

Куча (heap) — область динамической памяти, в которой движок обычно размещает объекты, массивы, функции и другие структуры с неизвестным заранее временем жизни. Недостижимые данные в куче освобождает сборщик мусора.

Упрощённая модель выглядит так:

```text
Call stack                         Heap
┌─────────────────────┐           ┌──────────────────────┐
│ showUser()           │           │ { name: 'Alex' }     │
│ user: ссылка ────────┼──────────►│                      │
├─────────────────────┤           └──────────────────────┘
│ main()               │
└─────────────────────┘
```

Фраза «примитивы хранятся в стеке, объекты — в куче» полезна лишь как грубая модель. Спецификация JavaScript не задаёт конкретное расположение данных, а движок может оптимизировать его. Для понимания поведения важнее следующее:

- примитив копируется как самостоятельное значение;
- при присваивании объекта копируется ссылка на тот же объект;
- стек описывает активные вызовы функций;
- куча связана с динамически создаваемыми данными и сборкой мусора.

## Частые ошибки

- Присваивание `const copy = original` принято за копию → изменение `copy` меняет `original`, баг всплывает далеко от места правки → делать поверхностную копию `{ ...original }` или глубокую через `structuredClone()`.
- Поверхностная копия вложенного объекта → `assignCopy.address.city = 'Kazan'` меняет и оригинал → для вложенных структур использовать `structuredClone()` или явную функцию копирования.
- Объект в роли ключа обычного объекта → все ключи превращаются в `'[object Object]'` и перезаписывают друг друга → брать `Map`, где ключом может быть любое значение.
- Проверка наличия свойства через `object.key !== undefined` → свойство со значением `undefined` считается отсутствующим, а унаследованное `toString` — присутствующим → использовать `Object.hasOwn()` для собственных свойств и `in`, если подходят унаследованные.
- `Object.freeze()` принят за глубокую заморозку → вложенные объекты по-прежнему меняются → замораживать вложенные объекты отдельно или не полагаться на заморозку как на защиту данных.

## Когда не использовать

Если нужен словарь с произвольными ключами, который часто пополняется и очищается, обычный объект подходит плохо: ключи приводятся к строкам, а порядок и размер приходится считать вручную. Для этого есть [`Map` и `Set`](collections.md). Упорядоченный список однотипных элементов — это [массив](arrays.md), а не объект с числовыми ключами.

`Proxy`, descriptors и `Object.defineProperty()` нужны библиотекам и фреймворкам, а в прикладном коде усложняют отладку: свойство ведёт себя не так, как выглядит. Для проверки данных при записи обычно достаточно обычной функции или setter в [классе](classes.md).
