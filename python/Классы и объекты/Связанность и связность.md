**Связанность модулей (coupling)**, часто называемую **зацеплением**, характеризует степень независимости модулей. При проектировании систем необходимо стремиться, чтобы модули имели минимальную зависимость друг от друга, т.е. были минимально «сцеплены» между собой (отсюда и термин «сцепление» или связанность). Это требование вытекает из одного из основных принципов системного подхода, требующего минимизации информационных потоков между подсистемами.

**Связанность (Coupling)** — это степень зависимости одного модуля (класса, функции, компонента) от других.

- **Высокая связанность** означает, что модули сильно зависят друг от друга: изменение одного приводит к необходимости менять другие.
- **Низкая связанность** (loose coupling) — идеал проектирования: модули независимы, изменение одного не влияет на другие.

Плохая связанность:

```python
# Плохая связанность: один модуль напрямую меняет атрибут другого
class A:
    def __init__(self):
        self.data = 0

class B:
    def change_a(self, a):
        a.data = 10  # напрямую меняет внутреннее состояние
```

Хорошая связанность:

```python
class A:
    def __init__(self):
        self._data = 0
    def set_data(self, value):
        self._data = value

class B:
    def update_a(self, a):
        a.set_data(10)  # взаимодействие через интерфейс
```

**Связность (cohesion)** характеризует целостность, «плотность» модуля, т.е. насколько модуль является простым с точки зрения его использования. В идеале модуль должен выполнять одну единственную функцию и иметь минимальное число «ручек управления». Примером модуля имеющего максимальную связность является модуль проверки орфографии, вычисления заработной платы сотрудника, вычисления логарифма функции. Если связанность является характеристикой системы, то связность характеризует отдельно взятый модуль.

- **Высокая связность (high cohesion)**: модуль делает только одну вещь, все его части нужны для решения этой задачи.
- **Низкая связность (low cohesion)**: модуль "размыт", занимается многими вещами, разными задачами.

Плохой пример:

```python
def process_all():
    check_spelling()
    calculate_salary()
    send_email()
# Несвязанные действия в одном модуле — низкая связность
```

Хороший пример:

```python
def calculate_salary():
    # Всё внутри связано с расчётом зарплаты сотрудника
    ...
```

**Высокая связность (cohesion)** и **низкая связанность (coupling)** делают код более читаемым, удобным для изменений и тестирования.

- **Coupling**: _Между модулями_. Стремимся к минимальной зависимости.
- **Cohesion**: _Внутри модуля_. Стремимся к максимальной "склеенности" (одна задача — один модуль).
