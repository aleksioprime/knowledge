# Менеджеры контекста

Открытый файл, соединение с базой, временная папка — всё это нужно освободить, даже если посередине работы случилась ошибка. Писать `try/finally` вокруг каждого такого места утомительно и легко забыть. Менеджер контекста и конструкция `with` берут это на себя: ресурс гарантированно освобождается при выходе из блока. Свой менеджер можно написать классом с `__enter__` и `__exit__` или генератором с декоратором `@contextmanager`.

## Минимальный пример

```python run
from contextlib import contextmanager

@contextmanager
def open_session(user):
    print(f'{user}: вход')
    try:
        yield {'user': user, 'tasks': []}
    finally:
        print(f'{user}: выход')

with open_session('alice') as session:
    session['tasks'].append('Купить хлеб')
    print(session['tasks'])  # ['Купить хлеб']

try:
    with open_session('bob') as session:
        raise ValueError('ошибка внутри блока')
except ValueError:
    print('выход выполнен даже при ошибке')
```

Вывод: `alice: вход`, список задач, `alice: выход`, затем `bob: вход`, `bob: выход` и сообщение об ошибке — `finally` отработал в обоих случаях.

## Как это работает

### Конструкция with

Менеджер контекста (context manager) даёт доступ к ресурсу внутри блока `with` и гарантирует, что ресурс освободится при выходе из блока — даже если внутри возникла ошибка.

Типичный пример — работа с файлом: после блока `with` файл закрывается автоматически.

```python run
# Создаём файл для примера
with open('data.txt', 'w') as file:
    file.write('apple\nbanana\ncherry')

with open('data.txt', 'r') as file:
    content = file.read()

print(file.closed)  # True
print(content)
```

### Класс-менеджер контекста

Свой менеджер контекста — класс с двумя методами:

- `__enter__` вызывается при входе в блок `with`; то, что он вернёт, попадает в переменную после `as`;
- `__exit__` вызывается при выходе из блока, в том числе при ошибке.

```python run
class Connection:
    def __enter__(self):
        print("Открываю соединение")
        self.connection = 1
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        print("Закрываю соединение при выходе или ошибке")
        self.connection = 0

with Connection() as obj:
    print("Внутри контекста:", obj.connection)  # Внутри контекста: 1

print("После выхода:", obj.connection)  # После выхода: 0
```

### Декоратор contextmanager

Менеджер контекста можно написать и функцией-генератором с декоратором `@contextmanager`. Код до `yield` выполняется при входе в блок, значение из `yield` попадает в переменную после `as`, а код в `finally` выполняется при выходе.

```python run
from contextlib import contextmanager

@contextmanager
def connection():
    print("Открываю соединение")
    conn = {"state": 1}
    try:
        yield conn
    finally:
        print("Закрываю соединение")
        conn["state"] = 0

with connection() as conn:
    print("Внутри контекста:", conn["state"])  # Внутри контекста: 1

print("После выхода:", conn["state"])  # После выхода: 0
```

## Частые ошибки

- `yield` в функции под `@contextmanager` не обёрнут в `try/finally` → при ошибке внутри блока `with` код после `yield` не выполняется, ресурс остаётся открытым → всегда ставить освобождение ресурса в `finally`.
- `__enter__` ничего не возвращает → переменная после `as` равна `None`, и обращение к ней падает с `AttributeError` → вернуть из `__enter__` `self` или нужный объект.
- `__exit__` возвращает `True` «на всякий случай» → исключения внутри блока молча проглатываются, ошибки теряются → возвращать `True` только тогда, когда исключение действительно обработано.
- Работа с объектом после выхода из `with` (`file.read()` после блока) → `ValueError: I/O operation on closed file` → переносить работу внутрь блока или сохранять результат в переменную.
- Два `yield` в одной функции под `@contextmanager` → `RuntimeError: generator didn't stop` → в менеджере контекста ровно один `yield`.

## Когда не использовать

Менеджер контекста нужен там, где есть пара «занять — освободить». Если ресурса нет, а блок `with` используется только чтобы «сгруппировать код» или выполнить действие один раз, это лишняя обёртка: достаточно обычной функции. Для действия, которое просто надо выполнить при выходе из функции, часто хватает `try/finally`, а для однократной очистки при завершении программы — `atexit`.

Если ресурс живёт дольше одного блока, например соединение с базой на всё время работы приложения, `with` на каждый вызов не подходит. Тогда ресурс открывают один раз при старте и закрывают при остановке, а менеджер контекста используют на уровне всего приложения или через `contextlib.ExitStack`.
