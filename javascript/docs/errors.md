# Ошибки и отладка

Ошибка прерывает обычный ход выполнения и передаёт информацию о проблеме вызывающему коду. Грамотная обработка не скрывает сбой, а позволяет восстановиться там, где это возможно, и сохранить полезный контекст для диагностики.

## Объект `Error`

Для программной ошибки обычно создают объект `Error`:

```js
const error = new Error('Пользователь не найден')

error.name // 'Error'
error.message // 'Пользователь не найден'
error.stack   // стек вызовов, формат зависит от среды
```

Основные свойства:

- `name` — название типа ошибки;
- `message` — понятное описание;
- `stack` — место возникновения и цепочка вызовов;
- `cause` — исходная причина, если она передана при создании.

## `throw`

`throw` немедленно прекращает текущее выполнение и передаёт ошибку вверх по стеку до ближайшего подходящего `catch`:

```js
function divide(a, b) {
  if (b === 0) {
    throw new RangeError('Деление на ноль')
  }

  return a / b
}
```

Технически бросить можно любое значение, но лучше бросать экземпляр `Error`: у него есть тип, сообщение и stack trace.

```js
throw new Error('Ошибка') // рекомендуется
throw 'Ошибка'            // допустимо, но неудобно обрабатывать
```

После `throw` перенос строки перед значением недопустим из-за автоматической вставки точки с запятой.

## `try...catch...finally`

Конструкция разделяет опасную операцию, восстановление после ошибки и обязательную завершающую работу:

- `try` содержит код, который может выбросить ошибку;
- `catch` выполняется при ошибке и получает брошенное значение;
- `finally` выполняется после `try/catch` независимо от результата.

```js
try {
  const user = await loadUser(id)
  renderUser(user)
} catch (error) {
  console.error(error)
  showGenericError()
} finally {
  hideLoader()
}
```

`finally` используют для очистки: скрытия loader, закрытия ресурса или снятия блокировки. Не возвращайте значение и не бросайте новую ошибку из `finally` без необходимости: это может заменить исходный результат или ошибку.

Если объект ошибки не нужен, параметр `catch` можно опустить:

```js
function parseOrNull(text) {
  try {
    return JSON.parse(text)
  } catch {
    return null
  }
}
```

## Встроенные типы ошибок

| Тип | Типичная причина |
|---|---|
| `Error` | общая программная ошибка |
| `TypeError` | операция с неподходящим типом значения |
| `ReferenceError` | обращение к неизвестной переменной |
| `SyntaxError` | некорректный синтаксис или JSON |
| `RangeError` | значение вне допустимого диапазона |
| `URIError` | некорректная обработка URI |
| `AggregateError` | несколько ошибок, например из `Promise.any()` |

```js
null.name // TypeError
unknownVariable // ReferenceError
JSON.parse('{broken}') // SyntaxError
new Array(-1) // RangeError — пытаемся создать массив с недопустимой длиной
```

`EvalError` сохранён ради совместимости, но современный JavaScript почти не создаёт его автоматически.

## Пользовательские ошибки

Собственный класс позволяет отличать ожидаемую ошибку предметной области от остальных:

```js
class ValidationError extends Error {
  constructor(message, field, options) {
    super(message, options)
    this.name = 'ValidationError'
    this.field = field
  }
}

try {
  validateUser(user)
} catch (error) {
  if (error instanceof ValidationError) {
    showFieldError(error.field, error.message)
  } else {
    throw error
  }
}
```

Неизвестную ошибку нужно пробрасывать дальше: текущий уровень не знает, как корректно её обработать.

### Причина ошибки — `cause`

При добавлении контекста сохраняйте исходную причину:

```js
async function loadProfile(id) {
  try {
    return await requestProfile(id)
  } catch (error) {
    throw new Error(`Не удалось загрузить профиль ${id}`, {
      cause: error,
    })
  }
}
```

Так верхний уровень получает понятный контекст, а `error.cause` сохраняет первоначальную ошибку.

## Распространение ошибок

Если функция не обрабатывает ошибку, она автоматически передаётся вызывающей функции:

```js
function readSettings() {
  return parseSettings()
}

try {
  readSettings()
} catch (error) {
  console.error('Настройки не загружены', error)
}
```

Перехватывайте ошибку там, где можно восстановиться, добавить полезный контекст или показать корректное состояние интерфейса. Не оборачивайте каждую функцию в `try...catch`.

## Синхронные и асинхронные ошибки

`try...catch` перехватывает ошибку только в текущем синхронном выполнении:

```js
try {
  setTimeout(() => {
    throw new Error('Поздняя ошибка')
  }, 0)
} catch (error) {
  // Не выполнится: callback запустится позже в другом вызове стека.
}
```

Обрабатывать такую ошибку нужно внутри callback:

```js
setTimeout(() => {
  try {
    riskyOperation()
  } catch (error) {
    reportError(error)
  }
}, 0)
```

### Ошибки Promise

Отклонённый Promise обрабатывают через `.catch()` или `await` внутри `try...catch`:

```js
try {
  await riskyOperation()
} catch (error) {
  reportError(error)
}

riskyOperation().catch(reportError)
```

Если забыть `await`, окружающий `try...catch` не перехватит позднее отклонение Promise. Promise нужно вернуть, ожидать или явно обработать через `.catch()`.

```js
try {
  riskyOperation() // Promise запущен, но не ожидается
} catch (error) {
  // rejected Promise сюда не попадёт
}
```

## Что находится в `catch`

JavaScript позволяет бросить любое значение, поэтому нельзя без проверки считать, что в `catch` всегда находится `Error`:

```js
try {
  riskyOperation()
} catch (error) {
  const message = error instanceof Error
    ? error.message // для Error используем его понятное сообщение
    : String(error) // неизвестное брошенное значение приводим к строке

  console.error(message)
}
```

## Глобальные ошибки в браузере

На верхнем уровне браузер позволяет заметить синхронную необработанную ошибку и отклонённый Promise. Такие обработчики подходят для журналирования, но не заменяют локальное восстановление интерфейса.

```js
window.addEventListener('error', (event) => {
  reportError(event.error)
})

window.addEventListener('unhandledrejection', (event) => {
  reportError(event.reason)
})
```

Эти обработчики подходят для последнего уровня мониторинга и логирования. Они не заменяют локальную обработку там, где приложение умеет восстановиться.

## Частые ошибки обработки

Следующие приёмы скрывают исходную проблему или делают поведение программы непредсказуемым:

- пустой `catch`, который скрывает проблему;
- вывод ошибки в консоль без восстановления или повторного `throw`;
- перехват слишком высоко без полезного контекста;
- потеря исходной ошибки при создании новой без `cause`;
- забытый `await` или `.catch()`;
- использование исключений для обычного ветвления, например проверки отсутствующего необязательного значения;
- показ пользователю внутренних stack trace и технических деталей;
- логирование паролей, токенов и персональных данных.

## Отладка

Отладка начинается не с исправления наугад, а с воспроизведения проблемы и поиска первой строки собственного кода в стеке вызовов:

- изучайте stack trace с первой относящейся к проекту строки;
- используйте breakpoints и пошаговое выполнение в DevTools;
- смотрите вкладки Network, Console и Sources;
- применяйте `console.table` для коллекций и `console.trace` для стека;
- воспроизводите ошибку на минимальном наборе входных данных;
- не выводите пароли, токены и персональные данные в production-логи.

## Частые источники ошибок

При диагностике полезно сначала проверить типичные причины, которые встречаются в прикладном JavaScript-коде:

- обращение к свойству `null` или `undefined`;
- потеря контекста `this`;
- изменение общего объекта или массива;
- забытый `await`;
- последовательное ожидание независимых операций;
- сравнение объектов по ссылке вместо сравнения нужных полей;
- использование пользовательских данных в `innerHTML`.
