# Использование v-html в Vue.js

Общий обзор XSS, CSRF, CORS и clickjacking находится в разделе [Веб-безопасность](../../backend/web/security/browser_attacks.md).

`v-html` вставляет строку как сырой HTML в DOM. Vue не экранирует содержимое, поэтому этот способ подходит только для доверенного и заранее очищенного HTML.

## Опасности

- XSS: если в строке окажется вредоносный HTML или скриптовые атрибуты, пользователь может выполнить чужой код.
- Потеря защиты Vue: интерполяция `{{ }}` экранирует данные, а `v-html` обходится без этой защиты.
- Непредсказуемое поведение: в HTML могут попасть лишние теги, inline-обработчики и чужая разметка, которая сломает верстку.

## Как избежать проблем

- Не передавайте в `v-html` данные от пользователя без очистки.
- Очищайте HTML через allowlist-фильтр, например на сервере или на границе входа.
- Используйте `v-text` или обычную интерполяцию, если нужен только текст.
- Для внешнего контента применяйте библиотеку санитайза, например DOMPurify, и по возможности дополняйте ее CSP.

## Когда использовать

- Когда нужно отобразить доверенный HTML из CMS, редактора или документации.
- Когда источник и правила очистки контролируются приложением.

## Пример

```vue
<template>
  <div v-html="safeHtml"></div>
</template>
```

Перед использованием убедитесь, что `safeHtml` уже очищен и не содержит произвольный пользовательский ввод.
