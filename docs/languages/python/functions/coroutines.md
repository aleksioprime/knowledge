# Корутины на генераторах

Иногда функции нужно «жить» между вызовами: накапливать состояние, принимать новые данные и отдавать результат, не пересчитывая всё с нуля. Класс с методами для этого тяжеловат, а генератор с `send()` делает то же самое в несколько строк. На этом приёме строились корутины до появления `async`/`await`, и он помогает понять, что происходит внутри современной асинхронности.

## Минимальный пример

```python run
def average_check():
    total = 0
    count = 0
    average = None
    while True:
        amount = yield average
        total += amount
        count += 1
        average = total / count

checks = average_check()
next(checks)             # запуск: корутина доходит до первого yield
print(checks.send(100))  # 100.0
print(checks.send(300))  # 200.0
print(checks.send(200))  # 200.0
checks.close()
```

## Как это работает

Корутина, или сопрограмма (coroutine), — функция, выполнение которой можно приостанавливать и возобновлять, передавая в неё данные в момент возобновления.

До Python 3.5 корутины делали на генераторах (generator-based coroutines). Генератор останавливается на `yield`, ждёт значение, получает его через метод `send()` и продолжает работу с места остановки.

### Передача данных через send

Перед первым `send()` корутину нужно запустить вызовом `next()` — так она дойдёт до первого `yield` и встанет в ожидание.

```python run
def coro():
    # Ждёт значение, отправленное внутрь генератора
    value = yield
    print(value)

print(coro())  # <generator object coro at 0x...>

c = coro()
next(c)  # выполняет код до первого yield
try:
    c.send(10)  # передаёт 10 в корутину, она печатает его и завершается
except StopIteration:
    # После print больше нет yield — генератор закончился,
    # и send() сообщает об этом исключением StopIteration
    print("Корутина завершилась")
c.close()  # для завершённого генератора ничего не делает
```

Чтобы `send()` вернул результат, после приёма значения нужен ещё один `yield`:

```python run
def coro():
    value = yield
    yield value * 2

gen = coro()
next(gen)
# send() передаёт 10 и получает значение из второго yield
print(gen.send(10))  # 20
```

### Исключения и закрытие: throw и close

Метод `throw()` выбрасывает исключение внутри корутины в точке, где она остановилась. Корутина может его перехватить и продолжить работу.

Метод `close()` завершает корутину: внутри неё в точке остановки возникает исключение `GeneratorExit`.

```python run
def coro_with_exception():
    try:
        yield
    except ValueError:
        yield "Исключение ValueError поймано"

c = coro_with_exception()
next(c)
print(c.throw(ValueError))  # Исключение ValueError поймано

def coro_to_close():
    try:
        yield 1
    except GeneratorExit:
        print("Генератор закрывается")

c = coro_to_close()
next(c)
c.close()  # Генератор закрывается
```

### Пример: расчёт вклада

Корутина один раз вычисляет множитель для процентов, а затем в бесконечном цикле принимает суммы вкладов и возвращает итоговые суммы.

В цикле два `yield`: первый принимает вклад, второй отдаёт результат. Поэтому после каждого `send()` вызывается `next()`, чтобы вернуть корутину к ожиданию следующего значения.

```python run
import math

def cash_return_coro(percent, years):
    """Считает сумму вклада с учётом процентов за указанный срок"""
    value = math.pow(1 + percent / 100, years)
    while True:
        try:
            deposit = yield
            yield round(deposit * value, 2)
        except GeneratorExit:
            print('Выход из корутины')
            raise

coro = cash_return_coro(5, 5)
next(coro)
values = [1000, 2000, 5000, 10000, 100000]
for item in values:
    print(coro.send(item))
    next(coro)
coro.close()  # Выход из корутины
```

### Корутины и потоки

Поток (thread) — составная часть процесса, который выполняется в операционной системе. Корутины работают внутри одного потока или пула потоков. Но принцип похож на работу потоков: корутины останавливаются и возобновляются, ждут друг друга и обмениваются данными.

## Частые ошибки

- `send(value)` сразу после создания корутины, без `next()` → `TypeError: can't send non-None value to a just-started generator` → сначала `next(coro)` или `coro.send(None)`, чтобы дойти до первого `yield`.
- После приёма значения в корутине нет следующего `yield` → `send()` выбрасывает `StopIteration`, результата не видно → добавить `yield результат` или обрабатывать `StopIteration`.
- В `except GeneratorExit` корутина продолжает работу и делает ещё один `yield` → `RuntimeError: generator ignored GeneratorExit` → после очистки выйти из функции или сделать `raise`.
- Забытый `close()` для корутины с открытым ресурсом → `finally` выполнится только при сборке мусора, в непредсказуемый момент → закрывать явно или оборачивать в `contextlib.closing`.
- Два `yield` в цикле, как в примере с вкладом, но `next()` после `send()` не вызывается → корутина отдаёт `None` через раз → либо вызывать `next()` после каждого `send()`, либо объединить приём и выдачу в один `yield`: `deposit = yield result`.

## Когда не использовать

Для настоящей асинхронности — сети, ожидания ввода-вывода, параллельных запросов — корутины на генераторах устарели: с Python 3.5 для этого есть `async`/`await` и `asyncio`, а генераторные корутины для `asyncio` удалены в Python 3.11. Приём стоит знать, чтобы понимать механику, но новый асинхронный код на нём не пишут.

Если состояние между вызовами простое, часто понятнее обычный класс с методом: он явно показывает поля и не требует помнить про запуск через `next()`. А если корутина только выдаёт значения и ничего не принимает, это обычный генератор — `send()` там не нужен.
