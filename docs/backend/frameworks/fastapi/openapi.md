# Документация API

FastAPI строит документацию сам: открываете `/docs` — там все эндпоинты. Но если ничего для неё не делать, фронтендер увидит заголовок «FastAPI 0.1.0», эндпоинт `get_task_tasks__task_id__get`, поле `title` без единого слова пояснения и ни одного описанного ответа, кроме `200` и `422`. Что вернётся, если задачи нет, — непонятно, придётся спрашивать в чате. Эта заметка о том, как превратить автодокументацию в документ, по которому с API можно работать без вопросов к автору.

## Минимальный пример

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

app = FastAPI(title='Задачник', description='API задач, меток и пользователей.', version='1.4.0')


class ErrorSchema(BaseModel):
    detail: str = Field(description='Что пошло не так', examples=['Задача не найдена'])


class TaskRead(BaseModel):
    id: int = Field(description='Идентификатор задачи', examples=[42])
    title: str = Field(description='Название задачи', examples=['Сдать отчёт'])
    done: bool = Field(description='Выполнена ли задача')


@app.get(
    '/tasks/{task_id}',
    tags=['tasks'],
    summary='Задача по id',
    responses={404: {'model': ErrorSchema, 'description': 'Задачи нет или она чужая'}},
)
def get_task(task_id: int) -> TaskRead:
    """Возвращает одну задачу текущего пользователя."""
    raise HTTPException(status_code=404, detail='Задача не найдена')
```

Всё, что здесь написано, попадает в схему OpenAPI — машиночитаемое описание API, из которого строятся страницы `/docs` (Swagger UI) и `/redoc` (ReDoc). Схему можно получить прямо в коде:

```python
schema = app.openapi()
print(schema['info'])
# {'title': 'Задачник', 'description': 'API задач, меток и пользователей.', 'version': '1.4.0'}
print(schema['paths']['/tasks/{task_id}']['get']['responses']['404'])
# {'description': 'Задачи нет или она чужая',
#  'content': {'application/json': {'schema': {'$ref': '#/components/schemas/ErrorSchema'}}}}
```

## Как это работает

OpenAPI — стандартный формат описания HTTP API в JSON: какие есть пути, какие у них параметры, тело запроса, возможные ответы и схемы данных. FastAPI собирает его из того, что уже есть в коде: путей, подсказок типов, моделей Pydantic. Swagger UI и ReDoc — просто веб-страницы, которые читают этот JSON с `/openapi.json` и рисуют по нему документацию.

Значит, чтобы документация стала понятной, нужно добавить в код описания — в трёх местах: у приложения, у эндпоинтов и у схем.

## Приложение: метаданные и адреса документации

```python
import os

from fastapi import FastAPI

DESCRIPTION = """
API учебного «Задачника»: задачи, метки и пользователи.

Все даты — в формате ISO 8601, время — в UTC.
"""

TAGS = [
    {'name': 'tasks', 'description': 'Создание, поиск и изменение задач.'},
    {'name': 'labels', 'description': 'Метки, которыми помечают задачи.'},
]

is_prod = os.getenv('APP_ENV') == 'prod'

app = FastAPI(
    title='Задачник',
    description=DESCRIPTION,
    version='1.4.0',
    openapi_tags=TAGS,
    docs_url=None if is_prod else '/docs',
    redoc_url=None if is_prod else '/redoc',
)
```

- `title`, `version` — заголовок страницы документации. `version` — версия *вашего API*, а не FastAPI; удобно брать её из `pyproject.toml` или переменной сборки.
- `description` — вводный текст, поддерживает Markdown. Сюда пишут то, что касается всего API: как авторизоваться, в каком формате даты, какие ограничения на частоту запросов.
- `openapi_tags` — описания групп эндпоинтов и их порядок в `/docs`. Сами эндпоинты относятся к группе через `tags=['tasks']` у декоратора или у `APIRouter`.

**Адреса документации.** `docs_url` (по умолчанию `/docs`), `redoc_url` (`/redoc`) и `openapi_url` (`/openapi.json`) можно сменить или отключить, передав `None`. С `APP_ENV=prod` пример выше отвечает так:

```text
GET /docs          404
GET /redoc         404
GET /openapi.json  200
```

Страницы скрыты, но сама схема по-прежнему доступна: по ней можно восстановить весь API. Чтобы убрать и её, задайте `openapi_url=None` — тогда `/docs` и `/redoc` тоже перестанут работать, потому что им нечего читать. Скрывать документацию в проде стоит для внутренних API, которые не должны светить свою структуру наружу; для публичного API документация, наоборот, часть продукта. Альтернатива отключению — закрыть `/docs` авторизацией или отдавать её только во внутренней сети.

## Эндпоинты: что делает, что принимает, что вернёт

```python
from fastapi import HTTPException, Query, status


@app.get(
    '/tasks',
    tags=['tasks'],
    summary='Список задач',
    response_description='Задачи, подходящие под фильтры',
)
def list_tasks(
    done: bool | None = Query(None, description='Только выполненные (`true`) или только открытые (`false`)'),
    label: str | None = Query(None, description='Метка, по которой фильтровать', examples=['работа']),
    limit: int = Query(20, ge=1, le=100, description='Сколько задач вернуть'),
) -> list[TaskRead]:
    ...


@app.get(
    '/tasks/search',
    tags=['tasks'],
    summary='Поиск задач',
    deprecated=True,
    description='Устарел: используйте `GET /tasks` с фильтрами.',
)
def search_tasks(q: str) -> list[TaskRead]:
    ...


@app.get(
    '/tasks/{task_id}',
    tags=['tasks'],
    summary='Задача по id',
    responses={404: {'model': ErrorSchema, 'description': 'Задачи нет или она принадлежит другому пользователю'}},
)
def get_task(task_id: int) -> TaskRead:
    """
    Возвращает одну задачу текущего пользователя.

    Чужие задачи для API не существуют: на них тоже придёт **404**.
    """
    if task_id not in tasks:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail='Задача не найдена')
    return tasks[task_id]
```

- `summary` — короткое название в списке эндпоинтов. Без него FastAPI сделает заголовок из имени функции: `Get Task`.
- `description` или **docstring** функции — подробное описание в Markdown. Если указаны оба, побеждает `description`. Docstring удобнее: описание лежит рядом с кодом. Вот что попало в схему:

```json
{
  "tags": ["tasks"],
  "summary": "Задача по id",
  "description": "Возвращает одну задачу текущего пользователя.\n\nЧужие задачи для API не существуют: на них тоже придёт **404**."
}
```

- `response_description` — подпись успешного ответа. По умолчанию это безликое `Successful Response`.
- `deprecated=True` — эндпоинт зачёркнут в `/docs`, а в схеме появляется `"deprecated": true`. Он продолжает работать: это предупреждение клиентам, а не отключение. Как выводить из эксплуатации целые версии API, разобрано в заметке про [проектирование API](../../web/http/api_design.md#как-вывести-старую-версию-из-эксплуатации).
- `Query(description=...)` — описание параметра строки запроса. То же есть у `Path`, `Header`, `Body`. Ограничения (`ge=1, le=100`) тоже попадают в схему, и клиент видит их без чтения кода.

### Ошибки в схеме

FastAPI знает только об успешном ответе и об ошибке проверки `422`. Про `404`, `401` или `409`, которые вы выбрасываете через `HTTPException`, он не знает: исключение может вылететь где угодно, и по коду это не определить. Без подсказки ошибка в документации просто не появится. Параметр `responses` описывает её явно:

```python
responses={404: {'model': ErrorSchema, 'description': 'Задачи нет или она принадлежит другому пользователю'}}
```

В схеме появляется ответ `404` со ссылкой на `ErrorSchema`, и генератор клиента создаст для него тип. Если одни и те же ошибки повторяются у многих эндпоинтов (`401` у всех защищённых), словарь `responses` можно передать в `APIRouter(responses=...)` один раз — он добавится ко всем эндпоинтам роутера.

`responses` только **описывает** ответ, но не создаёт его: следить, чтобы код действительно возвращал `{"detail": ...}` с кодом `404`, по-прежнему нужно самим. Как устроены сами ошибки — в заметке про [ошибки и коды ответов](errors.md).

## Схемы: описания и примеры полей

```python
from pydantic import BaseModel, Field


class TaskRead(BaseModel):
    id: int = Field(description='Идентификатор задачи', examples=[42])
    title: str = Field(description='Название задачи', examples=['Сдать отчёт'])
    done: bool = Field(description='Выполнена ли задача')
    labels: list[str] = Field(default=[], description='Метки задачи', examples=[['работа', 'срочно']])


class TaskCreate(BaseModel):
    title: str = Field(min_length=1, max_length=200, description='Название задачи')
    labels: list[str] = Field(default=[], description='Метки задачи')

    model_config = {
        'json_schema_extra': {
            'examples': [
                {'title': 'Сдать отчёт', 'labels': ['работа']},
                {'title': 'Купить хлеб'},
            ]
        }
    }
```

`Field(description=..., examples=[...])` описывает одно поле. `examples` — **список**: в Pydantic v2 это стандартное поле JSON Schema. Старый `example=` (в единственном числе) Pydantic v2 считает лишним аргументом и выдаёт предупреждение `PydanticDeprecatedSince20`. В схеме поле выглядит так:

```json
{"type": "string", "title": "Title", "description": "Название задачи", "examples": ["Сдать отчёт"]}
```

`model_config = {'json_schema_extra': {...}}` добавляет в схему модели целиком произвольные ключи — обычно примеры всего объекта. Это удобнее, когда поля имеют смысл только вместе: Swagger UI подставит такой пример в форму «Try it out», и запрос можно отправить сразу, не придумывая тело руками.

## Выгрузка схемы в `openapi.json`

Схема полезна не только как страница `/docs`. Если сохранить её в файл и положить в репозиторий, она становится **контрактом**, с которым могут работать другие:

- **фронтенд** видит точный формат запросов и ответов и может начать работу до того, как бэкенд готов;
- **генераторы клиентов** (openapi-generator, openapi-typescript) создают по ней типизированный клиент — функции и типы для TypeScript, Python, Kotlin;
- **Postman** импортирует её как коллекцию запросов (Import → файл `openapi.json`) — подробнее в заметке про [Postman](../../testing/postman/README.md);
- **ревью**: изменение схемы видно в диффе пулл-реквеста, и ревьюер сразу замечает, что поле переименовали.

Выгрузка — несколько строк:

```python
# scripts/export_openapi.py
import json
from pathlib import Path

from app.main import app

Path('openapi.json').write_text(json.dumps(app.openapi(), ensure_ascii=False, indent=2) + '\n')
```

```bash
python scripts/export_openapi.py
head -c 120 openapi.json
# {
#   "openapi": "3.1.0",
#   "info": {
#     "title": "Задачник",
#     ...
```

`app.openapi()` не запускает сервер и не обращается к базе — он только собирает схему из кода, поэтому скрипт работает и в CI.

### Проверка в CI: схема не изменилась незаметно

Простейшая защита — тест, который сравнивает текущую схему с сохранённой:

```python
# tests/test_openapi.py
import json
from pathlib import Path

from app.main import app


def test_openapi_schema_not_changed():
    saved = json.loads(Path('openapi.json').read_text())
    assert app.openapi() == saved, 'Схема API изменилась: проверьте совместимость и обновите openapi.json'
```

Если в `TaskRead` переименовать `labels` в `tags`, тест упадёт:

```text
E       AssertionError: Схема API изменилась: проверьте совместимость и обновите openapi.json
FAILED test_openapi.py::test_openapi_schema_not_changed - AssertionError: Схе...
1 failed in 0.36s
```

Тест не отличает совместимые изменения от ломающих: он падает на любом. Это намеренно — разработчик должен посмотреть на изменение, решить, не ломает ли оно клиентов (правила — в заметке про [проектирование API](../../web/http/api_design.md#обратная-совместимость)), и перевыгрузить файл. Если хочется автоматически отличать одно от другого, есть специальные утилиты сравнения схем OpenAPI (например, oasdiff), которые сообщают именно о ломающих изменениях.

## Внутренняя документация сервиса (README)

OpenAPI отвечает на вопрос «как вызвать API». Но новому разработчику в команде или дежурному ночью нужно другое: как этот сервис запустить, где его логи и от чего он зависит. Это пишут в `README.md` в корне репозитория сервиса. Хороший README отвечает на вопросы:

- **Назначение.** Что делает сервис и за что не отвечает — один абзац.
- **Как запустить локально.** Команды от `git clone` до работающего `/docs`: `docker compose up`, миграции, тестовые данные.
- **Переменные окружения.** Таблица: имя, назначение, пример значения, обязательна ли. Ссылка на `.env.example`.
- **Как запустить тесты и линтеры.** Одна-две команды.
- **Окружения и наблюдаемость.** Адреса стенда и прода, где документация API, дашборды мониторинга, где искать логи и трассировки.
- **Зависимости.** Базы, очереди, кэш и другие сервисы, которые этот сервис вызывает, — и кто вызывает его.
- **Как деплоится.** Что запускает выкатку, как откатиться, кто владелец сервиса.

Небольшой пример — README учебного проекта [«Задачник»](../../../practice/projects/tasker/README.md): запуск, проверка руками, мониторинг и структура. Главное правило: README должен быть достаточно коротким, чтобы его обновляли вместе с кодом. Устаревший README хуже отсутствующего — ему верят.

## Частые ошибки

- **Ошибки не описаны в `responses`.** В документации только `200` и `422`, а фронтенд узнаёт о `404` и `409` в бою. Описывайте каждую ошибку, которую эндпоинт может вернуть.
- **`example=` вместо `examples=[...]`.** В Pydantic v2 это устаревший способ, он выдаёт предупреждение; пишите список.
- **Отключили `docs_url`, но забыли `openapi_url`.** Страница `/docs` скрыта, а полная схема API по-прежнему отдаётся на `/openapi.json`.
- **Описание пересказывает имя.** `summary='Get task'`, `description='Получает задачу'` ничего не добавляют. Пишите то, чего не видно из сигнатуры: чьи задачи видны, что будет при повторе, какие ограничения.
- **`openapi.json` в репозитории устарел.** Файл выгрузили один раз и забыли. Без проверки в CI он отстаёт от кода через пару пулл-реквестов.
