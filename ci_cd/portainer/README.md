# Portainer

На сервере крутится десяток контейнеров, и чтобы посмотреть логи одного из них, перезапустить другой или понять, почему третий упал, каждый раз нужно заходить по SSH и вспоминать команды Docker. Portainer — веб-интерфейс для Docker, Docker Swarm и Kubernetes: контейнеры, образы, тома, сети и логи видны в браузере, а простые действия делаются кнопками.

## Минимальный пример

```bash
docker volume create portainer_data
docker run -d --name portainer --restart=always \
  -p 9443:9443 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v portainer_data:/data \
  portainer/portainer-ce:2.21.5
```

Откройте https://localhost:9443. Браузер предупредит о самоподписанном сертификате — для своей машины это нормально. При первом входе Portainer попросит придумать логин и пароль администратора.

```bash
curl -k https://localhost:9443/api/system/status
# {"Version":"2.21.5","InstanceID":"e4558449-...",...}
```

## Как это работает

Portainer — это сам по себе контейнер. Управлять Docker он может потому, что ему подключён сокет `/var/run/docker.sock`: через него Portainer отдаёт Docker те же команды, что и `docker` в терминале. Свои настройки и пользователей он хранит в томе `portainer_data`.

Другие серверы подключают как дополнительные **окружения** (environments): на каждом ставится лёгкий Portainer Agent, и все серверы видны в одном интерфейсе.

## Что удобно делать в Portainer

- **Посмотреть логи и состояние** контейнера, не вспоминая `docker logs -f --tail 100`;
- **открыть консоль** внутри контейнера прямо в браузере;
- **перезапустить, остановить, удалить** контейнер;
- **запустить стек** — вставить `docker-compose.yaml` в раздел Stacks и развернуть. Стек можно подключить к git-репозиторию, и Portainer будет обновлять его при изменениях;
- **почистить** неиспользуемые образы и тома;
- **выдать доступ** коллеге только к нужным контейнерам, не давая ему SSH на сервер.

## Когда не использовать

Portainer удобен для небольших серверов, домашних лабораторий и команд, где не все уверенно работают с Docker в терминале. Для продакшена с CI/CD изменения лучше вносить через репозиторий и пайплайн ([GitHub Actions](../github/README.md)), а Portainer использовать для наблюдения. Иначе однажды кто-то поменяет настройку кнопкой, и в репозитории её не будет.

## Частые ошибки

- **Портал без пароля дольше 5 минут.** Если сразу после запуска не создать администратора, Portainer из соображений безопасности остановит настройку, и контейнер придётся перезапустить: `docker restart portainer`.
- **Порт 9443 открыт в интернет.** Доступ к Portainer — это фактически root-доступ к серверу: через Docker можно запустить любой контейнер с любыми правами. Открывайте его только через VPN ([WireGuard](../../linux/docs/wireguard_setup.md)) или SSH-туннель.
- **Вход по HTTP на порту 9000.** В старых статьях Portainer открывают по `http://...:9000`. Внутри контейнера этот порт по-прежнему слушается, но публиковать его наружу не стоит: пароль администратора пойдёт открытым текстом. Публикуйте только 9443 (HTTPS), как в примере выше.
