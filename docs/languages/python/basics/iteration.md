# Генераторы коллекций и перебор

Когда из одного списка нужно собрать другой — отфильтровать, преобразовать, построить словарь, — цикл с `append` занимает пять строк и легко обрастает ошибками. Генераторы коллекций (comprehensions) делают то же в одну строку, а `range`, `enumerate` и `zip` избавляют от ручных индексов при переборе.

## Минимальный пример

```python run
tasks = ["Купить хлеб", "Позвонить врачу", "Сдать отчёт"]
done = [True, False, False]

pending = [task for task, is_done in zip(tasks, done) if not is_done]
print(pending)  # ['Позвонить врачу', 'Сдать отчёт']

status = {task: is_done for task, is_done in zip(tasks, done)}
print(status["Сдать отчёт"])  # False

for number, task in enumerate(pending, start=1):
    print(f"{number}. {task}")
# 1. Позвонить врачу
# 2. Сдать отчёт
```

## Как это работает

Генератор коллекции — это цикл `for`, записанный внутри скобок: квадратные дают список, фигурные — множество или словарь (если есть `ключ: значение`), а круглые — ленивый генератор. Условие `if` в конце отбрасывает ненужные элементы. Функции `range`, `enumerate` и `zip` возвращают итераторы, которые отдают элементы по одному, поэтому не создают лишних списков в памяти.

### Генераторы коллекций (comprehensions)

```python run
# Списка
list_ = [i for i in range(5) if i % 2 == 0]
print(list_)  # [0, 2, 4]

# Множества
set_ = {i for i in range(5) if i % 2 == 0}
print(set_)  # {0, 2, 4}

# Словаря
dict_ = {i: i**2 for i in range(5) if i % 2 == 0}
print(dict_)  # {0: 0, 2: 4, 4: 16}
```

### Перебор с `range`, `enumerate`, `zip`

```python run
num = 3

# range — последовательность чисел: от 1 до num (не включая) с шагом 2
for n in range(1, num, 2):
    print(f"Значение: {n}")

fruits = ["apple", "banana", "cherry"]

# enumerate — элементы вместе с индексами
for index, fruit in enumerate(fruits):
    print(index, fruit)

a = [1, 2, 3]
b = [4, 5, 6, 7]
c = [8, 9]

# zip — параллельный перебор; останавливается на самой короткой коллекции
for i in zip(a, b, c):
    print(i)
```

## Частые ошибки

- Перебор через `for i in range(len(tasks))` ради индекса → код длиннее и ломается при смене типа коллекции на множество или генератор → используйте `enumerate(tasks)`, а если индекс нужен для второго списка — `zip`.
- `zip` над списками разной длины → лишние элементы длинного списка молча отбрасываются, и часть данных теряется → проверьте длины заранее или передайте `strict=True` (Python 3.10+), чтобы получить `ValueError`.
- Изменение списка во время перебора `for task in tasks: tasks.remove(task)` → часть элементов пропускается, потому что индексы сдвигаются → соберите новый список генератором с условием или перебирайте копию `tasks[:]`.
- Двойной или тройной вложенный генератор с условиями → строка не читается, порядок `for` путается → разбейте на обычный цикл или вынесите внутреннюю часть в функцию.
- Генератор ради побочного эффекта: `[print(task) for task in tasks]` → создаётся ненужный список из `None`, и смысл кода скрыт → используйте обычный цикл `for`.

## Когда не использовать

Генератор коллекции хорош, когда результат — новая коллекция и логика помещается в одну строку. Если в теле нужны несколько шагов, обработка ошибок или вызовы с побочными эффектами (запись в файл, вывод), обычный цикл `for` читается лучше и его проще отлаживать.

Когда результат нужен только для однократного перебора и элементов много, вместо списка возьмите генераторное выражение в круглых скобках: `sum(order.total for order in orders)` не строит промежуточный список и экономит память.
