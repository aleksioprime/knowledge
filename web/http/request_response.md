# Структура HTTP-запроса и ответа

## Запрос

HTTP/1.1-запрос состоит из стартовой строки, заголовков, пустой строки и необязательного тела:

```http
POST /api/users?notify=true HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <token>
Content-Length: 25

{"name":"Alex","age":30}
```

Стартовая строка содержит:

- метод — какое действие запрашивается;
- target — путь и query-параметры;
- версию протокола.

Основные методы:

| Метод | Назначение | Идемпотентный |
|---|---|---|
| `GET` | Получить ресурс | Да |
| `HEAD` | Получить только заголовки | Да |
| `POST` | Создать ресурс или запустить операцию | Обычно нет |
| `PUT` | Полностью заменить ресурс | Да |
| `PATCH` | Частично изменить ресурс | Не обязательно |
| `DELETE` | Удалить ресурс | Да |
| `OPTIONS` | Узнать доступные возможности | Да |

Идемпотентность означает, что повтор одного и того же запроса должен приводить к тому же состоянию сервера. Это важно для безопасных повторов после сетевых ошибок.

## Ответ

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/users/42
Content-Length: 23

{"id":42,"name":"Alex"}
```

Ответ содержит строку статуса, заголовки и необязательное тело. Группы кодов:

- `1xx` — промежуточная информация;
- `2xx` — успешная обработка;
- `3xx` — перенаправление или использование кеша;
- `4xx` — ошибка запроса клиента;
- `5xx` — ошибка сервера или прокси.

Частые коды: `200 OK`, `201 Created`, `204 No Content`, `301/308` для постоянного перенаправления, `304 Not Modified`, `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`, `409 Conflict`, `422 Unprocessable Content`, `429 Too Many Requests`, `500 Internal Server Error`, `502 Bad Gateway`, `503 Service Unavailable`, `504 Gateway Timeout`.

## URL

```text
https://user@example.com:443/products/42?color=black#reviews
└─scheme─┘     └─host────┘port└──path────┘└─query────┘└fragment┘
```

Фрагмент после `#` обрабатывает браузер: в обычный HTTP-запрос он не отправляется. Секреты не следует помещать в URL, потому что URL попадают в историю, логи и заголовок `Referer`.
