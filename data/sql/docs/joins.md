# JOIN

### Логические виды JOIN

Пусть `A` — левая таблица, `B` — правая.

| Вид | Результат |
|---|---|
| `INNER JOIN` | Только совпавшие пары A–B |
| `LEFT OUTER JOIN` | Все строки A; для несовпавших B заполнена `NULL` |
| `RIGHT OUTER JOIN` | Все строки B; для несовпавших A заполнена `NULL` |
| `FULL OUTER JOIN` | Все совпавшие пары и несовпавшие строки обеих таблиц |
| `CROSS JOIN` | Декартово произведение: каждая строка A с каждой B |
| Self join | Таблица соединена сама с собой через разные alias |
| Semi join | Строки A, для которых существует совпадение в B |
| Anti join | Строки A, для которых совпадения в B нет |

Semi/anti join обычно записываются через `EXISTS` / `NOT EXISTS`:

```sql
SELECT d.*
FROM departments d
WHERE EXISTS (
    SELECT 1
    FROM employees e
    WHERE e.department_id = d.id
);
```

`NATURAL JOIN` и `JOIN ... USING (...)` соединяют одноимённые столбцы. `NATURAL JOIN` хрупок: добавление одноимённой колонки может молча изменить результат, поэтому в прикладном коде лучше явный `ON`.

### Условие в ON и WHERE

Для `INNER JOIN` перенос условия между `ON` и `WHERE` часто эквивалентен. Для `OUTER JOIN` — нет:

```sql
-- сохраняет отделы без активных сотрудников
SELECT d.name, e.email
FROM departments d
LEFT JOIN employees e
  ON e.department_id = d.id
 AND e.active;

-- WHERE отбрасывает NULL-расширенные строки и превращает смысл в INNER JOIN
SELECT d.name, e.email
FROM departments d
LEFT JOIN employees e ON e.department_id = d.id
WHERE e.active;
```

### Физические алгоритмы JOIN

Логический `INNER/LEFT/...` описывает результат, а физический алгоритм — способ вычисления.

| Алгоритм | Идея | Хорошо работает когда |
|---|---|---|
| Nested Loop | Для каждой внешней строки ищет совпадения во внутреннем источнике | Внешний набор мал, на внутреннем есть подходящий индекс |
| Hash Join | Строит hash-таблицу по меньшей стороне и проверяет большую | Equality join, достаточно памяти |
| Merge Join | Читает обе стороны в порядке ключа и сливает | Входы уже отсортированы/индексированы или сортировка окупается |

Некоторые СУБД имеют дополнительные варианты. Алгоритм выбирает оптимизатор; название логического JOIN само по себе алгоритм не определяет.

### Сколько строк может вернуть JOIN

Для таблиц по 10 и 100 строк **без ограничений уникальности**:

| JOIN | Минимум | Максимум |
|---|---:|---:|
| `CROSS JOIN` | 1000 | 1000 |
| `INNER JOIN` | 0 | 1000 |
| `LEFT JOIN` | 10 | 1000 |
| `RIGHT JOIN` | 100 | 1000 |
| `FULL JOIN` | 100 | 1000 |

Максимум достигается, если каждая строка совпадает с каждой. Для `FULL JOIN` отсутствие совпадений даёт 110 строк, но минимум — 100: все 10 левых строк можно сопоставить с частью правых, сохранив итог не меньше большей стороны.
