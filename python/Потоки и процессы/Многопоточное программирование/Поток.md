**Поток** — наименьшая единица выполнения операций с независимым набором инструкции. Это — часть процесса. Каждая программа представляет собой процесс (или несколько) и имеет по крайней мере один поток — главный, который выполняет инструкции для этого процесса. Процесс не может существовать без потока, и поток не может быть без процесса. В контексте многопоточности, в пределах одного процесса потоки могут выполняться *параллельно, делая возможным одновременное выполнение нескольких задач в рамках одной программы.

Параллелизм:

- **_GIL_** — это механизм, который предотвращает одновременное выполнение нескольких потоков Python в одном процессе в единицу времени. Это означает, что даже в многоядерной системе в любой момент времени только один поток может исполнять байт-код. Потоки же конкурируют за получение GIL, поэтому, когда речь идет о CPython, встреченные в тексте фразы: "параллельное выполнение потоков" или  "одновременное выполнение потоков" следует понимать, как "конкурентное выполнение потоков".  
- **Конкурентность**: Конкурентное выполнение потоков означает, что потоки конкурируют за свое выполнение, то есть, кто первый захватил GIL, тот и выполняется в текущий момент времени. Например, когда потоки занимаются операциями ввода-вывода или ожиданием событий, которые не требуют исполнения Python-кода. В таких случаях GIL может быть освобожден (напомню, I/O bound операции выполняются на ресурсах ОС), позволяя другим потокам продолжить выполнение. Это создает иллюзию одновременности, поскольку потоки переключаются достаточно быстро. Однако, в действительности конкуренции за процессорное время в прямом смысле нет — потоки просто ожидают своей очереди на исполнение, а распределение процессорного времени между ними определяется планировщиком задач операционной системы, согласно его алгоритму.

В Python потоки можно создавать, используя модуль `threading` и встроенный в него класс `Thread`:

```python
import threading

thread = threading.Thread()
```

- `Thread` — это основной класс модуля, представляющий отдельный поток выполнения. Все потоки в Python-процессе разделяют одно и то же адресное пространство памяти процесса. Все глобальные переменные доступны из любого потока. Однако, каждый поток имеет свою собственную локальную память и собственный стек вызовов.
- Потоки часто используются для выполнения задач, которые требуют ожидания, например, ввода-вывода, позволяя программе продолжать выполнение других задач во время ожидания.
- Когда нам нужно создать и запустить новый поток — Python обращается к операционной системе с "просьбой" создать его, т.к. сам он сделать этого не может (_поскольку создание потоков и процессов_ — _это вотчина ОС_). ОС (_а точнее, ее планировщик_), увидев "просьбу", создает поток (_однако он может это сделать не сразу_).

Конструктор класса имеет следующий вид:

`Thread(group=None, target=None, name=None, args=(), kwargs={}, *, daemon=None)`, где:

- `group=None` — зарезервировано для будущего расширения при реализации класса `ThreadGroup`.
- `target=None` — вызываемый объект (функция), который будет вызываться методом`Thread.run()`. По умолчанию `None` это означает, что ничего не вызывается.
- `name=None` — имя потока. По умолчанию уникальное имя создается в форме "Thread-N", где N - небольшое десятичное число или с версии Python 3.10 `Thread-N (target)`, где `target` — это `target.__ name__`, если конечно указан аргумент `target`.
- `args=()` — кортеж аргументов для вызываемого объекта `target`. Может передаваться и в списке. По умолчанию `()`
- `kwargs={}` — словарь ключевых аргументов для вызываемого объекта `target`. По умолчанию {}.
- `daemon=None` — если аргумент `daemon` не `None`, то он явно устанавливает, является ли поток демоническим. Если `daemon=None` (по умолчанию), то демоническое свойство наследуется от текущего потока.

  
**Пошаговый(_условный_) процесс создания потока:**

- Пользовательский код создает запрос на создание нового потока.
- CPython вызывает функции из операционной системы для создания нового системного потока ОС.
- Новый поток ждет момента, пока GIL не освободится от другого потока(если до этого был создан другой поток).
- Новый системный поток ОС захватывает GIL и запускает пользовательскую функцию.
- Каждый системный поток OС, запущенный для выполнения Python кода, ждет освобождения GIL.
- Планировщик операционной системы планирует несколько активных системных потоков для выполнения на одном процессоре и занимается перераспределением ресурсов, когда другой поток отпустил GIL.

Задачу можно запустить в новом потоке, создав экземпляр класса `Thread` и указав функцию для выполнения в новом потоке через аргумент `target`.

```python
# создаем и настраиваем новый поток для выполнения функции
thread = Thread(target=task)
```

После создания потока его необходимо запустить, вызвав метод `start()`.

```python
# запускаем задачу в новом потоке
thread.start()
```

```python
Простой пример выполнения целевой функции task() в отдельном потоке:

import threading

# Функция, которую мы хотим выполнить в отдельном потоке
def task():
    for i in range(1, 6):        
        print(i)

# Создаем объект Thread, указывая функцию для выполнения
thread = threading.Thread(target=task)

# Запускаем поток
thread.start()
```

Вывод:

```undefined
1
2
3
4
5
```

- Когда Вы создаете новый поток с помощью `Thread(target=task)` и запускаете его методом `start()`, происходит запуск этого потока и выполнение внутри него переданной функции `task()`.
    - `task()` просто проходится циклом `for` по итератору и выводит каждый его элемент.
    - По факту завершения работы функции этот поток завершит свою работу.

Порой нам необходимо дождаться выполнения одного потока — этого можно добиться с помощью метода `join()`.

```python
from time import sleep, time
from threading import Thread, current_thread


# Простая функция, которая приостанавливает свое выполнение на 1 секунду и выводит сообщение
def task():
    # Определяем id потока, в котором работает функция
    task_thread_id = current_thread().ident
    # Засыпаем...
    sleep(1)
    # Обозначаем поток, который выполняется
    print(f'Это сообщение от задачи task из потока {task_thread_id}')


# Засекаем время начала выполнения скрипта
start = time()

# Определяем id главного потока и выводим его
base_thread_id = current_thread().ident
print(f'id главного потока: {base_thread_id}')

# Создаем и запускаем новый поток для выполнения функции task
thread = Thread(target=task)
print("Запускаем новый поток")
thread.start()

# выводим сообщение
print('Ждем завершения нового потока...')

# Главный поток засыпает
sleep(1)

# Ждем завершения задачи и завершения работы нового потока
thread.join()
print('Работа нового потока завершена')
print(f"Время выполнения программы: {time() - start:.4f} секунды")
```

```
id главного потока: 132541433880576
Запускаем новый поток
Ждем завершения нового потока...
Это сообщение от задачи task из потока 132541418829376
Работа нового потока завершена
Время выполнения программы: 1.0009 секунды
```

- **Создание и запуск нового потока**: Когда вы создаете новый поток с помощью `Thread(target=task)` и запускаете его методом `start()`, происходит запуск этого потока и выполнение внутри него переданной функции `task()`.
    - `task()` просто ждет 1 секунду `sleep(1)` и затем выводит сообщение.
    - По факту завершения работы функции этот поток завершит свою работу.
- **Вывод сообщения в главном потоке**: Пока новый поток занят выполнением функции `task()`, главный поток продолжает выполнение программы и выводит сообщение "Ждем завершения нового потока...". Это сообщение появляется сразу после запуска нового потока. После него вставлен "сон" на 1 секунду. После того, как новый поток завершит свою работу (`thread.join()`), произойдет печать сообщений о завершении его работы и времени выполнения всей программы.
- **Ожидание главным потоком завершения работы нового потока**: Метод `join()` не позволяет завершиться главному потоку до момента окончания работы нового потока. В примере, когда выполнение программы в главном потоке доходит до инструкции `thread.join()`, главный поток блокируется и ждет, пока новый поток завершит выполнение функции `task()` и завершит свою работу. Только после этого продолжится выполнение программы в главном потоке.
- **Еще несколько важных моментов**: Обратите внимание на **id потоков**, главного и того, в котором выполняется задача task, они **разные**, что подтверждает создание и работу нового потока, отличного от главного.  
    Обратите внимание на время работы программы, оно **не 2 секунды**, как можно было бы ожидать, а **чуть больше одной**, что говорит о том, что два вызова функции `sleep(1)` (_один в основном потоке и один в дочернем потоке_) выполнялись конкурентно, благодаря многопоточности.
