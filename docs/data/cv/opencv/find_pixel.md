# Поиск пикселя по цвету

Найти на изображении пиксель нужного цвета — маркер, лазерную точку, белую метку — задача, которую хочется решить двумя вложенными циклами. На изображении 1920×1080 это два миллиона итераций на Python и секунды ожидания. NumPy и OpenCV делают то же самое одним вызовом за миллисекунды, нужно лишь помнить, в каком порядке они возвращают координаты.

## Минимальный пример

Белый пиксель на чёрном фоне. Маска `np.all(image == [255, 255, 255], axis=-1)` отмечает пиксели, у которых совпали все три канала, а `np.argwhere` возвращает их координаты как `(строка, столбец)`.

```python
import cv2
import numpy as np

image = np.zeros((5, 10, 3), dtype=np.uint8)
image[3, 7] = (255, 255, 255)                       # белый пиксель: y=3, x=7

mask = np.all(image == [255, 255, 255], axis=-1)    # форма (5, 10), True там, где белый
coords = np.argwhere(mask)
print(coords)                                       # [[3 7]] — (y, x)

y, x = coords[0]
cv2.circle(image, (x, y), 2, (0, 0, 255), 1)        # в OpenCV точка передаётся как (x, y)
```

## Как это работает

### Перебор пикселей циклами

Самый прямой способ — вложенные циклы по строкам и столбцам. Он понятен, но самый медленный: каждое сравнение выполняется в Python.

```python
for y in range(image.shape[0]):          # строки
    for x in range(image.shape[1]):      # столбцы
        if (image[y, x] == [255, 255, 255]).all():
            print(y, x)                  # 3 7
```

### Маска и `np.where`

Сравнение `image == [255, 255, 255]` даёт массив формы `(h, w, 3)` из `True`/`False` по каждому каналу. `np.all(..., axis=-1)` сворачивает последнюю ось: пиксель считается подходящим, только если совпали все три канала. Получается двумерная маска.

`np.where(mask)` с одним аргументом возвращает кортеж из двух массивов: отдельно строки и отдельно столбцы всех подходящих пикселей.

```python
mask = np.all(image == [255, 255, 255], axis=-1)
rows, cols = np.where(mask)
if rows.size > 0:
    print(rows[0], cols[0])   # 3 7 — первый найденный пиксель, (y, x)
```

### `np.argwhere`

`np.argwhere(mask)` возвращает те же координаты, но в виде массива пар `[y, x]` — удобнее, когда нужно перебирать точки.

```python
mask = np.all(image == [255, 255, 255], axis=-1)
points = np.argwhere(mask)
if points.size > 0:
    print(tuple(points[0]))   # (3, 7) — (y, x)
```

### `cv2.findNonZero`

Функция OpenCV находит все ненулевые пиксели **одноканального** изображения. Сначала строится бинарная маска `uint8`, где искомые пиксели равны 255, затем `findNonZero` возвращает их координаты уже в порядке OpenCV — `(x, y)`.

```python
binary = np.where(np.sum(image, axis=-1) > 30, 255, 0).astype(np.uint8)
points = cv2.findNonZero(binary)            # None, если ничего не найдено
if points is not None:
    print(tuple(points[0][0]))              # (7, 3) — (x, y)
```

`np.sum(image, axis=-1) > 30` отмечает любые не совсем чёрные пиксели — это удобно, если цвет не идеально чистый. Для поиска точного цвета бинарную маску проще получить из `mask.astype(np.uint8) * 255`.

### Поиск по диапазону цвета

На реальных фотографиях цвет никогда не совпадает точно. Вместо `==` используют `cv2.inRange`, который отмечает пиксели в диапазоне между нижней и верхней границей по каждому каналу.

```python
lower = np.array([200, 200, 200])
upper = np.array([255, 255, 255])
mask = cv2.inRange(image, lower, upper)     # uint8: 255 внутри диапазона, 0 снаружи
points = cv2.findNonZero(mask)
```

## Частые ошибки

- `image == [255, 255, 255]` без `np.all(axis=-1)` → маска трёхмерная, `np.where` возвращает три массива, а индексы попадают в каналы → сворачивать ось каналов.
- Координаты из `np.where`/`np.argwhere` переданы в `cv2.circle` как есть → точка рисуется в `(y, x)` вместо `(x, y)` → переставлять или брать `findNonZero`.
- `cv2.findNonZero` на цветном изображении → `cv2.error: ... src.channels() == 1` → сначала построить одноканальную маску `uint8`.
- Обращение к `white_pixel[0][0]` без проверки → `IndexError`, если пикселя нет, или `TypeError` на `None` от `findNonZero` → проверять `size > 0` и `is not None`.
- Поиск точного цвета на JPEG → ничего не найдено, потому что сжатие сдвинуло значения на несколько единиц → использовать `cv2.inRange` с допуском или сравнивать расстояние до цвета.
- Маска из `np.where(..., 255, 0)` без `.astype(np.uint8)` → `int64`, функции OpenCV её не принимают → приводить тип.

## Когда не использовать

Если нужны не отдельные пиксели, а объект — пятно, метка, фигура, — поиск по координатам даст тысячи точек без структуры. Для этого есть `cv2.findContours` (контуры фигур) и `cv2.connectedComponentsWithStats` (связные области с их центрами и размерами): они сразу дают центр и площадь объекта.

Когда искомый цвет меняется от освещения, сравнение в BGR ненадёжно: светлый и тёмный красный далеки друг от друга по всем трём каналам. Переводят в HSV (`cv2.COLOR_BGR2HSV`) и задают диапазон по тону (Hue), тогда яркость перестаёт мешать.
