# Динамическое программирование

«Сколькими способами», «минимальное число монет», «самая длинная общая часть двух строк» — такие задачи решаются рекурсией, которая на `n ≈ 40` уже не успевает: одни и те же подзадачи считаются миллионы раз. Динамическое программирование (dynamic programming, DP) заставляет решать каждую подзадачу один раз, и экспоненциальный перебор превращается в `O(n)` или `O(n·m)`.

## Минимальный пример

```python run
from functools import lru_cache

calls = 0

def ways_naive(steps):
    """Сколькими способами подняться по лестнице шагами по 1 или 2 ступеньки."""
    global calls
    calls += 1
    if steps <= 2:
        return steps
    return ways_naive(steps - 1) + ways_naive(steps - 2)

@lru_cache(maxsize=None)
def ways(steps):
    if steps <= 2:
        return steps
    return ways(steps - 1) + ways(steps - 2)

print(ways_naive(20), calls)        # 10946 13529 — вызовов больше, чем ступенек
print(ways(20), ways.cache_info().misses)   # 10946 20 — каждая подзадача решена один раз
```

## Как это работает

Наивная рекурсия часто решает одни и те же подзадачи снова и снова. **Динамическое программирование** (dynamic programming, DP) — приём, при котором каждая подзадача решается **один раз**, а результат сохраняется.

Он применим, когда у задачи есть два свойства:

1. **Оптимальная подструктура** — решение задачи складывается из решений её подзадач.
2. **Перекрывающиеся подзадачи** — одни и те же подзадачи возникают много раз.

### Два подхода

#### Сверху вниз: мемоизация

**Сверху вниз** (top-down, memoization): пишем обычную рекурсию, но кешируем ответы. Подходит, когда нужны не все подзадачи.

#### Снизу вверх: табуляция

**Снизу вверх** (bottom-up, tabulation): заполняем таблицу `dp[]` от меньших подзадач к большим. Не тратит стек рекурсии.

### Числа Фибоначчи

Сверху вниз с `functools.lru_cache`:

```python run
from functools import lru_cache

@lru_cache(maxsize=None)
def fib_topdown(n):
    if n < 2: return n
    return fib_topdown(n - 1) + fib_topdown(n - 2)

fib_topdown(50)
```

Снизу вверх с массивом:

```python run
def fib_bottomup(n):
    if n < 2: return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

fib_bottomup(50)
```

Снизу вверх с памятью `O(1)`: хранить весь массив не нужно, хватает двух последних значений.

```python run
def fib_optimized(n):
    if n < 2: return n
    a, b = 0, 1
    for _ in range(n - 1):
        a, b = b, a + b
    return b

fib_optimized(50)
```

### Лестница (Climbing Stairs)

За один шаг можно подняться на 1 или 2 ступеньки. Сколькими способами можно подняться на `n` ступенек?

По сути это Фибоначчи: `dp[n] = dp[n-1] + dp[n-2]`.

```python run
def climb_stairs(n):
    if n <= 2: return n
    a, b = 1, 2
    for _ in range(n - 2):
        a, b = b, a + b
    return b

climb_stairs(5)   # 8
```

### Размен монет (Coin Change)

Даны номиналы монет и сумма `amount`. Нужно найти минимальное число монет, которыми её можно набрать.

Состояние: `dp[i]` — минимальное число монет для суммы `i`.

```python run
def coin_change(coins, amount):
    INF = amount + 1
    dp = [INF] * (amount + 1)
    dp[0] = 0
    for i in range(1, amount + 1):
        for c in coins:
            if c <= i:
                dp[i] = min(dp[i], dp[i - c] + 1)
    return dp[amount] if dp[amount] != INF else -1

coin_change([1, 2, 5], 11)   # 3 (5 + 5 + 1)
```

### Рюкзак 0/1 (0/1 Knapsack)

Есть `n` предметов с весами `w[i]` и стоимостями `v[i]`, рюкзак вмещает вес `W`. Каждый предмет можно взять **0 или 1 раз**. Нужно набрать максимальную суммарную стоимость.

Состояние: `dp[i][w]` — максимальная стоимость, если использовать первые `i` предметов и рюкзак вместимостью `w`.

```python run
def knapsack(weights, values, W):
    n = len(weights)
    dp = [[0] * (W + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for w in range(W + 1):
            dp[i][w] = dp[i - 1][w]                    # не берём i-й предмет
            if weights[i - 1] <= w:
                dp[i][w] = max(
                    dp[i][w],
                    dp[i - 1][w - weights[i - 1]] + values[i - 1]
                )
    return dp[n][W]

weights = [1, 3, 4, 5]
values  = [1, 4, 5, 7]
knapsack(weights, values, 7)   # 9 (2-й и 3-й предметы: вес 3 + 4 = 7, стоимость 4 + 5 = 9)
```

### Наибольшая общая подпоследовательность (LCS)

**Наибольшая общая подпоследовательность** (Longest Common Subsequence, LCS): найти её длину для двух строк.

Состояние: `dp[i][j]` — длина LCS для первых `i` символов `s1` и первых `j` символов `s2`.

```python run
def lcs(s1, s2):
    n, m = len(s1), len(s2)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if s1[i - 1] == s2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[n][m]

lcs('ABCBDAB', 'BDCAB')   # 4 (например, 'BCAB')
```

### Наибольшая возрастающая подпоследовательность (LIS)

**Наибольшая возрастающая подпоследовательность** (Longest Increasing Subsequence, LIS): найти длину самой длинной строго возрастающей подпоследовательности.

Простая версия работает за `O(n²)`:

```python run
def lis(arr):
    n = len(arr)
    if n == 0: return 0
    dp = [1] * n
    for i in range(1, n):
        for j in range(i):
            if arr[j] < arr[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

lis([10, 9, 2, 5, 3, 7, 101, 18])   # 4 ([2, 3, 7, 101])
```

### Как распознать задачу на DP

Подсказки в формулировке:

- «найти **минимальное** или **максимальное** …»;
- «сколько **способов** …»;
- «есть ли способ …» (часто решается через DP или BFS);
- последовательность шагов, на каждом из которых есть выбор.

Шаги решения:

1. Определить **состояние** (`dp[i]`, `dp[i][j]`).
2. Найти **переход** — рекуррентное соотношение.
3. Задать базовые случаи.
4. Выбрать порядок заполнения.
5. Подумать, можно ли сэкономить память: часто хватает одной-двух предыдущих строк.

## Частые ошибки

- Таблица создана как `dp = [[0] * m] * n` → все строки — один и тот же список, запись в `dp[1][w]` меняет и `dp[0][w]`, ответ неверный → `[[0] * m for _ in range(n)]`.
- `lru_cache` на функции, которая принимает `list` → `TypeError: unhashable type: 'list'` → передавать индексы или кортеж, а сам массив держать снаружи.
- Подход сверху вниз при `n` в десятки тысяч → `RecursionError: maximum recursion depth exceeded` → переписать снизу вверх, таблица заполняется циклом.
- Не проверены базовые случаи → `IndexError` на `dp[1]` при `n = 0` или неверный ответ для `n = 1` → явно обработать `n < 2` до создания таблицы.
- Перепутан порядок циклов в задачах «сколько способов набрать сумму» → монеты во внутреннем цикле считают `1 + 2` и `2 + 1` разными способами → если порядок монет не важен, внешний цикл по монетам, внутренний по суммам.

## Когда не использовать

Если подзадачи не повторяются, кеш ничего не ускорит: обычная рекурсия или «разделяй и властвуй» (сортировка слиянием, бинарный поиск) работают без таблицы. Если на каждом шаге можно выбрать локально лучший вариант и это доказуемо даёт оптимум, достаточно жадного алгоритма: размен монетами 1, 5, 10, 50 или выбор непересекающихся встреч.

Когда таблица состояний слишком велика (например, рюкзак с вместимостью порядка миллиарда), DP в лоб не помещается в память: нужно переформулировать состояние, сжать его до одной строки или искать другой подход. А если `n` маленькое, прямой перебор короче и понятнее.
