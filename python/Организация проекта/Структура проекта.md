**Структура проекта Python** — это организация файлов и папок в вашем проекте, которая определяет, насколько удобно проект поддерживать, развивать, тестировать и масштабировать. Правильная структура облегчает командную работу, внедрение автоматизации (тесты, CI/CD), публикацию и совместимость с инструментами Python-экосистемы.
## Ключевые принципы организации структуры проекта

- **Изоляция исходного кода:** основной код отделён от тестов, конфигураций, данных и вспомогательных скриптов.
- **Единый стиль именования:** имена папок и файлов понятны и не конфликтуют с внутренними/внешними модулями.
- **Минимизация корня проекта:** в корне только файлы верхнего уровня и базовые папки.
- **Простота навигации:** легко понять, где искать код, тесты, настройки и документацию.
## Классическая структура

Сегодня всё чаще используют структуру с отдельной папкой `src/` для исходного кода:

```
project_name/
│
├── src/
│   ├── __init__.py
│   ├── modules/
│   ├── ...                # Другие модули, подпапки
│   └── main.py            # Точка входа в приложение
│
├── tests/                 # Все тесты проекта
│   └── ...
│
├── scripts/               # Вспомогательные скрипты (опционально)
│   └── ...
│
├── requirements.txt       # Зависимости pip
├── pyproject.toml         # Общая конфигурация (Poetry, build, black и др.)
├── setup.py / setup.cfg   # Конфигурация для публикации (если библиотека)
├── README.md              # Описание проекта
├── LICENSE                # Лицензия
├── .gitignore             # Игнорируемые git-файлы и папки
└── .env                   # Переменные окружения (обычно не коммитится)
```

## Основные элементы структуры

- **src/**— основной пакет проекта, только здесь размещается бизнес-логика и основной функционал.
- **tests/** — тесты, полностью изолированные от кода, чтобы не было пересечений при импортах.
- **scripts/** — скрипты для миграций, CLI и т.д.
- **README.md** — инструкция по использованию, установке и развитию проекта.
- **pyproject.toml, requirements.txt, setup.py** — инструменты и файлы для управления зависимостями, сборкой и публикацией.
- **.gitignore, LICENSE, .env** — служебные файлы.

## Советы и best practices

- Не кладите исходный код прямо в корень проекта — используйте отдельную папку (`src/`).
- Разделяйте код, тесты, конфиги, документацию и данные по разным папкам.
- Для библиотек — всегда размещайте пакет в отдельной директории.
- Старайтесь, чтобы структура была одинакова для всех ваших проектов — это ускоряет работу в команде.
- Используйте современные стандарты (`pyproject.toml`), линтеры, документацию и CI/CD.
