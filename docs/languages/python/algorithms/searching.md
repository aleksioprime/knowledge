# Поиск в массиве

Найти элемент в массиве — самая частая задача на собеседовании и одна из самых частых в рабочем коде: по идентификатору пользователя, по дате, по ближайшему значению. Два алгоритма нужно знать наизусть: линейный поиск, который работает везде, и бинарный, который на отсортированных данных ищет за `O(log n)`.

## Минимальный пример

На отсортированном списке идентификаторов оба способа дают один ответ, а `bisect` из стандартной библиотеки ещё и подсказывает, куда вставить новое значение.

```python run
import bisect

user_ids = [3, 8, 15, 21, 42, 57, 90]   # отсортировано по возрастанию

def linear_search(items, target):
    for i, item in enumerate(items):
        if item == target:
            return i
    return -1

def binary_search(items, target):
    left, right = 0, len(items) - 1
    while left <= right:
        mid = (left + right) // 2
        if items[mid] == target:
            return mid
        if items[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

print(linear_search(user_ids, 42))            # 4
print(binary_search(user_ids, 42))            # 4
print(bisect.bisect_left(user_ids, 42))       # 4
print(bisect.bisect_left(user_ids, 50))       # 5 — куда вставить, чтобы сохранить порядок
```

## Как это работает

### Линейный поиск — O(n)

Перебираем все элементы подряд. Работает на любых данных.

```python run
def linear_search(arr, target):
    for i, x in enumerate(arr):
        if x == target:
            return i
    return -1

linear_search([4, 7, 1, 9, 3], 9)   # 3
```

### Бинарный поиск — O(log n)

**Бинарный поиск** (binary search) работает **только на отсортированном массиве**. Смотрим на середину, сравниваем с искомым значением и продолжаем в нужной половине. На каждом шаге отбрасываем половину элементов.

```python run
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1

binary_search([1, 3, 4, 7, 9, 11, 15], 9)   # 4
```

### Рекурсивный бинарный поиск

```python run
def binary_search_rec(arr, target, left=0, right=None):
    if right is None:
        right = len(arr) - 1
    if left > right:
        return -1
    mid = (left + right) // 2
    if arr[mid] == target:
        return mid
    if arr[mid] < target:
        return binary_search_rec(arr, target, mid + 1, right)
    return binary_search_rec(arr, target, left, mid - 1)

binary_search_rec([1, 3, 4, 7, 9, 11, 15], 11)
```

### Модуль bisect

В рабочем коде удобнее не писать бинарный поиск руками, а взять стандартный модуль `bisect`. Он возвращает индекс, куда нужно вставить значение, чтобы сохранить сортировку.

```python run
import bisect

arr = [1, 3, 4, 7, 9, 11, 15]

print(bisect.bisect_left(arr, 7))   # 3 (позиция самого 7)
print(bisect.bisect_right(arr, 7))  # 4 (позиция сразу за 7)

bisect.insort(arr, 8)   # вставка с сохранением порядка
print(arr)   # [1, 3, 4, 7, 8, 9, 11, 15]
```

### Когда что использовать

- **Неотсортированный массив** — линейный поиск. Если искать придётся часто, массив лучше один раз отсортировать.
- **Отсортированный массив** — бинарный поиск (`bisect`).
- **Поиск по ключу** — хеш-таблица `dict`, `O(1)`.
- **Поиск ближайшего значения** — бинарный поиск: `bisect` подскажет позицию.

## Частые ошибки

- Бинарный поиск на неотсортированном массиве → элемент есть, а функция возвращает `-1`, причём только на некоторых данных → сначала `sorted()`, либо использовать линейный поиск или `dict`.
- Условие цикла `left < right` без знака равенства → последний оставшийся элемент не проверяется, и поиск «не видит» значение на краю → писать `while left <= right`.
- Границы сужаются через `left = mid` или `right = mid` → на двух элементах `mid` не сдвигается, и цикл становится бесконечным → сужать только через `mid + 1` и `mid - 1`.
- `bisect_left` и `bisect_right` перепутаны → при дубликатах позиция смещается на число повторов, а проверка «есть ли элемент» ломается → для поиска элемента взять `bisect_left` и проверить `i < len(arr) and arr[i] == target`; для вставки после равных — `bisect_right`.
- Перенос `mid = (left + right) // 2` в другие языки без изменений → в C или Java `left + right` переполняется на больших индексах → писать `mid = left + (right - left) / 2`; в Python переполнения целых нет, и это безопасно.

## Когда не использовать

Бинарный поиск лишний, если массив маленький или ищут один раз: сортировка стоит `O(n log n)`, а линейный проход — всего `O(n)`. Он не подходит и для данных, которые часто меняются: каждая вставка в отсортированный список — это `O(n)` сдвиг элементов.

Если искать нужно по ключу, а не по позиции, берите `dict` или `set`: они находят значение за `O(1)` и не требуют сортировки. Для диапазонных запросов на часто изменяемых данных лучше подходят сбалансированные деревья или индексы базы данных.
