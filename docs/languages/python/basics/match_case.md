# Сопоставление с образцом (match-case)

Когда значение нужно разобрать по форме — команда из нескольких слов, кортеж с координатами, словарь с полем `type`, — цепочка `if`/`elif` с проверками длины, индексов и ключей быстро становится нечитаемой. Оператор `match` описывает ожидаемую форму прямо в ветке и сам извлекает из значения нужные части.

## Минимальный пример

```python run
def handle(command):
    match command.split():
        case ["add", *words]:
            return f"Добавлена задача: {' '.join(words)}"
        case ["done", number] if number.isdigit():
            return f"Задача {number} выполнена"
        case ["list"] | ["ls"]:
            return "Список задач"
        case _:
            return "Неизвестная команда"


print(handle("add Купить хлеб"))  # Добавлена задача: Купить хлеб
print(handle("done 2"))           # Задача 2 выполнена
print(handle("ls"))               # Список задач
print(handle("done two"))         # Неизвестная команда
```

## Как это работает

Оператор `match` сравнивает значение с несколькими образцами (patterns) и выполняет ветку первого совпадения. Это замена длинных цепочек `if`/`elif` при разборе значений. Образец — это не выражение, а описание формы: литерал `1`, последовательность `[x, y]`, словарь `{"type": t}`, класс `Point(x=0)`. Имена в образце не сравниваются, а связываются с частями значения (capture), а `_` принимает что угодно.

Несколько образцов объединяют через `|`, после образца можно добавить условие-охрану (guard) `if ...`, а `*words` собирает остаток последовательности. Ветки проверяются сверху вниз, поэтому общий случай `case _` ставят последним.

```python run
def process_value(value):
    match value:
        case 1:
            print("Value is 1")
        case 2 | 3 | 4:
            print("Value is 2 or 3 or 4")
        case _:
            print("Value is not 1 or 2 or 3 or 4")

process_value(1)  # Value is 1
process_value(3)  # Value is 2 or 3 or 4
```

## Частые ошибки

- Сравнение с константой через имя: `case MAX_SIZE:` → ветка срабатывает всегда, потому что голое имя — это захват, а не сравнение; имя `MAX_SIZE` перезаписывается → используйте точечное имя (`case Config.MAX_SIZE:`) или литерал.
- `case _:` не последней веткой → интерпретатор выдаёт `SyntaxError`: ветки после неё недостижимы → ставьте `_` в конец.
- Ожидание, что `match` сравнивает «как `==`» → образец `[1, 2]` совпадает и с кортежем `(1, 2)`, а строка `"ab"` не раскладывается на `["a", "b"]` → помните, что строки и байты не считаются последовательностями в образцах, а списки и кортежи взаимозаменяемы.
- Образец класса без `__match_args__`: `case Point(0, 0):` → `TypeError` при сопоставлении, потому что позиционные поля неизвестны → используйте именованные поля `Point(x=0, y=0)` или `@dataclass`, который задаёт `__match_args__` сам.
- Образец словаря `{"type": "order"}` считается «точным» → на самом деле лишние ключи разрешены, и ветка ловит больше, чем ожидалось → добавьте проверку в охране `if` или используйте `**rest` и проверьте его пустоту.

## Когда не использовать

Для простого сравнения одного значения с двумя-тремя вариантами `match` лишний: `if status == "done"` короче и понятнее. Если ветки отличаются только значением, а не формой, возьмите словарь `handlers = {"add": add_task, "done": finish_task}` и вызывайте `handlers[command]()`. `match` окупается, когда нужно разобрать структуру: вложенные списки, словари с разным набором ключей, объекты разных классов.

Помните и об ограничении: `match` появился в Python 3.10, поэтому в коде, который должен работать на старых версиях, остаются `if`/`elif`.
