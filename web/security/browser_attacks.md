# Атаки на браузер и пользователя

## XSS

Cross-Site Scripting возникает, когда недоверенные данные попадают в HTML, JavaScript, CSS или URL без безопасного кодирования. Скрипт выполняется с правами сайта и может читать доступные данные или выполнять действия от имени пользователя.

Защита:

- использовать автоэкранирование шаблонов и не вставлять сырой HTML;
- очищать HTML по allowlist, если разметка действительно нужна;
- применять CSP как дополнительный слой;
- помечать сессионные cookies `HttpOnly`;
- не считать фильтрацию отдельных строк достаточной защитой.

См. также [безопасное использование `v-html`](../../vuejs/docs/v_html.md).

## CSRF

Cross-Site Request Forgery заставляет браузер авторизованного пользователя отправить нежелательный запрос. Риск возникает, когда браузер автоматически прикладывает cookies или другие учётные данные.

Защита:

- CSRF-токены для изменяющих состояние запросов;
- `SameSite=Lax` или `Strict`, когда это совместимо со сценарием;
- проверка `Origin`, а при необходимости `Referer`;
- запрет изменяющих операций через `GET`;
- повторная аутентификация для критичных действий.

## CORS

CORS определяет, каким origin браузер разрешает читать ответ. Это не механизм аутентификации и не защита серверного API от запросов вне браузера. Нельзя сочетать произвольный `Access-Control-Allow-Origin` с передачей credentials.

## Clickjacking

Сайт помещают в невидимый или замаскированный `iframe`, побуждая пользователя нажать на элементы интерфейса. Защита: CSP `frame-ancestors` и, для старых клиентов, `X-Frame-Options`.
