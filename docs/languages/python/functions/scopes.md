# Области видимости и замыкания

Переменная присвоена внутри функции, а снаружи её не видно; счётчик во вложенной функции не увеличивается; имя `list` вдруг перестало быть встроенной функцией. Все эти ситуации объясняет одно правило — как Python ищет имена. Здесь правило LEGB, операторы `global` и `nonlocal` и замыкания — функции, которые запоминают переменные внешней функции. На замыканиях построены декораторы.

## Минимальный пример

```python run
def make_counter(start=0):
    count = start

    def next_id():
        nonlocal count
        count += 1
        return count

    return next_id

task_id = make_counter()
print(task_id())  # 1
print(task_id())  # 2

order_id = make_counter(100)
print(order_id())  # 101
print(task_id())   # 3 — у каждого замыкания свой count
```

## Как это работает

### Области видимости

#### Правило LEGB

Когда функция обращается к имени, Python ищет его в четырёх областях видимости по порядку:

- **Local** — локальная область текущей функции;
- **Enclosing** — области внешних (объемлющих) функций;
- **Global** — глобальная область модуля;
- **Built-in** — встроенные имена Python (`str`, `len`, `print`).

Используется первое найденное значение. В примере имя `str` по очереди перекрывается на каждом уровне:

```python run
print(str)  # <class 'str'>

str = "global"

def outer():
    str = "enclosing"

    def inner():
        str = "local"
        print(str)  # local

    inner()
    print(str)  # enclosing

outer()
print(str)  # global

# Возвращаем встроенный str, чтобы не сломать остальной код
import builtins
str = builtins.str
```

#### Операторы global и nonlocal

Присваивание внутри функции по умолчанию создаёт локальную переменную. Чтобы изменить переменную из другой области, её нужно объявить:

- `global` — переменная из глобальной области модуля;
- `nonlocal` — переменная из ближайшей внешней функции.

```python run
a = 0
b = 0

def outer():
    a = 1
    b = 1

    def inner():
        global a
        a = 2
        nonlocal b
        b = 2

    inner()
    # Локальная a в outer не изменилась, а b изменилась через nonlocal
    print(f"a = {a} b = {b}")  # a = 1 b = 2

outer()
# Глобальная a изменилась через global, а глобальная b осталась прежней
print(f"a = {a} b = {b}")  # a = 2 b = 0
```

### Замыкание

Замыкание (closure) — функция, которая запоминает переменные из внешней области видимости даже после того, как внешняя функция завершила работу.

Например, функция сложения с запомненным слагаемым:

```python run
def add_number(a):
    def add(b):
        return a + b

    return add

# add_number(5) вернула внутреннюю функцию add, которая помнит a = 5
add_five = add_number(5)
print(add_five(2))   # 7
print(add_five(10))  # 15
```

Замыкание может не только читать, но и изменять запомненную переменную — для этого нужен `nonlocal`. Так получается счётчик:

```python run
def make_counter():
    count = 0

    def inner():
        nonlocal count
        count += 1
        return count

    return inner

# make_counter() уже отработала, но inner() помнит переменную count
counter = make_counter()

print(counter())  # 1
print(counter())  # 2
print(counter())  # 3

# Кортеж ячеек (cell), в которых Python хранит захваченные переменные
print(counter.__closure__)
```

## Частые ошибки

- Переменную читают, а потом присваивают в той же функции (`count += 1` без `nonlocal`) → `UnboundLocalError: local variable referenced before assignment`, хотя снаружи переменная есть → объявить `nonlocal count` или `global count` в начале функции.
- Имя переменной совпадает со встроенным (`list = [...]`, `id = 5`) → дальше `list(...)` падает с `TypeError: 'list' object is not callable` → не перекрывать встроенные имена, переименовать переменную.
- Лямбды создают в цикле и ждут, что каждая запомнит своё `i` → все замыкания возвращают последнее значение, потому что захватывается переменная, а не её значение → зафиксировать значение через параметр по умолчанию: `lambda x, i=i: x + i`.
- `global` используют, чтобы функция «вернула» несколько значений или поменяла настройки → состояние модуля меняется из любого места, тесты зависят друг от друга → возвращать значения через `return`, а состояние хранить в объекте или передавать параметром.
- `nonlocal` объявлен для переменной, которой нет ни в одной внешней функции (например, только в модуле) → `SyntaxError: no binding for nonlocal 'x' found` → для переменной модуля нужен `global`.

## Когда не использовать

Замыкание хранит состояние неявно: его не видно снаружи, нельзя посмотреть или сбросить без лазанья в `__closure__`. Если состояние нужно читать, сохранять, передавать между частями программы или у него больше одного-двух полей, честнее завести класс: атрибуты видны, а методы можно называть по смыслу. Замыкание уместно там, где нужна одна функция с запомненным параметром — обработчик, ключ сортировки, обёртка в декораторе.

`global` в прикладном коде почти всегда сигнал, что функции не хватает параметра или возвращаемого значения. Исключение — константы и настройки, которые только читаются: для них объявление не нужно вовсе.
