# Массивы

Список задач нужно отфильтровать по статусу, собрать из него заголовки, посчитать сумму часов и отсортировать по сроку — и всё это без ручных циклов со счётчиками. Методы массива делают каждую такую операцию одной строкой, но у них есть ловушки: часть методов меняет исходный массив, `sort()` без comparator сортирует числа как строки, а `delete` оставляет «дырку». Здесь создание массивов, добавление и удаление элементов, перебор, поиск, сортировка и таблица, какие методы мутируют данные.

## Минимальный пример

```js
const tasks = [
  { title: 'Купить хлеб', done: true, hours: 1 },
  { title: 'Позвонить врачу', done: false, hours: 0.5 },
  { title: 'Сдать отчёт', done: false, hours: 4 },
]

const pending = tasks.filter((task) => !task.done)
const titles = pending.map((task) => task.title)
const totalHours = pending.reduce((sum, task) => sum + task.hours, 0)

console.log(titles) // [ 'Позвонить врачу', 'Сдать отчёт' ]
console.log(totalHours) // 4.5
console.log(tasks.find((task) => task.hours > 2)?.title) // Сдать отчёт
console.log(tasks.some((task) => task.done)) // true
console.log(tasks.length) // 3 — filter и map не изменили исходный массив
```

## Как это работает

### Основы массивов

#### `Array.isArray()`

Для проверки массива используйте `Array.isArray()`, а не `typeof` или `instanceof`: `Array.isArray()` корректно работает и с массивами из другого окна.

```js
Array.isArray([]) // true
Array.isArray(new Array()) // true
Array.isArray({ 0: 'a', length: 1 }) // false
Array.isArray('text') // false
```

Это статический метод конструктора `Array`, поэтому он вызывается как `Array.isArray(value)`, а не `value.isArray()`.

#### Создание массива

Чаще всего массив создают литералом `[]`. `Array.of()` удобен, когда значения уже передаются отдельными аргументами, а `Array.from()` преобразует iterable или массивоподобный объект в настоящий массив.

```js
const empty = []
const numbers = [1, 2, 3]
const fromValues = Array.of(1, 2, 3)
const fromString = Array.from('abc') // ['a', 'b', 'c']
const range = Array.from({ length: 3 }, (_, index) => index)
```

Конструктор с одним числом создаёт не элемент, а разреженный массив заданной длины:

```js
Array(3) // [empty × 3]
Array.of(3) // [3]
```

Обычно литерал `[]` проще и понятнее конструктора.

#### Что может храниться в массиве

Массив может одновременно хранить значения любых типов, включая другие массивы, объекты и функции:

```js
const mixed = [1, 'text', null, { id: 1 }, [2, 3], () => {}]
```

Технически это допустимо, но коллекции элементов одного назначения обычно проще обрабатывать.

#### `length`

`length` обычно равен индексу последнего элемента плюс один, а не количеству реально заполненных ячеек.

```js
const values = ['a', 'b', 'c']

values.length // 3
values[10] = 'x'
values.length // 11
```

Уменьшение `length` удаляет элементы с конца. Увеличение создаёт пустые ячейки — holes:

```js
values.length = 2 // ['a', 'b']
values.length = 5 // ['a', 'b', empty × 3]
```

Разреженные массивы ведут себя неодинаково в разных методах, поэтому их лучше не создавать намеренно.

#### Доступ и изменение элементов

Индексация начинается с нуля:

```js
const colors = ['red', 'green', 'blue']

colors[0] // 'red'

colors[1] = 'yellow'
colors[3] = 'black'
```

##### `at()`

Метод `at(index)` возвращает элемент по индексу или `undefined`, если такой позиции нет. Отрицательный индекс отсчитывается от конца:

```js
const colors = ['red', 'green', 'blue']

colors.at(0) // 'red'
colors.at(-1) // 'blue'
colors.at(-2) // 'green'
colors.at(10) // undefined
```

В отличие от `colors[-1]`, который ищет обычное свойство с ключом `'-1'`, `at(-1)` действительно получает последний элемент.

Современный `with(index, value)` возвращает изменённую копию:

```js
const updated = colors.with(1, 'white') // копия, где элемент [1] заменён на 'white'
```

#### Почему не следует использовать `delete`

`delete array[index]` удаляет свойство, но не сдвигает остальные элементы и не меняет `length`. В массиве остаётся пустая ячейка:

```js
const values = ['a', 'b', 'c']

delete values[1] // остальные элементы не сдвигаются, остаётся «дырка»

values // ['a', empty, 'c']
values.length // 3
```

Для удаления используйте мутирующий `splice()` или немутирующий `toSpliced()`.

### Добавление и удаление с краёв

#### `push()` и `pop()`

`push(...items)` добавляет элементы в конец и возвращает новую длину. `pop()` удаляет последний элемент и возвращает его либо `undefined` для пустого массива.

```js
const values = [1, 2]

values.push(3, 4) // 4; values = [1, 2, 3, 4]
values.pop() // 4; values = [1, 2, 3]
```

#### `unshift()` и `shift()`

`unshift(...items)` добавляет элементы в начало и возвращает новую длину. `shift()` удаляет первый элемент и возвращает его либо `undefined`.

```js
const values = [2, 3]

values.unshift(0, 1) // 4; values = [0, 1, 2, 3]
values.shift() // 0; values = [1, 2, 3]
```

`shift()` и `unshift()` обычно дороже операций с концом, потому что движку приходится переиндексировать элементы.

### Получение и замена части массива

#### `slice()`

`slice(start, end)` возвращает поверхностную копию диапазона, не включая `end`, и не изменяет исходный массив. Отрицательные индексы отсчитываются от конца.

```js
const values = ['a', 'b', 'c', 'd']

values.slice(1, 3) // ['b', 'c']
values.slice(-2) // ['c', 'd']
values.slice()     // копия всего массива
```

#### `splice()` и `toSpliced()`

`splice(start, deleteCount, ...items)` изменяет массив и возвращает массив удалённых элементов:

```js
const values = ['a', 'b', 'c', 'd']
const removed = values.splice(1, 2, 'x', 'y') // изменяет исходный массив

removed // ['b', 'c']
values // ['a', 'x', 'y', 'd']
```

`toSpliced()` принимает те же основные аргументы, но возвращает новый массив и не изменяет исходный:

```js
const values = ['a', 'b', 'c']
const updated = values.toSpliced(1, 1, 'x') // исходный массив не меняется

values // ['a', 'b', 'c']
updated // ['a', 'x', 'c']
```

#### `concat()`

`concat(...values)` возвращает новый массив, объединяя исходный массив с переданными значениями и массивами. Исходные массивы не изменяются.

```js
const first = [1, 2]
const second = [3, 4]

first.concat(second, 5) // [1, 2, 3, 4, 5]
```

Копия поверхностная: вложенные объекты остаются общими.

### Перебор и преобразование

Callback большинства методов получает `(element, index, array)`.

#### `forEach()`

Сигнатура: `array.forEach(callback, thisArg?)`.

Вызывает callback для каждого элемента и всегда возвращает `undefined`. Callback получает `(element, index, array)`:

```js
users.forEach((user, index) => {
  console.log(index, user.name)
})
```

`forEach()` нельзя остановить через `break` или `return`, и он не ожидает async-callback. Для таких случаев используйте `for...of`.

#### `map()`

Сигнатура: `array.map(callback, thisArg?)`.

Вызывает callback `(element, index, array)` и возвращает новый массив результатов такой же длины. Исходный массив сам метод не изменяет.

```js
const names = users.map((user) => user.name)
```

#### `filter()`

Сигнатура: `array.filter(callback, thisArg?)`.

Возвращает новый массив только из тех элементов, для которых callback `(element, index, array)` вернул truthy-значение. Длина результата может отличаться от исходной.

```js
const activeUsers = users.filter((user) => user.active)
```

#### `reduce()`

Сигнатура: `array.reduce(callback, initialValue?)`.

Сворачивает массив в одно итоговое значение и возвращает его. Сам метод исходный массив не изменяет. Callback получает `(accumulator, currentValue, currentIndex, array)` и должен вернуть аккумулятор для следующей итерации:

```js
const total = prices.reduce((sum, price) => sum + price, 0)
```

Начальное значение `0` передано вторым аргументом. Его лучше указывать явно: без него пустой массив вызовет `TypeError`, а первым аккумулятором станет первый элемент.

Результатом может быть не только число:

```js
const usersById = users.reduce((result, user) => {
  result[user.id] = user
  return result
}, {})
```

`reduceRight()` работает аналогично, но проходит массив справа налево.

#### `flat()` и `flatMap()`

`flat(depth = 1)` возвращает новый массив с уменьшенной вложенностью. Исходный массив не изменяется; для раскрытия всех уровней можно передать `Infinity`.

```js
[[1, 2], [3]].flat() // [1, 2, 3]
[[1, [2]]].flat(Infinity) // [1, 2]
```

`flatMap(callback, thisArg?)` вызывает callback `(element, index, array)`, затем раскрывает результат ровно на один уровень. Он возвращает новый массив и эквивалентен `map(...).flat(1)`:

```js
users.flatMap((user) => user.roles)
```

`flatMap()` удобен, когда из одного входного элемента нужно получить ноль, один или несколько элементов результата.

#### Что такое `thisArg`

Многие перебирающие методы принимают необязательный второй аргумент `thisArg`. Он становится значением `this` внутри обычной callback-функции:

```js
const limits = { minimum: 18 }

const adults = users.filter(function (user) {
  return user.age >= this.minimum
}, limits)
```

`thisArg` поддерживают, в частности, `forEach`, `map`, `filter`, `find`, `findIndex`, `findLast`, `findLastIndex`, `some`, `every` и `flatMap`.

Стрелочная функция игнорирует `thisArg`, потому что берёт `this` из внешней области:

```js
users.filter((user) => user.age >= this.minimum, limits) // limits не станет this
```

В современном коде замыкание обычно читается понятнее, чем `thisArg`:

```js
users.filter((user) => user.age >= limits.minimum)
```

У `reduce()` и `sort()` параметра `thisArg` нет.

### Поиск и проверки

Метод выбирают по тому, какой ответ нужен: наличие конкретного значения, его индекс, первый элемент по условию или логический результат проверки нескольких элементов.

#### Массивный `indexOf()`

Сигнатура: `array.indexOf(searchElement, fromIndex = 0)`.

Возвращает индекс первого совпадения или `-1`. Сравнивает по правилам строгого равенства `===`, поэтому не находит `NaN`. Отрицательный `fromIndex` отсчитывается от конца.

#### Массивный `includes()`

Сигнатура: `array.includes(searchElement, fromIndex = 0)`.

Возвращает boolean. В отличие от `indexOf()`, использует сравнение SameValueZero и умеет находить `NaN`.

```js
[NaN].indexOf(NaN) // -1
[NaN].includes(NaN) // true
```

#### `find()`

Сигнатура: `array.find(callback, thisArg?)`.

Возвращает первый элемент, для которого callback `(element, index, array)` дал truthy-значение, либо `undefined`. Если в массиве действительно может находиться `undefined`, по результату нельзя отличить найденный элемент от отсутствия совпадения.

#### `findIndex()`

Сигнатура: `array.findIndex(callback, thisArg?)`.

Работает как `find()`, но возвращает индекс найденного элемента или `-1`. `findLast()` и `findLastIndex()` выполняют такой же поиск с конца.

#### `some()` и `every()`

`some(callback, thisArg?)` возвращает `true`, если callback дал truthy хотя бы для одного элемента. `every(callback, thisArg?)` возвращает `true`, только если условие выполнилось для всех элементов.

Пустой массив даёт `false` для `some()` и `true` для `every()`.

### Сортировка и изменение порядка

Сигнатуры:

```js
array.sort(compareFn?)
array.toSorted(compareFn?) // отсортированная копия, исходный массив не меняется
```

`sort()` изменяет исходный массив и возвращает ссылку на этот же массив. Без callback он сравнивает строковые представления элементов:

```js
[10, 2, 1].sort() // [1, 10, 2]
```

Для чисел нужен comparator. Отрицательный результат ставит `a` раньше `b`, положительный — позже, `0` сохраняет их относительный порядок:

```js
numbers.sort((a, b) => a - b) // изменяет numbers
```

`toSorted()` принимает такой же необязательный comparator, но возвращает отсортированную копию и не изменяет исходный массив:

```js
const sorted = numbers.toSorted((a, b) => a - b) // отсортированная копия, исходный массив не меняется
```

Сигнатуры: `array.reverse()` и `array.toReversed()`.

`reverse()` меняет порядок элементов на обратный, изменяет исходный массив и возвращает ссылку на него. `toReversed()` возвращает перевёрнутую копию.

```js
const values = [1, 2, 3]

values.reverse() // [3, 2, 1]; изменён сам values
values.toReversed() // [1, 2, 3]; новый массив
```

#### `fill()` и `copyWithin()`

Сигнатура: `array.fill(value, start = 0, end = array.length)`.

Метод заполняет диапазон от `start` до `end`, не включая `end`, и возвращает тот же изменённый массив. Отрицательные границы отсчитываются от конца:

```js
const values = [1, 2, 3, 4]

values.fill(0, 1, 3) // [1, 0, 0, 4]
```

Если значением является объект, во все позиции записывается одна и та же ссылка.

`copyWithin(target, start, end)` копирует часть массива в другую позицию внутри него, не меняя `length`, и также возвращает исходный изменённый массив:

```js
const values = [1, 2, 3, 4, 5]

values.copyWithin(0, 3) // [4, 5, 3, 4, 5]
```

### Преобразование в строку

`toString()` не принимает аргументов и соединяет элементы запятыми.

Сигнатура `join(separator = ',')`. Метод возвращает строку, не изменяя массив. Значения `null`, `undefined` и пустые ячейки превращаются в пустые строки:

```js
[1, 2, 3].toString() // '1,2,3'
[1, 2, 3].join(' — ') // '1 — 2 — 3'
[1, null, undefined].join('|') // '1||'
[].toString() // ''
```

Объекты внутри массива преобразуются своими методами преобразования в строку, поэтому результат может быть `'[object Object]'`.

### Мутирующие и немутирующие методы

| Не изменяют исходный массив | Изменяют исходный массив |
|---|---|
| `map`, `filter`, `flatMap`, `slice`, `concat` | `push`, `pop`, `shift`, `unshift` |
| `find`, `some`, `every`, `includes`, `join` | `splice`, `sort`, `reverse` |
| `toSorted`, `toReversed`, `toSpliced`, `with` | `fill`, `copyWithin` |

Даже немутирующий метод обычно создаёт только поверхностную копию: объекты внутри нового и старого массива остаются теми же объектами.

## Частые ошибки

- Числа сортируются через `sort()` без comparator → `[10, 2, 1]` превращается в `[1, 10, 2]`, потому что элементы сравниваются как строки → передавать `(a, b) => a - b`.
- Массив из состояния или аргумента «отсортирован на месте» через `sort()` или `reverse()` → исходные данные изменились у всех, кто держит ссылку → использовать `toSorted()`, `toReversed()`, `toSpliced()` или сначала сделать копию `slice()`.
- `reduce()` вызван без начального значения → на пустом массиве `TypeError`, а первым аккумулятором становится первый элемент, что ломает подсчёт объектов → всегда передавать второй аргумент (`0`, `{}`, `[]`).
- Элемент удалён через `delete array[index]` → `length` не меняется, в массиве остаётся пустая ячейка, перебор даёт `undefined` → удалять через `splice()` или `toSpliced()`.
- Поиск `NaN` или проверка наличия через `indexOf() !== -1` → `indexOf()` не находит `NaN`, а условие с `-1` легко написать с ошибкой → использовать `includes()` для проверки наличия и `find()`/`findIndex()` для условия.

## Когда не использовать

Массив не подходит, когда нужны уникальные значения или быстрый поиск по ключу: проверка `includes()` на большом массиве линейна, а объекты в нём сравниваются по ссылке. Для уникальности берите `Set`, для пар ключ–значение с любыми ключами — `Map` из заметки о [коллекциях](collections.md).

Цепочка `map().filter().reduce()` хороша для преобразований, но если внутри нужен `break`, последовательный `await` или индекс соседнего элемента, честный `for...of` читается проще, чем ухищрения с `some()` или `reduce()`. А `forEach()` ради одного вызова на элемент уступает `for...of`, который умеет прерываться и ждать.
