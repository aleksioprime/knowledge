# JavaScript в браузере

После перезагрузки страницы выбранная тема и фильтры списка задач сбрасываются, уведомление нужно скрыть через три секунды, а анимацию — рисовать плавно, не дёргая страницу. Сам язык JavaScript этого не умеет: хранение данных между перезагрузками, таймеры и синхронизацию с отрисовкой предоставляет браузер. Здесь собраны API, которые относятся именно к хранению данных и планированию работы.

## Минимальный пример

```js
const settings = { theme: 'dark', showDone: false }

localStorage.setItem('settings', JSON.stringify(settings))

const saved = JSON.parse(localStorage.getItem('settings'))
console.log(saved.theme) // 'dark'

const timeoutId = setTimeout(() => {
  console.log('Уведомление скрыто') // появится не раньше чем через 3 секунды
}, 3000)

clearTimeout(timeoutId) // отмена: сообщение не выведется
```

Хранилище принимает только строки, поэтому объект превращают в JSON и обратно. `setTimeout()` не останавливает программу, а планирует вызов и сразу возвращает идентификатор, по которому вызов можно отменить.

## Как это работает

### Хранилища

`localStorage` и `sessionStorage` хранят пары «ключ — значение». Оба API принимают только строки, поэтому объект перед записью нужно сериализовать, а после чтения — разобрать.

- `localStorage` сохраняет данные после закрытия вкладки и браузера;
- `sessionStorage` хранит данные только в рамках текущей вкладки до её закрытия.

```js
const settings = { theme: 'dark', pageSize: 20 }
const json = JSON.stringify(settings)

localStorage.setItem('settings', json)

const savedJson = localStorage.getItem('settings')
const savedSettings = savedJson === null ? null : JSON.parse(savedJson)

localStorage.removeItem('settings')
localStorage.clear()
```

Хранилища работают синхронно: во время чтения или записи основной поток ждёт завершения операции. Поэтому туда не следует помещать большие объёмы данных. Для сложных структур и большого количества записей используют асинхронную базу данных IndexedDB.

Не храните в браузерных хранилищах пароли и другие секреты. JavaScript-код страницы может прочитать эти значения, а значит, при XSS-уязвимости их сможет получить злоумышленник.

### Таймеры

Таймер не останавливает выполнение программы. Браузер запоминает callback и сможет вызвать его позже, когда истечёт задержка и основной поток освободится. Поэтому указанное время — минимальная задержка, а не гарантия точного момента запуска.

#### `setTimeout()`

`setTimeout()` планирует один вызов функции. Метод сразу возвращает идентификатор таймера, по которому вызов можно отменить.

```js
const timeoutId = setTimeout(() => { // не раньше чем через секунду
  console.log('Прошла как минимум секунда')
}, 1000)

clearTimeout(timeoutId) // отменит, если callback ещё не вызван
```

Дополнительные аргументы после задержки браузер передаёт callback, но замыкание обычно читается понятнее:

```js
const userName = 'Анна'

setTimeout(() => {
  console.log(`Привет, ${userName}`)
}, 500)
```

#### `setInterval()`

`setInterval()` пытается запускать callback через равные промежутки времени, пока интервал не будет отменён. Если сама операция выполняется долго, новые вызовы могут идти не с тем ритмом, который ожидался.

```js
let ticks = 0

const intervalId = setInterval(() => {
  ticks += 1
  console.log(ticks)

  if (ticks === 3) {
    clearInterval(intervalId)
  }
}, 1000)
```

Когда следующую операцию нужно запускать только после завершения предыдущей, удобнее рекурсивный `setTimeout()`. Такой подход не создаёт наложения медленных вызовов:

```js
async function poll() {
  await loadUpdates()
  setTimeout(poll, 5000) // следующий шаг — только после завершения загрузки
}

poll()
```

### Планирование работы

Для визуальных изменений лучше подходит `requestAnimationFrame()`. Браузер вызывает переданный callback перед ближайшей отрисовкой и передаёт ему время с момента запуска страницы.

```js
const animationId = requestAnimationFrame((time) => {
  box.style.transform = `translateX(${time / 20}px)`
})

cancelAnimationFrame(animationId) // отменит, если кадр ещё не начался
```

`requestIdleCallback()` позволяет выполнять необязательную фоновую работу в свободное время браузера, но поддерживается не во всех средах. Он не подходит для действий, которые должны произойти к конкретному сроку.

Какой инструмент выбирать:

- `setTimeout()` — один отложенный запуск;
- рекурсивный `setTimeout()` — повторение с паузой после завершения каждой операции;
- `setInterval()` — простое повторение, если длительность callback мала и стабильна;
- `requestAnimationFrame()` — обновление анимации перед отрисовкой кадра.

## Частые ошибки

- В `localStorage.setItem()` передан объект без `JSON.stringify()` → в хранилище лежит строка `[object Object]`, а при чтении `JSON.parse()` падает → сериализовать перед записью и разбирать после чтения.
- В `setTimeout` передан вызов, а не функция (`setTimeout(save(), 1000)`) → `save()` выполняется сразу, а через секунду вызывается `undefined` → передавать `save` или `() => save()`.
- `setInterval()` создан при открытии окна и не отменён при его закрытии → callback продолжает работать на уже удалённых элементах, память и запросы утекают → сохранять идентификатор и вызывать `clearInterval()` при уничтожении интерфейса.
- Анимация обновляется через `setInterval(..., 16)` → кадры не совпадают с отрисовкой, движение дёргается, а во фоновой вкладке таймер продолжает работать → использовать `requestAnimationFrame()`.
- В `localStorage` сохранён токен или пароль → при XSS скрипт злоумышленника читает их одной строкой → секреты держать в cookie с `HttpOnly` или в памяти страницы.

## Когда не использовать

`localStorage` не подходит для больших или часто меняющихся данных: он синхронный, ограничен несколькими мегабайтами и хранит только строки. Для кэша ответов, списков на тысячи записей и структурированных данных берите IndexedDB. Для данных, которые нужны и серверу, храните их на сервере, а не в браузере.

`setInterval()` и рекурсивный `setTimeout()` для опроса сервера оправданы при редких обновлениях. Если данные меняются часто и их должен присылать сервер, лучше [WebSocket](websocket.md) или Server-Sent Events. Для плавных визуальных переходов вместо таймеров чаще достаточно CSS-анимаций и `transition`: браузер выполняет их без участия JavaScript.
