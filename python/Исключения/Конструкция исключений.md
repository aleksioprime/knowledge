**Исключения** — это механизм в Python для обработки ошибок и неожиданных ситуаций, которые могут возникнуть во время выполнения программы. Вместо того чтобы программа завершилась аварийно, можно “поймать” исключение и обработать его специальным образом.
### Зачем нужна обработка исключений?

- Позволяет избежать аварийного завершения программы при ошибках.
- Даёт возможность реагировать на ошибки: например, повторить попытку, вывести сообщение, записать ошибку в лог и т.д.
- Помогает писать более надёжный, “живучий” код.
### Базовый синтаксис

```python
try:
    # Код, который может вызвать ошибку
    result = 10 / 0
except ZeroDivisionError:
    # Этот блок выполняется, если возникла ошибка деления на ноль
    print("Ошибка: деление на ноль!")
```
### Общая структура блока обработки исключений

```python
try:
    # опасный код
except SomeException:
    # обработка конкретного исключения
except AnotherException as e:
    # обработка с получением объекта исключения
else:
    # если не было исключения
finally:
    # выполняется всегда (например, для очистки ресурсов)
```

- **try** — блок, где может возникнуть ошибка.
- **except** — обработка определённого типа ошибки.
- **else** — выполняется, если не возникло исключений.
- **finally** — выполняется всегда, независимо от ошибок (например, для закрытия файла или соединения).
### Пример с несколькими except

```python
try:
    number = int(input("Введите число: "))
    result = 10 / number
except ValueError:
    print("Ошибка: введено не число!")
except ZeroDivisionError:
    print("Ошибка: деление на ноль!")
else:
    print("Результат:", result)
finally:
    print("Программа завершена.")
```
### Как “поднять” исключение вручную

Иногда полезно явно вызвать ошибку с помощью `raise`:

```python
def divide(a, b):
    if b == 0:
        raise ValueError("Деление на ноль запрещено!")
    return a / b

try:
    print(divide(10, 0))
except ValueError as e:
    print("Ошибка:", e)
```
### Иерархия исключений

- Все стандартные исключения наследуются от класса **BaseException**.
- Наиболее часто используется **Exception** — “родитель” для всех обычных ошибок (ValueError, TypeError и т.д.).
- Можно создавать собственные классы-исключения, наследуя их от **Exception**.
### Советы по обработке исключений

- Обрабатывайте только те ошибки, которые ожидаете и можете корректно обработать.
- Не используйте “пустой” except: — это затруднит отладку.
- Используйте finally для освобождения ресурсов (закрытия файлов, соединений и т.д.).
- По возможности уточняйте типы исключений.
