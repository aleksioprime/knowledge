# Классы и ООП

В приложении десятки задач, и у каждой должны быть одинаковые методы, проверка данных при создании и защищённое внутреннее состояние — если собирать такие объекты литералами, правила инициализации и поведение расползаются по коду. Класс (class) описывает в одном месте, как создавать однотипные объекты с общим поведением: конструктор, методы, аксессоры, приватные поля и наследование. Синтаксис `class` использует прототипный механизм JavaScript, но в этой заметке рассматривается именно работа с классами.

## Минимальный пример

```js
class Task {
  #done = false
  static count = 0

  constructor(title) {
    this.title = title
    Task.count += 1
  }

  complete() {
    this.#done = true
    return this
  }

  get status() {
    return this.#done ? 'выполнена' : 'в работе'
  }
}

const task = new Task('Купить хлеб')
console.log(task.status) // в работе
console.log(task.complete().status) // выполнена
console.log(Task.count) // 1
console.log(typeof task.complete) // function
```

## Как это работает

### Объявление и основные элементы класса

Рассмотрим один класс, в котором сразу показаны поля экземпляра, приватное состояние, конструктор, обычный метод, getter и static-метод.

```js
class User {
  role = 'user'           // публичное поле экземпляра
  #token                  // приватное поле экземпляра
  static type = 'account' // статическое поле класса

  constructor(name, token) {
    this.name = name
    this.#token = token
  }

  greet() {
    return `Привет, ${this.name}`
  }

  get tokenLength() {
    return this.#token.length
  }

  static fromJSON(data) {
    return new User(data.name, data.token)
  }
}
```

Основные элементы:

- `constructor` инициализирует новый экземпляр;
- публичные поля принадлежат каждому экземпляру;
- приватные поля и методы начинаются с `#` и доступны только внутри объявившего их класса;
- обычные методы являются общими для экземпляров и не копируются заново в каждый объект;
- getters и setters выглядят как свойства, но выполняют методы;
- элементы с `static` принадлежат самому классу, а не его экземплярам;
- статический блок `static { ... }` выполняет сложную однократную инициализацию класса.

Класс можно объявить декларацией или выражением:

```js
class User {}

const Admin = class {
  isAdmin() {
    return true
  }
}
```

Объявление класса нельзя использовать до строки инициализации: оно находится в temporal dead zone, подобно `let` и `const`. Всё тело класса выполняется в строгом режиме.

### Для чего нужен `constructor`

`constructor` вызывается оператором `new` для начальной настройки экземпляра. В одном классе может быть только один `constructor`.

```js
class User {
  constructor(name, age) {
    this.name = name
    this.age = age
  }
}
```

Если собственный конструктор не нужен, его можно не писать. Для обычного базового класса конструктор по умолчанию эквивалентен пустому:

```js
constructor() {}
```

### Создание экземпляра и возвращаемое значение

Экземпляр создают оператором `new`:

```js
const user = new User('Alex', 30)
```

Вызвать класс как обычную функцию нельзя:

```js
User('Alex', 30) // TypeError: class constructor нельзя вызвать без new
```

Оператор `new` создаёт экземпляр, вызывает его `constructor` и возвращает готовый объект.

Обычно из `constructor` ничего не возвращают. Если базовый конструктор явно вернёт другой объект, результатом `new` станет этот объект; возвращённое примитивное значение игнорируется. Такой код затрудняет понимание и почти не применяется.

```js
const user = new User('Alex', 30)
user.name // 'Alex'
```

### Поля класса

Поле можно объявить прямо в теле класса или создать через `this` в конструкторе:

```js
class Counter {
  step = 1
  #value = 0

  constructor(initialValue = 0) {
    this.#value = initialValue
  }

  increment() {
    this.#value += this.step
  }
}
```

Инициализатор публичного поля выполняется для каждого нового экземпляра. Поле-стрелка тоже создаётся отдельно в каждом объекте, тогда как обычный метод хранится один раз в прототипе.

Приватное поле должно быть заранее объявлено. Обращение к нему снаружи класса является синтаксической ошибкой, а дочерний класс не получает к нему прямого доступа.

### Getters и setters

Getter вычисляет значение при чтении свойства, setter выполняет проверку или преобразование при записи:

```js
class Temperature {
  #celsius = 0

  get celsius() {
    return this.#celsius
  }

  set celsius(value) {
    if (!Number.isFinite(value)) {
      throw new TypeError('Температура должна быть числом')
    }

    this.#celsius = value
  }
}

const temperature = new Temperature()
temperature.celsius = 20 // вызывает setter
temperature.celsius      // вызывает getter и возвращает 20
```

Аксессоры вызываются без круглых скобок. Не используйте внутри setter присваивание тому же свойству (`this.celsius = value`), иначе возникнет бесконечная рекурсия.

### Наследование через `extends`

Ключевое слово `extends` создаёт связь между прототипами родительского и дочернего классов:

```js
class Animal {
  constructor(name) {
    this.name = name
  }

  speak() {
    return `${this.name} издаёт звук`
  }

  static category() {
    return 'animal'
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name)
    this.breed = breed
  }

  speak() {
    return `${super.speak()}: гав`
  }
}
```

В результате экземпляр `Dog` получает методы экземпляров `Animal`, а сам класс `Dog` — доступные static-методы родительского класса.

### Переопределение методов и `super`

Если дочерний класс объявляет метод с тем же именем, он переопределяет унаследованный метод. Родительскую реализацию можно вызвать через `super.method()`:

```js
const dog = new Dog('Бим', 'корги')

dog.speak()       // 'Бим издаёт звук: гав'
Dog.category() // 'animal'
```

В обычном методе `super.method()` обращается к прототипу родительского класса, сохраняя текущий `this`. В static-методе `super.method()` обращается к static-методу родительского класса.

### Конструктор дочернего класса и `super()`

Если дочерний класс не объявляет `constructor`, JavaScript создаёт его примерно в таком виде:

```js
constructor(...args) {
  super(...args)
}
```

Если дочерний конструктор объявлен явно, он должен вызвать `super(...)` до первого обращения к `this` и до обычного завершения конструктора:

```js
class Dog extends Animal {
  constructor(name, breed) {
    super(name)        // создаёт и инициализирует this через родительский класс
    this.breed = breed
  }
}
```

```js
class BrokenDog extends Animal {
  constructor(name) {
    this.name = name // ReferenceError: super() ещё не вызван
  }
}
```

`super()` разрешён только в конструкторе дочернего класса. Он вызывает родительский конструктор и передаёт ему аргументы. `super` — специальное ключевое слово, а не переменная, поэтому сохранить его в переменную или вызвать отдельно нельзя.

### Статические методы, поля и блоки

Статические элементы принадлежат классу, а не его экземплярам. Их используют для фабричных методов, констант и логики, связанной со всем классом:

```js
class User {
  static defaultRole = 'user'
  static #createdCount = 0

  constructor(name) {
    this.name = name
    User.#createdCount += 1
  }

  static createGuest() {
    return new User('Гость')
  }

  static get createdCount() {
    return User.#createdCount
  }

  static {
    if (!this.defaultRole) {
      throw new Error('Не указана роль по умолчанию')
    }
  }
}

const guest = User.createGuest()

User.defaultRole // 'user'
User.createdCount // 1
guest.defaultRole // undefined
```

Статический блок выполняется один раз при вычислении определения класса. Внутри него доступен `this`, равный самому классу, и приватные static-поля.

### Защищённые свойства

Отдельного ключевого слова `protected` в JavaScript нет. Исторически имя с подчёркиванием, например `_balance`, означает «внутреннее по договорённости», но язык не запрещает доступ снаружи:

```js
class Account {
  constructor(balance) {
    this._balance = balance
  }
}

const account = new Account(100)
account._balance = -1000 // технически разрешено
```

Настоящее приватное поле `#balance` недоступно даже дочернему классу. Если подклассу нужен контролируемый доступ, родитель может предоставить обычные методы или getters/setters:

```js
class Account {
  #balance = 0

  getBalance() {
    return this.#balance
  }

  deposit(amount) {
    if (amount <= 0) {
      throw new RangeError('Сумма должна быть положительной')
    }

    this.#balance += amount
  }
}

class SavingsAccount extends Account {
  addInterest(rate) {
    const interest = this.getBalance() * rate
    this.deposit(interest)
  }
}
```

Такой публичный метод иногда играет роль protected-интерфейса по соглашению, но вызвать его снаружи всё равно можно.

### Примеси и множественное наследование

JavaScript-класс может напрямую наследоваться только от одного родителя: запись вроде `class C extends A, B` невозможна. Поведение нескольких источников обычно объединяют композицией или примесями.

Примесь (mixin) — объект или функция, добавляющая классу отдельную возможность:

```js
const canLog = {
  log(message) {
    console.log(`[${this.name}]: ${message}`)
  },
}

const canSerialize = {
  toJSON() {
    return { name: this.name }
  },
}

class User {
  constructor(name) {
    this.name = name
  }
}

Object.assign(User.prototype, canLog, canSerialize) // методы примесей попадают в прототип

const user = new User('Анна')
user.log('создан')
JSON.stringify(user)
```

Такой подход копирует методы в прототип, но не создаёт дополнительную цепочку наследования. Для mixin с getters, setters или особыми descriptors вместо `Object.assign()` понадобятся `Object.getOwnPropertyDescriptors()` и `Object.defineProperties()`.

Функциональная примесь может вернуть подкласс и сохранить использование `super`:

```js
const Timestamped = (Base) => class extends Base {
  createdAt = new Date()
}

class Entity {}
class User extends Timestamped(Entity) {}
```

Примеси полезны для небольших независимых возможностей. Если между ними появляются скрытые зависимости и конфликты имён, явная композиция объектов обычно понятнее.

### Принципы ООП

Объектно-ориентированный подход объединяет данные и поведение в объектах. JavaScript реализует наследование через прототипы, а `class` предоставляет более привычный синтаксис.

#### Инкапсуляция

Объект скрывает внутреннее состояние и предоставляет контролируемые методы работы с ним. Поля с `#` действительно приватны на уровне языка:

```js
class Counter {
  #value = 0

  increment() {
    this.#value += 1
  }

  get value() {
    return this.#value
  }
}
```

#### Абстракция

Пользователь объекта работает с понятным публичным интерфейсом и не зависит от деталей реализации. Например, вызывает `counter.increment()`, не зная, как хранится значение.

#### Полиморфизм

Разные объекты отвечают на одинаковый вызов по-разному:

```js
function makeSound(animal) {
  return animal.speak()
}

const dog = { speak: () => 'гав' }
const cat = { speak: () => 'мяу' }

makeSound(dog) // 'гав'
makeSound(cat) // 'мяу'
```

В JavaScript для такого полиморфизма формальное наследование не обязательно: достаточно, чтобы объект предоставлял нужный метод.

#### Композиция

Композиция собирает объект из небольших независимых возможностей вместо глубокой иерархии классов. На практике принцип «предпочитайте композицию наследованию» часто уменьшает связанность кода.

ООП не требует использовать классы везде. Обычные объекты, фабрики и замыкания тоже позволяют инкапсулировать состояние и поведение.

## Частые ошибки

- Обращение к `this` в конструкторе дочернего класса до `super()` → `ReferenceError`, экземпляр не создаётся → вызывать `super(...)` первой строкой и только потом настраивать поля.
- Метод класса передан как callback без привязки (`button.addEventListener('click', counter.increment)`) → внутри `this` равен `undefined`, обращение к полю падает с `TypeError` → привязывать `this.increment = this.increment.bind(this)` в конструкторе или объявлять метод стрелочным полем.
- Setter присваивает тому же свойству (`set celsius(value) { this.celsius = value }`) → бесконечная рекурсия и `RangeError: Maximum call stack size exceeded` → хранить значение в отдельном поле, обычно приватном `#celsius`.
- Вызов класса без `new` → `TypeError: Class constructor cannot be invoked without 'new'` → создавать экземпляр через `new` или дать статический фабричный метод.
- Ожидание, что `_balance` защищено, а `#balance` доступно подклассу → `_balance` меняется снаружи, а обращение к `#balance` из наследника — синтаксическая ошибка → для контролируемого доступа давать публичные методы или getters/setters.

## Когда не использовать

Классы удобны, когда нужны экземпляры с общими методами, контролируемой инициализацией и понятной моделью наследования. Для простого объединения данных часто достаточно литерала [объекта](objects.md), а фабрики и композиция помогают избежать глубоких иерархий. Если у «класса» один метод и нет состояния, это обычная [функция](functions.md); если состояние нужно, но экземпляр один (настройки, кеш), подойдёт объект-литерал или замыкание.

Композиция часто проще глубоких иерархий наследования: объект получает необходимые функции и зависимости явно, а не через длинную цепочку классов. Если подкласс переопределяет половину методов родителя или наследуется ради одного метода, вместо `extends` лучше передать нужное поведение параметром или примесью.
