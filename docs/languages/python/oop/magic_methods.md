# Магические методы

Магические методы нужны, чтобы свой класс вёл себя как встроенный: печатался понятной строкой, создавался с нужными проверками, складывался через `+`. Python вызывает их сам в ответ на создание объекта, вывод или арифметику. В заметке разобраны пары, которые путают чаще всего: `__new__` и `__init__`, `__str__` и `__repr__`.

## Минимальный пример

`__str__` даёт строку для пользователя, `__repr__` — для разработчика; второй подхватывается и при печати списка:

```python run
class Task:
    def __init__(self, title, done=False):
        self.title = title
        self.done = done

    def __repr__(self):
        return f'Task(title={self.title!r}, done={self.done})'

    def __str__(self):
        mark = 'x' if self.done else ' '
        return f'[{mark}] {self.title}'


task = Task('Купить хлеб')
print(task)        # [ ] Купить хлеб
print(repr(task))  # Task(title='Купить хлеб', done=False)
print([task])      # [Task(title='Купить хлеб', done=False)]
```

## Как это работает

### Разница между `__new__` и `__init__`

При создании объекта Python вызывает два метода по очереди:

- `__new__` создаёт объект и возвращает его;
- `__init__` получает готовый объект и заполняет его атрибутами.

```python run
class A:
    def __new__(cls, *args, **kwargs):
        print("New")
        obj = super().__new__(cls, *args, **kwargs)
        return obj

    def __init__(self):
        print("Init")
        self.some = 1

a = A()
```

### Разница между `__str__` и `__repr__`

- `__repr__` — формальное техническое представление объекта, удобное разработчику;
- `__str__` — представление для пользователя, его использует `print()`.

Если `__str__` нет, используется `__repr__`. Если нет и `__repr__`, Python выводит стандартное представление с адресом объекта.

```python run
class Cat:
    name: str

    def __init__(self, name):
        self.name = name

    def __repr__(self):
        return f"Cat(name='{self.name}')"

    def __str__(self):
        return f"It is my cat {self.name}"

cat = Cat("Barsik")
print(cat)        # It is my cat Barsik
print(repr(cat))  # Cat(name='Barsik')
```

## Частые ошибки

- `__init__` возвращает значение (`return self`) → `TypeError: __init__() should return None` → `__init__` только заполняет атрибуты и ничего не возвращает.
- `__new__` переопределён, но не возвращает объект → `__init__` не вызывается, а `Task()` возвращает `None` → завершать `__new__` строкой `return super().__new__(cls)`.
- `__new__` передаёт аргументы конструктора в `object.__new__` → `TypeError: object.__new__() takes exactly one argument` при вызове `Task('Купить хлеб')` → вызывать `super().__new__(cls)` без аргументов, а аргументы принимать в `__init__`.
- Определён только `__str__`, без `__repr__` → в списке, словаре или отладчике объект печатается как `<Task object at 0x...>` → всегда определять `__repr__`, а `__str__` добавлять, только если нужен другой вид для пользователя.
- `__repr__` возвращает произвольный текст → в логе невозможно понять, какие данные были в объекте → строить `__repr__` как выражение, воссоздающее объект: `Task(title='...', done=False)`.

## Когда не использовать

Если класс нужен только для хранения полей, писать `__init__`, `__repr__` и `__eq__` вручную не стоит: [dataclass](../typing/dataclasses.md) сгенерирует их сам и без опечаток. Переопределять `__new__` нужно совсем редко — для неизменяемых типов, синглтонов и кэша объектов; в остальных случаях хватает `__init__`.

Перегружать операторы вроде `__add__` или `__lt__` имеет смысл, когда у операции есть очевидный математический смысл (вектор, деньги, интервал). Для задачи или пользователя `task1 + task2` только запутает читателя — лучше метод с понятным именем.
