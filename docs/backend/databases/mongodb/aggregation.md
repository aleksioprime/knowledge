# MongoDB: агрегации

`find` отвечает на вопрос «какие документы подходят». Но для отчёта нужно другое: сколько задач у каждого пользователя, какие метки самые популярные, сколько задач создано по месяцам. В SQL это `GROUP BY`, а в MongoDB — **конвейер агрегации** (aggregation pipeline): список шагов, каждый из которых преобразует поток документов и передаёт его дальше.

## Минимальный пример

Сколько задач у каждого пользователя, сколько из них выполнено и сколько на них ушло часов:

```python
db.tasks.insert_many([
    {'title': 'Сдать отчёт', 'owner': 'anna', 'done': True, 'tags': ['работа', 'срочно'], 'hours': 3, 'created': datetime(2026, 10, 1)},
    {'title': 'Купить хлеб', 'owner': 'anna', 'done': True, 'tags': ['дом'], 'hours': 0.5, 'created': datetime(2026, 10, 3)},
    {'title': 'Починить кран', 'owner': 'boris', 'done': False, 'tags': ['дом', 'срочно'], 'hours': 2, 'created': datetime(2026, 10, 3)},
    {'title': 'Записаться к врачу', 'owner': 'anna', 'done': False, 'tags': [], 'hours': 0.5, 'created': datetime(2026, 11, 2)},
    {'title': 'Обновить резюме', 'owner': 'boris', 'done': True, 'tags': ['работа'], 'hours': 4, 'created': datetime(2026, 11, 5)},
])

db.tasks.aggregate([
    {'$group': {
        '_id': '$owner',
        'total': {'$sum': 1},
        'done': {'$sum': {'$cond': ['$done', 1, 0]}},
        'hours': {'$sum': '$hours'},
    }},
    {'$sort': {'_id': 1}},
])
# {'_id': 'anna', 'total': 3, 'done': 2, 'hours': 4.0}
# {'_id': 'boris', 'total': 2, 'done': 1, 'hours': 6}
```

## Как это работает

Конвейер похож на конвейер `|` в терминале: выход одного шага — вход следующего. Основные шаги и их аналоги в SQL:

| Шаг | Что делает | SQL |
|---|---|---|
| `$match` | отбирает документы | `WHERE` |
| `$group` | группирует и считает | `GROUP BY` |
| `$sort` | сортирует | `ORDER BY` |
| `$limit`, `$skip` | обрезает | `LIMIT`, `OFFSET` |
| `$project` | выбирает и вычисляет поля | `SELECT` |
| `$unwind` | разворачивает массив в отдельные документы | — |
| `$lookup` | подтягивает документы из другой коллекции | `LEFT JOIN` |

В `$group` поле `_id` — это ключ группировки, а `$имя_поля` — ссылка на значение поля документа. Для подсчёта используются аккумуляторы: `$sum`, `$avg`, `$min`, `$max`, `$push` (собрать в список), `$addToSet`.

Порядок шагов важен: `$match` в начале сокращает количество документов для всех следующих шагов и может использовать индекс.

## Типовые отчёты

**Топ-1 по часам на выполненных задачах:**

```python
db.tasks.aggregate([
    {'$match': {'done': True}},
    {'$group': {'_id': '$owner', 'hours': {'$sum': '$hours'}}},
    {'$sort': {'hours': -1}},
    {'$limit': 1},
])
# {'_id': 'boris', 'hours': 4}
```

**Популярные метки.** `$unwind` превращает задачу с тремя метками в три документа, по одному на метку, и их уже можно группировать:

```python
db.tasks.aggregate([
    {'$unwind': '$tags'},
    {'$group': {'_id': '$tags', 'count': {'$sum': 1}}},
    {'$sort': {'count': -1, '_id': 1}},
])
# {'_id': 'дом', 'count': 2}
# {'_id': 'работа', 'count': 2}
# {'_id': 'срочно', 'count': 2}
```

**Задачи по месяцам:**

```python
db.tasks.aggregate([
    {'$group': {
        '_id': {'$dateToString': {'format': '%Y-%m', 'date': '$created'}},
        'created': {'$sum': 1},
    }},
    {'$sort': {'_id': 1}},
])
# {'_id': '2026-10', 'created': 3}
# {'_id': '2026-11', 'created': 2}
```

**Данные из другой коллекции.** Невыполненные задачи с именем и городом владельца:

```python
db.tasks.aggregate([
    {'$match': {'done': False}},
    {'$lookup': {'from': 'users', 'localField': 'owner', 'foreignField': '_id', 'as': 'user'}},
    {'$unwind': '$user'},
    {'$project': {'_id': 0, 'title': 1, 'name': '$user.name', 'city': '$user.city'}},
])
# {'title': 'Починить кран', 'name': 'Борис', 'city': 'Пермь'}
# {'title': 'Записаться к врачу', 'name': 'Анна', 'city': 'Казань'}
```

`$lookup` всегда кладёт найденное в массив (`user: [...]`), поэтому следом идёт `$unwind`, чтобы получить один объект.

**Несколько отчётов за один проход** — `$facet`:

```python
db.tasks.aggregate([
    {'$facet': {
        'byStatus': [{'$group': {'_id': '$done', 'n': {'$sum': 1}}}, {'$sort': {'_id': 1}}],
        'longest': [{'$sort': {'hours': -1}}, {'$limit': 1}, {'$project': {'_id': 0, 'title': 1, 'hours': 1}}],
    }},
])
# {'byStatus': [{'_id': False, 'n': 2}, {'_id': True, 'n': 3}],
#  'longest': [{'title': 'Обновить резюме', 'hours': 4}]}
```

## Частые ошибки

- **`$unwind` теряет документы.** Задача с пустым списком меток просто исчезнет из результата: из 5 задач после `$unwind` получится 6 документов вместо 7. Если такие нужны, используйте `{'$unwind': {'path': '$tags', 'preserveNullAndEmptyArrays': True}}`.
- **`$match` в конце.** Фильтр после `$group` обрабатывает уже все документы коллекции. Ставьте отбор как можно раньше.
- **Забытый `$` в ссылке на поле.** `{'$sum': 'hours'}` сложит строку `'hours'` (то есть 0), а не значения поля. Нужно `'$hours'`.
- **Много `$lookup`.** Если отчёт требует пяти соединений коллекций, возможно, данные лучше хранить в реляционной базе или вложить в документ.

## Когда не использовать

Если нужен один документ или список по условию, конвейер лишний: `find`, `count_documents` и `distinct` читаются проще и используют те же индексы. Конвейер берут, когда данные надо группировать, считать или перекладывать из одной формы в другую.

Когда в отчёте копятся `$lookup` по трём-четырём коллекциям и сложные условия между ними, это сигнал, что данные реляционные: в [SQL](../sql/null_and_aggregation.md) такой отчёт короче и быстрее. Тяжёлую аналитику по миллионам событий в рабочей базе тоже не считают — агрегации мешают основной нагрузке, такие данные выносят в аналитическое хранилище вроде [ClickHouse](../clickhouse/README.md).
