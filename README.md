# База знаний

Мои конспекты и примеры кода. Заметки лежат в папке [docs](docs/README.md) и публикуются сайтом: https://aleksioprime.github.io/knowledge/ — с поиском, тёмной темой, анимациями процессов и запуском Python и SQL прямо на странице.

## Как устроен репозиторий

```text
docs/           база знаний: README.md — главная страница, дальше группы и разделы
.vitepress/     конфигурация сайта, компоненты и проверка ссылок
.github/        сборка и публикация сайта
_template.md    шаблон новой заметки
```

Папки в `docs/` повторяют меню сайта: группа (`languages`, `backend`, `infrastructure`, `data`, `practice`) → раздел → тема. У каждой папки есть `README.md` со вступлением и блоком `## Содержание`; заметки лежат рядом с ним, код примеров — в `examples/`.

Блок «Содержание» — единственный источник меню: боковое меню сайта строится из него, в том же порядке и с теми же названиями, а подзаголовки `###` внутри блока становятся группами меню. Главный `docs/README.md` так же задаёт выпадающие меню сайта. Заметка, которой нет в содержании своей папки, останавливает сборку.

## Как устроены заметки

Новые заметки пишутся по [шаблону](_template.md): задача → минимальный пример → как работает → частые ошибки → когда не использовать. Там же правила стиля для текста и кода.

Сквозной учебный проект — [«Задачник»](docs/practice/projects/tasker/README.md): на нём показаны FastAPI, базы данных, кэш, фоновые задачи и мониторинг.

## Локальный запуск сайта

Сайт собирается VitePress из тех же файлов `.md`.

```bash
npm install
npm run dev
```

Каждый push в `main` с изменениями заметок пересобирает сайт и публикует его на GitHub Pages. Сборка останавливается на битой ссылке: на несуществующую заметку, на заголовок, которого нет, на файл, которого нет в репозитории, а также на заметке, не упомянутой в содержании. Проверить всё это локально после сборки:

```bash
npm run build
npm run check-links
```

Якоря строятся из заголовков так же, как на GitHub, поэтому ссылка вида `[текст](notes.md#3-заголовок-заметки)` работает и в репозитории, и на сайте.

## Запускаемые блоки кода

Чтобы фрагмент можно было запустить в браузере, пометьте блок кода как `python run` или `sql run`:

- Python выполняется через Pyodide, поэтому сторонние сервисы (базы, брокеры, сеть) в таких примерах недоступны;
- SQL выполняется в настоящем PostgreSQL, собранном в WebAssembly (PGlite): у каждого запуска чистая база в памяти и одно соединение;
- `session=имя` связывает блоки одного языка в цепочку: перед запуском молча выполняются блоки выше с тем же именем;
- `setup=имя` помечает подготовку (например, таблицы с данными), а `uses=имя` выполняет перед блоком только её — так примеры не тянут за собой все блоки выше. Их можно сочетать: `session=шаги uses=данные`.

Пример анимации процесса — [цикл событий asyncio наглядно](docs/languages/python/concurrency/event_loop_visual.md).
