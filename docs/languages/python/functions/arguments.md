# Аргументы и функции как значения

Функция принимает список, меняет его — и внезапно меняется исходный список у вызывающего. Или значение по умолчанию «помнит» предыдущие вызовы. Чтобы такие сюрпризы не ловить в отладчике, нужно понимать, как Python передаёт аргументы, зачем нужны `*args` и `**kwargs` и как передать функцию в другую функцию — через лямбду, `map` и `filter`.

## Минимальный пример

```python run
def add_task(title, tasks=None):
    if tasks is None:
        tasks = []
    tasks.append(title)
    return tasks

print(add_task('Купить хлеб'))     # ['Купить хлеб']
print(add_task('Позвонить маме'))  # ['Позвонить маме'] — новый список, а не общий

def describe(*tags, **fields):
    print(tags, fields)

describe('дом', 'срочно', priority='high')  # ('дом', 'срочно') {'priority': 'high'}

tasks = [('хлеб', True), ('молоко', False)]
print(sorted(tasks, key=lambda task: task[1]))  # [('молоко', False), ('хлеб', True)]
```

## Как это работает

### Аргументы функции

#### Передача изменяемых объектов

Python передаёт в функцию ссылку на объект, а не его копию. Поэтому функция может изменить переданный список, и изменение будет видно снаружи:

```python run
a = [1, 2, 3]

def some(arg):
    # Аргумент внутри функции — тот же объект, что и снаружи
    print(arg is a)  # True
    arg.append(4)
    return arg

print(some(a))  # [1, 2, 3, 4]
print(a)        # [1, 2, 3, 4] — оригинал тоже изменился
```

#### Изменяемое значение по умолчанию

Значение по умолчанию вычисляется один раз — когда Python создаёт функцию. Дальше при каждом вызове используется тот же самый объект, а не новый. Если это список, он будет накапливать значения между вызовами:

```python run
# Как неправильно
def some(a=[]):
    a.append(1)
    return a

print(some())    # [1]
print(some([]))  # [1]
print(some())    # [1, 1] — добавилось к списку из первого вызова
print(some([]))  # [1]

# Как правильно
def some(a=None):
    if a is None:
        a = []
    a.append(1)
    return a

print(some())    # [1]
print(some([]))  # [1]
print(some())    # [1]
print(some([]))  # [1]
```

#### *args и **kwargs

Функция может принимать произвольное число аргументов:

- `*args` — позиционные аргументы, собираются в кортеж;
- `**kwargs` — именованные аргументы, собираются в словарь.

```python run
def some(*args, **kwargs):
    print(locals())  # {'args': (1, 2, 3), 'kwargs': {'a': 1, 'b': 2}}

some(1, 2, 3, a=1, b=2)
```

### Функции как значения

#### Лямбда-функции

Лямбда-функция (lambda) — короткая безымянная функция из одного выражения. Её удобно передавать туда, где ждут функцию, например в параметр `key`.

Найдём ключ словаря с наибольшим значением: `max` перебирает ключи, а лямбда говорит сравнивать их по значениям.

```python run
a = {
    1: 3,
    2: 2,
    3: 1
}

print(max(a, key=lambda x: a[x]))  # 1
```

#### Функции высшего порядка: map и filter

Функция высшего порядка принимает другую функцию как аргумент. Встроенные `map` и `filter` возвращают ленивые итераторы — значения вычисляются, только когда их запрашивают:

- `map` применяет функцию к каждому элементу;
- `filter` оставляет элементы, для которых функция вернула истину.

```python run
a = [i for i in range(5)]

a_map = map(lambda x: x**2, a)
print(a_map)        # <map object at 0x...>
print(list(a_map))  # [0, 1, 4, 9, 16]

a_filter = filter(lambda x: x % 2 == 0, a)
print(a_filter)        # <filter object at 0x...>
print(list(a_filter))  # [0, 2, 4]
```

## Частые ошибки

- Список или словарь в значении по умолчанию (`def add(task, tasks=[])`) → данные накапливаются между вызовами, второй вызов видит задачи первого → ставить `None` по умолчанию и создавать объект внутри функции.
- Функция изменяет переданный список «на месте» → у вызывающего кода неожиданно меняется исходный объект → либо работать с копией (`list(tasks)`), либо явно описать в документации, что функция меняет аргумент.
- Позиционный аргумент после именованного в вызове (`f(a=1, 2)`) → `SyntaxError` → сначала позиционные, потом именованные.
- Распаковка `*` и `**` перепутана: `f(*options)` для словаря → в функцию уходят ключи словаря, а не пары «ключ-значение» → для словаря использовать `**options`.
- Результат `map` или `filter` печатают или перебирают дважды → во второй раз итератор пуст, а `print(map(...))` показывает `<map object>` → обернуть в `list()` там, где нужен готовый список.

## Когда не использовать

`*args` и `**kwargs` уместны в обёртках и декораторах, где функция не знает, что ей передадут. В обычной функции с понятным набором параметров они только прячут сигнатуру: читатель и редактор не видят, какие аргументы ожидаются. Лучше перечислить параметры явно, а для набора связанных значений завести класс или `dataclass`.

Лямбда хороша для одной строки в `key=` или `map`. Если в ней появляется условие или вычисление в несколько шагов, объявите обычную функцию через `def` с именем. А `map` и `filter` с лямбдами почти всегда короче и понятнее записываются списковым включением: `[task.title for task in tasks if not task.done]`.
