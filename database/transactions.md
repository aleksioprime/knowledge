# Транзакции

Транзакция — это **группировка нескольких операций в одну единицу работы**. Она либо **выполняется полностью**, либо **не выполняется вообще**. Это гарантирует целостность данных.

**Если несколько запросов изменяют данные и зависят друг от друга — используй транзакции**

Когда ты работаешь с базой данных, все изменения происходят **временно**, пока не будет подтверждено (`COMMIT`). Если что-то пошло не так, можно отменить (`ROLLBACK`).

1️. Открывается транзакция  
2️. Выполняются SQL-запросы (вставка, удаление, обновление)  
3️. Если всё прошло хорошо → `COMMIT` (изменения сохраняются)  
4️. Если произошла ошибка → `ROLLBACK` (всё отменяется)

Пример перевода денег между счетами:

```python
from sqlalchemy.ext.asyncio import AsyncSession
from sqlalchemy.future import select
from sqlalchemy.exc import SQLAlchemyError

async def transfer_money(session: AsyncSession, from_user: int, to_user: int, amount: float):
    try:
        # Запрашиваем баланс отправителя
        sender = await session.execute(select(Account).where(Account.id == from_user))
        sender = sender.scalars().first()

        if sender.balance < amount:
            raise ValueError("Недостаточно средств")

        # Списываем деньги
        sender.balance -= amount

        # Запрашиваем баланс получателя
        receiver = await session.execute(select(Account).where(Account.id == to_user))
        receiver = receiver.scalars().first()

        # Зачисляем деньги
        receiver.balance += amount

        # Фиксируем транзакцию
        await session.commit()

    except (SQLAlchemyError, ValueError) as e:
        await session.rollback()  # Если что-то пошло не так, отменяем всё
        raise e  # Пробрасываем ошибку выше
```

- Запрашиваем баланс отправителя (`select(Account).where(Account.id == from_user)`)
- Проверяем, хватает ли денег
- Обновляем баланс у отправителя и получателя
- **`session.commit()`** → сохраняет изменения в БД
- Если где-то ошибка → **`session.rollback()`** откатывает изменения

Каждая транзакция в БД должна соответствовать **ACID-принципам**:

| Принцип                               | Описание                                                                                                                                       |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **A (Atomicity) – Атомарность**       | Транзакция либо выполнится **полностью**, либо **не выполнится вообще**. Никаких промежуточных состояний.                                      |
| **C (Consistency) – Согласованность** | Данные в базе должны оставаться в **корректном состоянии** после транзакции. Например, нельзя оставить баланс в минусе, если не хватает денег. |
| **I (Isolation) – Изоляция**          | Две параллельные транзакции **не должны мешать друг другу**. Если два человека переводят деньги одновременно, это не должно привести к ошибке. |
| **D (Durability) – Долговечность**    | После `COMMIT` данные **надёжно сохранены**, даже если сервер базы данных внезапно упадёт.                                                     |
Когда нужны транзакции?

✅ Когда несколько SQL-запросов **должны выполняться вместе**, иначе данные будут в неправильном состоянии.  
✅ Когда важно **откатить изменения при ошибке**, чтобы не сломать данные.  
✅ Когда в системе **много пользователей**, и транзакции помогают избежать конфликтов.

Когда НЕ нужны транзакции?

❌ Когда ты просто читаешь данные (`SELECT`) → читать можно без транзакций.  
❌ Когда изменения происходят в **одной таблице и нет зависимости от других**.  
❌ Если данные **не критичны**, и небольшой сбой не страшен.
