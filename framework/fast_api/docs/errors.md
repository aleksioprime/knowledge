# Ошибки и коды ответов

Клиенту мало знать, что запрос не удался: от причины зависит, что ему делать дальше. Задачи нет — показать «не найдено». Нет прав — предложить войти. Данные неверны — подсветить поле в форме. Всё это передаётся кодом ответа и понятным телом ошибки. В FastAPI для этого есть `HTTPException` и обработчики исключений.

## Минимальный пример

```python
from fastapi import FastAPI, HTTPException, status

app = FastAPI()
tasks = {1: 'Купить хлеб'}


@app.get('/tasks/{task_id}')
def get_task(task_id: int):
    if task_id not in tasks:
        raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail='Задача не найдена')
    return {'id': task_id, 'title': tasks[task_id]}
```

```bash
curl -i localhost:8000/tasks/7
# HTTP/1.1 404 Not Found
# {"detail":"Задача не найдена"}
```

## Как это работает

`HTTPException` — это исключение, которое FastAPI превращает в HTTP-ответ с нужным кодом и телом `{"detail": ...}`. Поскольку это исключение, его можно выбросить где угодно ниже по стеку, в том числе в [зависимости](dependencies.md), и обработка запроса сразу остановится.

Константы из `fastapi.status` (`HTTP_404_NOT_FOUND`) читаются лучше, чем голые числа.

## Какой код выбрать

| Код | Когда | Пример в «Задачнике» |
|---|---|---|
| `400 Bad Request` | Запрос неверен по смыслу, но не по формату | Дата выполнения раньше даты создания |
| `401 Unauthorized` | Нет токена или он неверный | Запрос без `Authorization` |
| `403 Forbidden` | Пользователь известен, но прав не хватает | Обычный пользователь удаляет чужой проект |
| `404 Not Found` | Объекта нет | Задачи с таким `id` нет |
| `409 Conflict` | Конфликт с текущим состоянием | Email уже зарегистрирован |
| `422 Unprocessable Content` | Данные не прошли проверку схемы | Пустое название задачи. FastAPI отвечает так сам |
| `500 Internal Server Error` | Ошибка в коде сервера | Необработанное исключение |

Полный список кодов — в заметке про [структуру HTTP-ответа](../../../web/http/request_response.md).

## Свои исключения и обработчики

Сервисный слой не должен знать про HTTP: функцию «найти задачу» можно вызвать и из фоновой задачи, где никакого HTTP нет. Поэтому сервис выбрасывает своё исключение, а превращает его в ответ обработчик на уровне приложения:

```python
from fastapi import Request
from fastapi.responses import JSONResponse


class TaskLimitError(Exception):
    def __init__(self, limit: int):
        self.limit = limit


@app.exception_handler(TaskLimitError)
async def task_limit_handler(request: Request, exc: TaskLimitError):
    return JSONResponse(status_code=409, content={'detail': f'Нельзя создать больше {exc.limit} задач'})


@app.post('/tasks', status_code=201)
def create_task(title: str):
    if len(tasks) >= 100:
        raise TaskLimitError(limit=100)
    ...
```

Обработчик регистрируется один раз и срабатывает, где бы ни было выброшено исключение. В «Задачнике» так устроен [`TaskNotFoundError`](../../../pet/tasker/app/main.py): сервис сообщает, что задачи нет, а приложение отвечает 404.

## Необработанные ошибки

Если в коде случилось непредвиденное исключение, FastAPI вернёт `500` с телом `Internal Server Error`, а traceback напишет в лог сервера:

```python
@app.get('/boom')
def boom():
    return 1 / 0

# 500 Internal Server Error
```

Это правильное поведение: клиенту не нужны подробности, а злоумышленнику они могут помочь. Подробности ищите в [логах](../../../python/extra/logging.md).

## Частые ошибки

- **Ответ 200 с ошибкой в теле.** `return {'error': 'not found'}` — клиент и мониторинг сочтут запрос успешным. Ошибка должна менять код ответа.
- **403 вместо 404 для чужих объектов.** Ответ «Нет доступа» к `/tasks/42` подтверждает, что задача 42 существует. Для чужих объектов обычно отвечают 404 — как для несуществующих.
- **Путать 401 и 403.** 401 — «я не знаю, кто вы», 403 — «знаю, но нельзя».
- **Отдавать текст исключения клиенту.** `detail=str(error)` может выдать SQL-запрос, путь к файлу или имя таблицы.
