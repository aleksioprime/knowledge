# Vue DevTools

Компонент не перерисовывается, в хранилище Pinia лежит не то значение, непонятно, какой маршрут сейчас активен, — и `console.log` в каждом методе быстро перестаёт помогать. [Vue DevTools](https://devtools.vuejs.org/) показывает дерево компонентов, их `props` и состояние, события, маршруты Vue Router и хранилища Pinia прямо в браузере, без правок в коде приложения.

## Минимальный пример

```bash
npm add -D vite-plugin-vue-devtools
npm run dev   # на странице появляется плавающая кнопка Vue DevTools
```

```js
// vite.config.js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueDevTools from 'vite-plugin-vue-devtools'

export default defineConfig({
  plugins: [vueDevTools(), vue()],
})
```

Если менять конфиг не хочется, достаточно поставить расширение для браузера — вкладка `Vue` появится в инструментах разработчика без изменений в проекте.

## Как это работает

Актуальная версия Vue DevTools поддерживает Vue 3. Для проектов на Vue 2 нужна предыдущая, шестая версия расширения.

### Расширение для браузера

Самый простой способ начать работу — установить расширение для браузера:

- [Chrome и другие Chromium-браузеры](https://devtools.vuejs.org/guide/browser-extension#chrome), включая Edge, Brave и Arc;
- [Firefox](https://devtools.vuejs.org/guide/browser-extension#firefox).

После установки:

1. Запустите Vue-приложение, например командой `npm run dev`.
2. Откройте приложение в браузере.
3. Откройте инструменты разработчика браузера.
4. Перейдите на вкладку `Vue`.

Расширение устанавливается в браузер и не добавляется в зависимости проекта.

### Плагин для Vite

Для проекта на Vite можно использовать плагин с дополнительными возможностями: инспектором компонентов, просмотром файлов проекта и открытием компонента в редакторе. Плагин требует Vite 6 или новее.

Установите пакет как dev-зависимость:

```sh
npm add -D vite-plugin-vue-devtools
```

Подключите его в `vite.config.js`:

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueDevTools from 'vite-plugin-vue-devtools'

export default defineConfig({
  plugins: [
    vueDevTools(),
    vue(),
  ],
})
```

После запуска проекта на странице появится кнопка Vue DevTools. Нажмите её, чтобы открыть панель инструментов. Браузерное расширение и Vite-плагин решают похожие задачи, поэтому для начала достаточно выбрать один вариант.

Если нужно открывать исходный файл компонента в WebStorm, укажите редактор в настройках плагина:

```js
vueDevTools({
  launchEditor: 'webstorm',
})
```

По умолчанию для функции открытия файла используется Visual Studio Code.

### Основные вкладки

- `Components` — дерево компонентов, их `props` и состояние. Значения можно временно изменять прямо во время отладки.
- `Timeline` — события и затраты времени на рендеринг и обновление приложения.
- `Router` — список маршрутов и сведения о текущем маршруте при использовании Vue Router.
- `Pinia` — список хранилищ, их состояние и действия. Состояние можно редактировать для проверки разных сценариев.
- `Inspector` — выбор элемента на странице и переход к Vue-компоненту, который его отрисовал; доступен в Vite-плагине.
- `Assets` — просмотр файлов проекта; доступен в Vite-плагине.

Изменения состояния через DevTools предназначены для экспериментов и не изменяют исходный код приложения. После перезагрузки страницы они обычно сбрасываются.

### Если вкладка Vue не появилась

Проверьте следующее:

- открыта страница именно Vue-приложения, а не стартовая страница или ответ backend;
- приложение запущено в режиме разработки;
- расширение разрешено для текущего сайта, в том числе для вкладок в режиме инкогнито, если он используется;
- на странице нет одновременно нескольких конфликтующих версий Vue DevTools;
- для Vue 2 установлена версия Vue DevTools 6, а не актуальная версия для Vue 3.

После установки или обновления расширения перезагрузите страницу и заново откройте инструменты разработчика.

## Частые ошибки

- Отлаживается сборка из `npm run preview` или задеплоенный сайт → расширение пишет `Vue.js not detected`, вкладки `Vue` нет → запускать приложение через `npm run dev`; production-сборка отключает DevTools.
- `vueDevTools()` поставлен в `plugins` после `vue()` → инспектор не находит компоненты, переход «открыть в редакторе» не работает → ставить плагин первым в списке.
- Значение изменено во вкладке `Components` или `Pinia`, и это принято за исправление → после перезагрузки страницы ошибка возвращается → переносить найденное исправление в код, DevTools только для проверки гипотезы.
- Плагин установлен в проект на Vite 5 → при запуске dev-сервера падает с ошибкой несовместимости → обновить Vite до 6 или ограничиться браузерным расширением.
- Расширение и Vite-плагин включены одновременно → две панели, которые мешают друг другу, часть вкладок пустая → оставить один вариант, второй отключить.

## Когда не использовать

Для разовой проверки одного значения DevTools открывать дольше, чем вывести его в шаблон (`<pre>{{ task }}</pre>`) или написать `console.log` в обработчике. Инструмент окупается, когда нужно смотреть на состояние нескольких компонентов сразу или следить за последовательностью событий.

Vite-плагин — только для разработки: в сборку для пользователей он не попадает, и подключать его «на всякий случай» в production-конфигурацию не нужно. Сетевые запросы и ответы backend удобнее смотреть во вкладке `Network` браузера, а узкие места по скорости — во вкладке `Performance`: Vue DevTools показывает рендеринг компонентов, а не всё приложение целиком.
