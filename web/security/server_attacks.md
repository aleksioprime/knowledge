# Атаки на сервер и HTTP-инфраструктуру

## SSRF

Server-Side Request Forgery возникает, когда сервер запрашивает переданный пользователем URL без достаточных ограничений. Атакующий может обратиться к внутренним сервисам или облачным metadata endpoints.

Защита: allowlist назначений, проверка разрешённого IP после DNS-резолвинга, запрет внутренних диапазонов и неожиданных схем, контроль перенаправлений и сетевые ограничения исходящего трафика.

## Path traversal

Последовательности наподобие `../` позволяют выйти за разрешённый каталог. Следует работать с внутренними идентификаторами файлов, нормализовать путь и проверять, что итоговый путь остаётся внутри заданного корня.

## HTTP request smuggling

Если frontend-прокси и backend по-разному определяют границы запроса, злоумышленник может спрятать дополнительный запрос в теле первого. Особенно опасны неоднозначные комбинации `Content-Length` и `Transfer-Encoding`.

Защита: обновлять прокси и серверы, отклонять неоднозначные запросы, нормализовать сообщения на границе и по возможности использовать однозначный протокол связи с upstream.

## Host Header attacks

Непроверенный `Host` может повлиять на абсолютные ссылки, сброс пароля или маршрутизацию. Сервер должен принимать только известные домены и не строить чувствительные URL из произвольного заголовка.

## Отказ в обслуживании

Slowloris удерживает множество соединений, очень медленно передавая запрос. Объёмные тела, дорогие endpoints и всплески запросов также истощают ресурсы.

Защита включает:

- таймауты чтения, отправки и соединения с upstream;
- ограничения размера заголовков и тела;
- лимиты соединений и частоты запросов;
- очереди, кеширование и ограничение конкурентных тяжёлых операций;
- внешний DDoS-фильтр для объёмных сетевых атак.

Rate limiting снижает нагрузку, но сам по себе не заменяет аутентификацию, оптимизацию и внешнюю защиту канала.
