# Использование v-html в Vue.js

Контент из редактора статей или подсказка из CMS приходят на фронтенд уже в виде HTML, и интерполяция `{{ }}` покажет его как текст с тегами. `v-html` вставляет такую строку в DOM как разметку, но вместе с ней может вставить и чужой скрипт. Здесь — как пользоваться `v-html` и не получить XSS.

Общий обзор XSS, CSRF, CORS и clickjacking находится в разделе [Веб-безопасность](../../backend/web/security/browser_attacks.md).

## Минимальный пример

```vue
<script setup>
import { computed } from 'vue'
import DOMPurify from 'dompurify'

const props = defineProps({ articleHtml: String })

// '<p>Привет</p><img src=x onerror=alert(1)>' → '<p>Привет</p><img src="x">'
const safeHtml = computed(() => DOMPurify.sanitize(props.articleHtml))
</script>

<template>
  <article v-html="safeHtml"></article>
</template>
```

## Как это работает

`v-html` вставляет строку как сырой HTML в DOM. Vue не экранирует содержимое, поэтому этот способ подходит только для доверенного и заранее очищенного HTML.

### Опасности

- XSS: если в строке окажется вредоносный HTML или скриптовые атрибуты, пользователь может выполнить чужой код.
- Потеря защиты Vue: интерполяция `{{ }}` экранирует данные, а `v-html` обходится без этой защиты.
- Непредсказуемое поведение: в HTML могут попасть лишние теги, inline-обработчики и чужая разметка, которая сломает верстку.

### Как избежать проблем

- Не передавайте в `v-html` данные от пользователя без очистки.
- Очищайте HTML через allowlist-фильтр, например на сервере или на границе входа.
- Используйте `v-text` или обычную интерполяцию, если нужен только текст.
- Для внешнего контента применяйте библиотеку санитайза, например DOMPurify, и по возможности дополняйте ее CSP.

### Когда использовать

- Когда нужно отобразить доверенный HTML из CMS, редактора или документации.
- Когда источник и правила очистки контролируются приложением.

### Пример

```vue
<template>
  <div v-html="safeHtml"></div>
</template>
```

Перед использованием убедитесь, что `safeHtml` уже очищен и не содержит произвольный пользовательский ввод.

## Частые ошибки

- `v-html` получает текст из поля ввода, комментария или параметра URL → любой пользователь вставляет `<img onerror=...>` и выполняет скрипт у других → выводить такие данные через `{{ }}` или очищать DOMPurify перед вставкой.
- Очистка сделана регулярным выражением на клиенте → фильтр обходится через нестандартные теги и атрибуты (`<svg onload>`, `javascript:` в `href`) → использовать проверенный санитайзер с allowlist, а лучше чистить на сервере при сохранении.
- `v-html` стоит на элементе с дочерней разметкой (`<div v-html="html"><p>...</p></div>`) → вложенное содержимое молча заменяется → оставлять элемент пустым или выносить `v-html` на отдельный узел.
- Стили из `<style scoped>` не применяются к разметке из `v-html` → вставленный контент выглядит без оформления → использовать `:deep()` или глобальные стили для вставленного HTML.
- Ожидание, что Vue обработает директивы внутри вставленной строки → `{{ }}` и `v-if` внутри `v-html` остаются текстом → для динамической разметки использовать компоненты, а не строки.

## Когда не использовать

Если нужен только текст — заголовок задачи, имя пользователя, сообщение об ошибке — `v-html` лишний: интерполяция `{{ }}` и `v-text` безопасны по умолчанию и экранируют всё сами. Переносы строк и простое форматирование проще сделать через CSS (`white-space: pre-line`) или разбить текст на элементы.

Когда разметка зависит от данных (список, таблица, карточки), собирать её строкой и вставлять через `v-html` тоже не стоит: такой код не проверяет компилятор Vue, в нём не работают компоненты и обработчики событий. Лучше описать структуру в шаблоне через `v-for` и компоненты.
