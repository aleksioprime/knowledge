# Основы SQL

## Базовая модель и термины

- **База данных** — организованная совокупность данных.
- **СУБД** — программа, которая хранит данные, выполняет запросы, управляет конкурентным доступом, целостностью и восстановлением.
- **Таблица (relation)** состоит из строк и столбцов.
- **Строка (tuple)** — один объект или факт.
- **Столбец (attribute)** — именованное свойство с определённым типом.
- **Схема** — пространство имён и описание объектов БД.
- **Первичный ключ** однозначно идентифицирует строку.
- **Внешний ключ** связывает таблицы и поддерживает ссылочную целостность.

SQL декларативен: `SELECT` не предписывает использовать индекс, hash join или сортировку. Это решает оптимизатор.

## Виды команд SQL

Классификация полезна для объяснения назначения команд, хотя границы групп в разных источниках немного различаются.

| Группа | Назначение | Основные команды |
|---|---|---|
| DQL — Data Query Language | Чтение данных | `SELECT` |
| DML — Data Manipulation Language | Изменение строк | `INSERT`, `UPDATE`, `DELETE`, `MERGE` |
| DDL — Data Definition Language | Изменение структуры | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| DCL — Data Control Language | Права доступа | `GRANT`, `REVOKE` |
| TCL — Transaction Control Language | Управление транзакциями | `BEGIN`, `COMMIT`, `ROLLBACK`, `SAVEPOINT` |

Одна и та же команда может вести себя по-разному в транзакциях разных СУБД. Например, PostgreSQL позволяет откатывать большинство DDL, а MySQL для многих DDL делает неявный `COMMIT`.

## Порядок выполнения SELECT

Пишется запрос примерно так:

```sql
SELECT department_id, COUNT(*) AS employee_count
FROM employees
WHERE active = true
GROUP BY department_id
HAVING COUNT(*) >= 5
ORDER BY employee_count DESC
LIMIT 10;
```

Логический порядок обработки:

1. `WITH`
2. `FROM` и `JOIN ... ON`
3. `WHERE`
4. `GROUP BY`
5. агрегаты
6. `HAVING`
7. оконные функции
8. `SELECT`
9. `DISTINCT`
10. операции множеств (`UNION`, `INTERSECT`, `EXCEPT`)
11. `ORDER BY`
12. `LIMIT` / `OFFSET` или `FETCH`

Это **логическая**, а не обязательная физическая последовательность. Оптимизатор вправе переставлять безопасные операции. Из порядка следует, почему alias из `SELECT` обычно нельзя использовать в `WHERE`, а оконную функцию нельзя фильтровать там же без подзапроса или `QUALIFY`.

## Операторы и условия

### Основные операторы

| Категория | Операторы |
|---|---|
| Сравнение | `=`, `<>` / `!=`, `<`, `>`, `<=`, `>=` |
| Логика | `AND`, `OR`, `NOT` |
| Арифметика | `+`, `-`, `*`, `/`, `%` |
| Диапазон | `BETWEEN ... AND ...` |
| Множество | `IN (...)`, `NOT IN (...)` |
| Шаблон | `LIKE`, в PostgreSQL `ILIKE` |
| Наличие | `EXISTS`, `NOT EXISTS` |
| NULL | `IS NULL`, `IS NOT NULL` |
| Склейка строк | стандарт и PostgreSQL: `||`; MySQL: `CONCAT()` |

Приоритет обычно: скобки → арифметика → сравнения → `NOT` → `AND` → `OR`. Не полагайтесь на память — неоднозначные условия группируйте скобками.

```sql
WHERE status = 'paid'
  AND (country = 'RU' OR country = 'KZ')
```

### Важные детали

- `BETWEEN 10 AND 20` включает обе границы.
- `LIKE 'Ann%'` — строка начинается с `Ann`; `_` означает ровно один символ.
- `IN` удобен для небольшого списка или подзапроса.
- Для проверки существования связанных строк обычно выразительнее `EXISTS`.
- `NOT IN` с `NULL` внутри подзапроса может не вернуть ни одной строки; безопаснее `NOT EXISTS`.
- Для дат полуинтервал обычно надёжнее включительного `BETWEEN`:

```sql
WHERE created_at >= DATE '2026-08-01'
  AND created_at <  DATE '2026-09-01'
```

## Типы данных

Выбор типа задаёт допустимые значения, операции, точность, объём и способы индексирования.

### Основные семейства

| Семейство | Примеры | Когда применять |
|---|---|---|
| Целые | `SMALLINT`, `INTEGER`, `BIGINT` | Счётчики, идентификаторы |
| Точные числа | `NUMERIC(p, s)`, `DECIMAL` | Деньги и расчёты, где нельзя терять точность |
| Приближённые числа | `REAL`, `DOUBLE PRECISION` | Научные расчёты, измерения |
| Строки | `CHAR(n)`, `VARCHAR(n)`, `TEXT` | Текст |
| Логический | `BOOLEAN` | Истина / ложь / неизвестно (`NULL`) |
| Дата и время | `DATE`, `TIME`, `TIMESTAMP`, `INTERVAL` | Временные данные |
| Бинарные данные | PostgreSQL `BYTEA`, стандарт `BLOB` | Байты; крупные файлы часто лучше хранить вне БД |

Для денег не используйте `FLOAT`: двоичное представление даёт погрешность. Обычно подходят `NUMERIC` или целое число минимальных денежных единиц.

### CHAR, VARCHAR и TEXT

- `CHAR(n)` дополняется пробелами до фиксированной длины. Уместен для действительно фиксированных кодов, но часто создаёт неожиданности.
- `VARCHAR(n)` хранит строку переменной длины и ограничивает число символов.
- `TEXT` хранит строку переменной длины без заданного прикладного лимита.

В PostgreSQL между `TEXT` и `VARCHAR` нет преимущества по производительности; проверка ограничения `VARCHAR(n)` может даже добавлять работу. Если лимит — бизнес-правило, можно использовать `VARCHAR(n)` или `CHECK (length(value) <= n)`.

### «Экзотические» типы

Набор зависит от СУБД. В PostgreSQL есть:

- `UUID`;
- `JSON` и бинарно разобранный `JSONB`;
- массивы, например `INTEGER[]`;
- диапазоны `int4range`, `daterange`, `tstzrange` и multirange;
- сетевые адреса `INET`, `CIDR`, `MACADDR`;
- геометрические типы `POINT`, `POLYGON`;
- полнотекстовые `TSVECTOR`, `TSQUERY`;
- `XML`, `ENUM`, составные и пользовательские типы;
- расширения: `geometry` / `geography` (PostGIS), `vector` (pgvector).

«Экзотический» тип полезен, если СУБД понимает его семантику, умеет валидировать, сравнивать и индексировать лучше, чем самодельную строку.

### Приведение типов

```sql
SELECT CAST('42' AS INTEGER);
SELECT '42'::INTEGER; -- сокращение PostgreSQL
```

Неявные преобразования бывают удобны, но могут приводить к ошибкам и мешать индексу. В интерфейсах приложений значения следует передавать параметрами, а не склеивать SQL-строки.

## Создание таблиц и ограничения

```sql
CREATE TABLE departments (
    id   BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE employees (
    id            BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    department_id BIGINT REFERENCES departments(id),
    email         TEXT NOT NULL UNIQUE,
    salary        NUMERIC(12, 2) CHECK (salary >= 0),
    active        BOOLEAN NOT NULL DEFAULT true,
    hired_at      DATE NOT NULL DEFAULT CURRENT_DATE
);
```

Основные constraints:

- `NOT NULL` — значение обязательно;
- `UNIQUE` — значения или комбинации не повторяются;
- `PRIMARY KEY` — уникальный и непустой идентификатор;
- `FOREIGN KEY` — ссылка должна существовать в родительской таблице;
- `CHECK` — значение удовлетворяет условию;
- `DEFAULT` — значение при отсутствии явного значения в `INSERT`.

`DEFAULT` не заменяет уже явно переданный `NULL`. `CHECK` в PostgreSQL считается выполненным, если выражение равно `TRUE` **или `NULL`**, поэтому обязательность колонки задают отдельным `NOT NULL`.

### Нормализация в одном абзаце

- **1НФ**: значения атомарны, нет повторяющихся групп столбцов.
- **2НФ**: 1НФ и каждый неключевой атрибут зависит от всего составного ключа.
- **3НФ**: 2НФ и нет транзитивной зависимости неключевых атрибутов от ключа.

Нормализация уменьшает дублирование и аномалии записи. Денормализация осознанно добавляет дублирование ради чтения и требует механизма согласования.

## Чтение и изменение данных

### SELECT

```sql
SELECT id, email
FROM employees
WHERE active
ORDER BY hired_at DESC, id
LIMIT 20;
```

Без `ORDER BY` порядок строк **не гарантирован**. `DISTINCT` удаляет дубликаты по всей выбранной комбинации столбцов.

### INSERT

```sql
INSERT INTO departments (name)
VALUES ('Engineering'), ('Analytics')
RETURNING id, name; -- PostgreSQL
```

### UPDATE

```sql
UPDATE employees
SET salary = salary * 1.10
WHERE department_id = 10;
```

### DELETE, TRUNCATE и DROP

| Команда | Что удаляет | `WHERE` | Структура остаётся | Типичный смысл |
|---|---|---:|---:|---|
| `DELETE` | Выбранные строки | Да | Да | Обычное DML-удаление |
| `TRUNCATE` | Все строки таблицы | Нет | Да | Быстро опустошить таблицу |
| `DROP TABLE` | Таблицу как объект | Нет | Нет | Удалить данные и определение |

В PostgreSQL:

- `DELETE` создаёт мёртвые версии строк по MVCC, пишет существенный WAL, запускает row-level triggers и не возвращает место ОС без последующей переработки файла;
- `TRUNCATE` обычно быстрее, берёт сильную блокировку `ACCESS EXCLUSIVE`, поддерживает `RESTART IDENTITY`, не запускает `ON DELETE` triggers;
- `DROP` удаляет сам объект и зависимые объекты только при явном `CASCADE`;
- все три можно откатить, если они выполнены внутри незавершённой транзакции.

В других СУБД транзакционность DDL и `TRUNCATE` отличается.
