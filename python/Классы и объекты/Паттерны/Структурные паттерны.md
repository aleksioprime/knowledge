**Структурные паттерны** описывают **способы организации (структурирования) классов и объектов в большие, сложные структуры**, но при этом делают эти структуры гибкими и удобными для расширения и поддержки.

- **Объединяют объекты и классы** в более крупные структуры, сохраняя при этом простоту использования.
- **Скрывают сложность** внутренней реализации, предоставляя простой интерфейс для работы с составной системой.
- Позволяют изменять состав или структуру компонентов без сильного изменения кода, использующего эти компоненты.
- **Обеспечивают повторное использование** уже написанных классов, даже если их интерфейсы несовместимы.

Вот самые известные структурные паттерны (GoF):

1. **Adapter (Адаптер)**
    - Позволяет объектам с несовместимыми интерфейсами работать вместе, “переводя” интерфейс одного в интерфейс другого.
2. **Facade (Фасад)**
    - Предоставляет простой интерфейс к сложной системе классов или объектам.
3. **Decorator (Декоратор)**
    - Динамически добавляет объекту новые обязанности/функционал, не изменяя его класс.
4. **Composite (Компоновщик)**
    - Позволяет сгруппировать объекты в древовидные структуры для представления иерархий “часть-целое”.
5. **Proxy (Заместитель)**
    - Представляет другой объект и контролирует доступ к нему.
6. **Bridge (Мост)**
    - Разделяет абстракцию и реализацию так, чтобы их можно было изменять независимо.
7. **Flyweight (Приспособленец)**
    - Позволяет эффективно поддерживать большое количество мелких объектов, используя общие данные.
